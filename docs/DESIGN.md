# 設計

ML-Provide の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

学習したモデルで新しいデータを推論し, 予測から結論を出す手元の Web アプリ. 推論と結論の中身は ML-Inference が持ち, このアプリは画面と, 画面のための API と置き場を持つ.

- 推論の一式 (ML-Inference の約束) を登録するか, 学習の結果 (モデルの定義, データセット, 実験) から画面で作る
- 新しいデータのファイルか, 画面に書いた文を推論し, 予測の表と結論 (判断の内訳, まとめの文) を見る
- 結論の決め方 (保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列) を画面で変え, 推論し直さずに結論だけを出し直す
- 結果を保存し, 後から開き, 予測の表を CSV で持ち出す
- 強化学習の方策の一式 (ML-Inference が読む `policy.json` と `policy.pt`) を登録し, 画面に入れた観測か観測のファイルから守りを当てた行動と守りの結果を見る (下の「方策の一式」)
- 列の予測 (クラス, 値, 分布) でない一式 (領域, 点群, ベクトル, 画像, 文を出す一式. ML-Inference の一式の版 3 と 4) も推論し, 1 件ごとの配列を見る (下の「受け持ちと出力の形」)
- データセットを持たない雑音だけの一式 (拡散やフローのモデル. 一式の版 5) を作り, 件数と種から生成して 1 件ごとの配列を見る (下の「雑音だけの一式」)
- 学習しない既製のモデル (ライブラリの学習済みの重み. 一式の版 6) の一式を作り, 画像から種類の名前と確信度を出す (下の「既製のモデルの一式」)
- ML-EDA の版 1 の音声のデータセットで学習した一式も推論する (読み込み `audio_folder` と中身の手順 (周波数, チャンネル, 長さをそろえる) は, 列の一式と同じく「読み込み」と「前処理」の行に出す). 一式の種類は「音声」と出し, 推論するデータの欄は音声のファイルか, 音声を並べたディレクトリを案内する (列のファイルを案内しても音声の一式では読めないため)
- ML-EDA のファイルの組のデータセット (版 2 と, 中身の手順をかけた版 3. 画像と領域, 撮影と点群) からも一式を作り, 新しい画像や撮影の領域と, 元の座標の点群を見る (下の「ファイルの組のデータセットの一式」)

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「推論」の段階で画面を受け持つ. ライブラリは ML-Inference.

- ML-Inference は submodule. 推論, 結論, 一式の形など, 画面の外でも使う仕組みは ML-Inference に足す. 画面と API に固有のもの (置き場, 結果の一覧, ページ分け) はこのリポジトリに置く
- 構成と道具は ML-Dashboard, ML-CreateArchitecture, ML-Fathom にそろえる (将来の統合のため). バックエンドは FastAPI, 画面は React と Vite, 起動ごとのトークンと Origin の確認も同じ
- 意思決定 (損得と制約) と結論の決め方は, 本来は問題の設定の段階 (ML-Quest, ML-Pathfinder) が決める. 一式に問題の設定をつなぐと, 推論の既定値を問題の設定の今の値にする (下の「問題の設定とのつなぎ」). つないでいない一式は, 一式の既定値と画面で選んだ値を使う

## 2. 使うライブラリと約束

ML-Inference と ML-Quest は submodule. 形の決まりを 2 か所に持たないため, 一式, 結果, 問題の設定のファイルは自分で解釈せず, それぞれのライブラリの関数で読み書きする.

| ファイル | 持ち主 | このアプリの扱い | 読む版 |
| --- | --- | --- | --- |
| 推論の一式 (`inference.yaml` と, モデルの定義, 重み, データセットの説明とレシピ) | ML-Inference | 登録した場所から読む (`load_bundle`, `describe_bundle`). 画面で作る一式は `make_bundle` (既製のモデルの一式は `make_ready_bundle`) で置き場に書く. 測り直した外れ方は一式に書き戻す (`remeasure`. 下の API の表) | 1 から 6 |
| 推論の結果 (`predictions.csv`, `result.yaml`, `artifacts/`) | ML-Inference | 置き場に書いて読む (`write_result`, `read_result`) | 1 と 2. `RESULT_FORMAT_VERSION` より新しい版は「この版の結果は読めません」で止める (一覧では飛ばす) |
| 問題の設定 (`problem.yaml`) | ML-Quest | 読むだけ (受け渡しの `handoff` の `inference` と, 今のやり方 `action.current`, 写しの元の場所 `problem_origin`, 書き出したプロジェクトの記録 `project`). 書き戻さない | 1 と 2. 新しい版は読めない理由を出して止まる |
| データセット | ML-EDA (ML-Fathom で書き出す) | 一式を作るときに `make_bundle` に渡す. 読めるのは `make_bundle` が読む形 (版 1 の列のデータセットと, 版 2 と版 3 のファイルの組). 一式を作る画面でファイルの組の項目と中身の手順を見せるために, ML-EDA の `load_items` で読む (書かない). 見本の一式は ML-Inference の `make_sample_bundle` が作る (図形の領域の見本は, ML-EDA の合成の画像と領域を書き出したデータセットから `make_bundle` で作る) |
| 既製のモデルの出どころ (重みの説明とライセンス) | ML-Inference (`READY_LIBRARIES`), ML-ModelControl (`pretrained_info`) | 一式を作る前の下見で, 種類の名前の表, 前処理, 重みのファイルの名前を `READY_LIBRARIES[library](model, weights)` で読み, ライセンスの情報を ML-ModelControl の `pretrained_info` で読む (このアプリが ML-ModelControl を直接使うのはここだけ). 読んだライセンスの情報を `make_ready_bundle` に渡す | ML-Inference に従う |
| モデルの定義 | ML-ModelControl (ML-CreateArchitecture で組む) | 一式を作るときに `make_bundle` に渡す | ML-Inference に従う |
| 実験のディレクトリ (重み, `run.json`) | ML-Found | 一式を作るときに読む. 書かない |  |
| 方策の一式 (`policy.json`, `policy.pt`, 写したモデルの定義) | ML-Inference (ML-Found が書き出す) | 登録した場所から読む (`read_policy_spec`, `load_policy`). 書かない | 1. 新しい版は ML-Inference が読まずに止まる |

- 実験のディレクトリには書かない (ML-Found の約束). 画面で作る一式は, このアプリの置き場に作る
- ML-Quest は submodule. 問題の設定のファイルは ML-Quest を通して読む (YAML を自分で解釈しない)

## 3. 画面

| 画面 | 内容 |
| --- | --- |
| 一式 | 登録した一式の一覧 (名前, データの種類, タスク, クラス (10 を超えれば先頭の 10 と残りの数. 既製のモデルの一式は種類の数だけ), 実験の状態とベストの値). 実験の一覧から選んで登録するか (下の「実験の一覧」), 場所で登録するか, 既製のモデルから作るか (下の「既製のモデルの一式」), 学習の結果から作る (データセットの説明を読み込む間と, 欄が読んだ場所と違う間は「作る」を押せない. 前のデータセットの説明で決めた欄を送らないため. ファイルの組のデータセットなら入力と正解の項目と中身の手順を見せ, 点を選ぶ数と種の欄を出す. 列のデータセットと雑音だけの一式なら, 繰り返しの手順 (登録簿から選ぶ名前, 回数, 種, 手順の設定の名前ごとの欄. 何でも受け取る自作の手順は `名前=値` の行. 設定の値は, 10 進の数を数, `true` と `false` を真偽, `null` を null, JSON の引用符で囲んだ値を JSON の決まり (`\"` と `\\` などのエスケープも) で読んだ文字, `[` か `{` で始まる値を JSON の決まりで読んだ配列か辞書 (入れ子も), 他を前後の空白を除いた文字として読む. 一式の画面に出た設定の値を写すと元の型に戻るため. 引用符で始まるのに JSON の文字として読めない値と, `[` か `{` で始まるのに JSON の配列か辞書として読めない値は誤りとして知らせる), 受け持ちと出力の形と形ごとの欄 (分布の水準, 領域のクラスの名前, 配列の出力の 1 件の形), モデルの入力ごとの出どころ (名前, 表の列か中身か手順の中身か手順の時刻, 先頭に足した番号) の欄を出す. 「雑音だけから作る」を選ぶとデータセットの欄を隠し, 雑音から始まる手順と配列の出力の形だけを選べるようにする). 試すための見本の一式を入れる (見本は学習の基盤を使わずに, ML-Inference の `make_sample_bundle` で小さなモデルを全ての行で 300 回更新して作る. 図形の領域の見本は, ML-ModelControl の見本の U-Net を全ての画像で 100 回更新して `make_bundle` で作る. 実験の記録は無い) |
| 一式の詳細 | 一式の説明 (データの種類, タスク, 目的の列, クラス, 学習に使う列, 読み込み, 前処理の手順, モデルの入力, 実験, 検証用の分割を一式で推論した評価と実験の記録が合うか, 外れ方の記録 (測り直した一式は作ったときの記録に戻せる. 種類ごとに測った一式は分けた列と種類の数. `describe_bundle` の `uncertainty.groups`), 注意. 版 3 と 4 の一式は受け持ち, 出力の形, 正解の種類と出どころ, 手順, 学習済みの重みの置き方と警告も. 版 4 の一式は 1 件の扱いも). 列の出力でない一式は結論の決め方と意思決定の欄を出さず, 件数だけを出すと書く. 既製のモデルの一式は, 読み込みと前処理の行の代わりに出どころ, 重みの説明の前処理, 重みのファイルと置き場にあるかを出し, ライセンスの警告を上に出す (下の「既製のモデルの一式」). 問題の設定 (つないだ問題の設定の名前, 意思決定の文, 損得の根拠, 一式との食い違い. つないでいなければ候補 (元の問題の設定か学習の時点の写しかの文を添える) とつなぐ場所の欄). 推論するデータ (ファイルを選ぶか, 文の一式なら文を書く. 雑音だけの一式は作る件数と乱数の種) と結論の決め方を選んで推論する (つないだ一式は問題の設定の値が既定). 過去の結果の一覧 |
| 結果 (列の出力でない一式) | 件数だけの結論の文, 正解の出どころの注意, 学習済みの重みの警告, 予測の表 (配列の出力は行を選ぶと, 領域と画像は絵, 点群は散布図, ベクトルは形と最初の値. `.npy` を落とせる), CSV のダウンロード |
| 方策の一式 | 登録した方策の一式の一覧 (名前, 観測と行動の空間, 外れたときの動き. 読めない一式は理由). 実験の一覧から選んで登録するか (下の「実験の一覧」), 場所で登録する |
| 方策の一式の詳細 | 観測と行動の空間, 出力の読み方, 読まなかった重みのキー, 守り (止める条件の範囲, 行動の範囲, 選んでよい行動, 外れたときの動き). 観測の欄 (カンマか空白で区切った数か, JSON の配列. 初めは観測の大きさの 0 の並び (64 要素を超える観測は空)) から行動を決め, 行動 (止めるか元の制御に戻す場合は「行動なし」), 守りの結果, 守りが働いた理由を出す (結果は残さない). 観測のファイル (CSV の行か `.npy` の並び) でまとめて決め, 方策の結果の画面に移る. この方策の結果の一覧 |
| 方策の結果 | 守りの結果ごとの件数 (横棒), 1 件ずつの観測, 行動, 守りの結果, 理由の表 (ページ分け, 守りの結果で絞る), CSV のダウンロード, 消す. 左の「結果」の一覧の「方策の結果」からも開き直す |
| 結果 | 意思決定 (行動の文, 前提, 決め直し, 過去のデータでのたどり直しと差の幅), 外れ方の確かめ (目的の列のある入力の結果だけ. 今の記録がこの実績を覆った割合と測り直した幅を見て, 確認の上で一式に書き戻す. 何段も先まで予測できる一式では, 何段先までと予測を始める時刻の列を選ぶと段ごとの外れ方も測る. 回帰と予測の一式では, 外れ方を分ける列 (結果の列から, 予測と判断の列, 種類ごとの確率の列, 目的の列を除いたもの) を選ぶと種類ごとの外れ方も測る (外れ方は行の種類で違うため). 書き戻した後の推論と決め直しから使う. 一式の画面で作ったときの記録に戻せる), 結論の文, 判断の内訳 (帯グラフ), まとめる列ごとの表, 列の効き (押すと求める), 1 行の予測の理由 (予測の表の「理由」か行の番号で選んだ行だけを求める), 予測の表 (ページ分け, 予測しなかった行と判断で絞る), 決め方を変えて出し直す, CSV のダウンロード |

## 4. API

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/auth` | 起動したときのトークンを Cookie に保存して画面に移る |
| `GET /api/info` | ML-Inference の版, 結論の決め方の項目, 繰り返しの手順の登録簿 (名前, 組み込みか, 始まり (`noise` は雑音, `given` は渡した番号の並び), 時刻を渡すか, 設定の名前. 設定の名前と既定値は ML-Inference の `procedure_options` から得る (決まりを ML-Inference の 1 か所に置くため). 名前は手順の関数の 5 つ目からの引数で `*args` の名前は入らず, 何でも受け取る自作の手順と引数を読めない手順は `null`. 設定の既定値 (`defaults`. 有限の数, 真偽値, 文字の既定値だけ. inf, NaN, None は除く) も), 起動の設定で読んだ手順のモジュール (`procedure_modules`) と部品のモジュール (`unit_modules`), 雑音だけの一式で一度に作る件数の上限 (`max_samples`), 画面で作る一式の手順の回数の上限 (`max_procedure_steps`), 既製のモデルの出どころ (`ready_libraries`. ML-Inference の `READY_LIBRARIES` の名前) |
| `GET /api/browse` | ディレクトリの中身 (ファイルとディレクトリを選ぶため) |
| `GET /api/bundles` | 登録した一式の一覧 (読めない一式は理由付き) |
| `POST /api/samples` | 見本の一式 (表の分類, 表の回帰, 時系列の先の予測, 文の分類, 画像の領域の分割) を, 見本のデータでその場で学習して作り登録する. 列の見本には意思決定の既定値と, たどり直しを試す目的の列のある過去のデータも付ける (時系列は 120 日. 7 段先までの外れ方を段ごとに測れる長さ). 領域の見本の新しいデータは画像を並べたディレクトリで, 過去のデータは無い (列の予測でない一式の画面を, 自分の一式を作らずに試すため) |
| `GET /api/experiments` | 問題の設定の置き場 (ML-Pathfinder) に記録したプロジェクトの, 推論の一式を持つ実験の一覧 (下の「実験の一覧」) |
| `GET /api/experiments/policies` | 同じプロジェクトの, 方策の一式を持つ実験の一覧 (行の `policy_id` で登録済みを見分ける. 下の「実験の一覧」) |
| `POST /api/bundles` | 場所を指定して登録 (`inference.yaml` を持つディレクトリ. 名前は省略すると一式の名前) |
| `GET /api/datasets/describe` | データセットのディレクトリ (`path`) の版と, 版 2 と版 3 なら受け持ち, 正解の種類と出どころ, 項目 (名前, 種類, 役, 中身の手順), 入力と正解の項目, 分割, 領域の値の名前, 点を選ぶ欄が要るか (下の「ファイルの組のデータセットの一式」) |
| `POST /api/bundles/create` | モデルの定義, データセット, 実験 (か重み) から置き場に作って登録. ファイルの組のデータセットは 1 件の扱い (`items`) も渡せる. `dataset` を省くか空にすると雑音だけの一式 (下の「雑音だけの一式」). 手順 (`procedure`), 出力の形ごとの欄 (`output_options`), 入力ごとの出どころ (`inputs`) はそのまま `make_bundle` に渡す. 手順の回数は 1,000 回まで (拡散の学習の時刻の数の既定と同じ. 回数ごとにモデルを件数分呼ぶので, 作るときの確かめと推論が長く止まらないように. 文の生成 (`greedy`, `sample`) の足す番号の数にも, `train_steps` を大きくした `ddim` にも同じ上限を当てる. 上限は `GET /api/info` の `max_procedure_steps` で, 画面の回数の欄も確かめる) |
| `GET /api/ready/preview` | 既製のモデルの一式を作る前の下見 (`library`, `model`, `weights`). 版の決まった重みの名前 (`DEFAULT` は直した名前), 種類の名前の表, 前処理, 重みの URL とファイルの名前, ライセンスの情報 (`license`, `status`, `redistributable`, `gated`, `alert`, `message`, `source`, `url`). 重みは取りに行かない. 無い出どころ, モデル, 重みは理由付きで断る |
| `POST /api/bundles/ready` | 既製のモデルの一式を置き場に作って登録する (`name`, `library`, `model`, `weights`, 任意の `sha256`). 出どころの重みを読んで hash を固定する (初回は時間の上限を付けて取りに行く). 重みを取れない場合は 502 |
| `GET /api/bundles/{id}` | 一式の説明 (ML-Inference の `describe_bundle`) と, モデルを組み立てたか (`model_loaded`. 学習済みの重みの警告は組み立てた後に出る). 手順が登録簿に無い一式は, 起動の設定に足すよう案内を添えた誤り |
| `GET /api/bundles/{id}/problem` | つないだ問題の設定から読んだ推論の値 (名前, 場所, 中身の印, 受け持ち, 推論の結論を扱う受け持ちか, 意思決定, 結論の決め方, 何期先まで, 損得の根拠, 一式との食い違い). つないでいなければ, 一式の場所から上にたどって見つけた問題の設定の候補 (`hint`. 写しが元の場所を持てば元) と, 元か写しかの文 (`hint_note`). 読めなくなっていれば理由. 雑音だけの一式では, 問題の設定を読まず候補も探さずに, つなぎの場所 (`path`) は返し, 他は空にする (画面は一式の種類が分からない間, 一式と並べてこれを読むため). 既製のモデルの一式は, 作り方が既製のモデルをそのままの問題の設定だけを候補に出し, 読んだ値は結論の決め方と重みの食い違いだけ (下の「既製のモデルの一式」) |
| `PUT /api/bundles/{id}/problem` | 問題の設定をつなぐ (`path` は problem.yaml かそのディレクトリ. 渡せない問題の設定は理由付きで断る). `path` が空ならつなぎを外す |
| `DELETE /api/bundles/{id}` | 登録を消す (置き場で作った一式は一式も消す) |
| `POST /api/bundles/{id}/restore-uncertainty` | 測り直した外れ方を, 一式を作ったときの記録に戻す (ML-Inference の `restore_uncertainty`) |
| `POST /api/bundles/{id}/predict` | ファイルの場所か文の並びを推論し, 結論を出して結果を保存. `forecast` で何段も先の予測 (目的の列の過去の値を使う回帰と予測の一式. 結果は先の行だけ). `decision` で意思決定もする (省略は一式の既定値, 空の辞書で意思決定しない). 列の出力でない一式では, 結論の決め方, 意思決定, 何段も先の予測を渡すと断り, 結論は件数だけ. 雑音だけの一式はファイルと文の代わりに件数 (`count`. 要る) と種 (`seed`. 省くと一式の手順の種) を受け取る (下の「雑音だけの一式」) |
| `GET /api/results` | 結果の一覧 (`bundle` で絞れる) |
| `GET /api/results/{id}` | 結果のまとめ, 文, 決め方, 列 |
| `GET /api/results/{id}/rows` | 予測の表の一部 (`offset`, `limit`, `status`, `decision` で絞る) |
| `GET /api/results/{id}/artifacts/{row}` | 配列の出力の結果の, 行の位置の配列の見本 (形, 型, 出力の形ごとの見せ方. 下の「受け持ちと出力の形」) |
| `GET /api/results/{id}/artifacts/{row}/file` | 行の位置の配列のファイル (`.npy`) |
| `POST /api/results/{id}/conclude` | 決め方を変えて結論だけを出し直す (結果を書き換える) |
| `POST /api/results/{id}/explain` | 入力の列ごとの効き (ML-Inference の `explain`) を求めて結果に残す (表と時系列のファイルの結果だけ) |
| `POST /api/results/{id}/rows/{row}/reason` | 結果の 1 行の, 元の列ごとにその行の値が予測を動かした向きと大きさ (`effects`) と, 効きの大きい 3 列の文 (`reason`) を求める (ML-Inference の `explain_rows`. 下の「1 行の予測の理由」). 表と時系列の, ファイルを 1 つ先まで予測した結果の, 予測した行だけ. 結果には残さない |
| `POST /api/results/{id}/decide` | 意思決定の決め方を変えて決め直す (推論はし直さない. 空で外す) |
| `POST /api/results/{id}/backtest` | 結果の入力 (目的の列を持つファイル) で, 意思決定の方針と素朴なやり方の実際の得と損を比べる |
| `POST /api/results/{id}/remeasure` | 結果の入力 (目的の列を持つファイル) で一式の予測の外れ方を測り直す (ML-Inference の `remeasure`). `write` が偽なら確かめるだけ, 真なら一式に書き戻す (置き場の外の一式なら, 登録した場所のファイルを書き換える. ただし学習の実験のディレクトリの中の一式 (一式か上の 2 つのディレクトリに `run.json` がある) は, 実験を書き換えないという ML-Found の約束に合わせて, 置き場に写してから書き戻し, 登録を写した方に移す. 応答の `copied_to` に写した場所. 「作ったときの記録に戻す」も同じ. 写しの登録は `copied_from` に元の場所を持ち, 元の場所を同じ登録として二重に登録しない. 写しを消しても元の実験の一式は残る. 写すか書き戻すかに失敗したら写しを消し, 登録は移さない). `horizon` と `time` で何段も先の外れ方も段ごとに測る (目的の列の過去の値を使う一式だけ. 画面は確かめたときの段の数と時刻の列で書き戻す). `groups` で外れ方を分ける列の種類ごとにも測る (回帰と予測の一式だけ. 20 行より少ない種類は全ての行の外れ方. 空は分けない. 予測と判断の列と種類ごとの確率の列 (`p:<種類>`) は画面と同じく 400 で断る. 画面は確かめたときの列で書き戻す). 結果には残さない |
| `GET /api/results/{id}/download` | 予測と判断の CSV |
| `DELETE /api/results/{id}` | 結果を消す |
| `GET /api/policies` | 登録した方策の一式の一覧 (`policy.json` の中身 `spec`. 重みは読まない. 読めない一式は理由付き) |
| `POST /api/policies` | 場所を指定して方策の一式を登録する (重みまで読めることを確かめる. 名前は省略するとディレクトリの名前) |
| `GET /api/policies/{id}` | 方策の一式の中身と, 重みのうち読まなかったキー (`unused_keys`). 重みを読めなくなっていれば理由 |
| `DELETE /api/policies/{id}` | 登録を外す (一式のファイルは消さない) |
| `POST /api/policies/{id}/act` | 観測 (`observation`) から, ML-Inference の `GuardedPolicy.act` で守りを当てた行動 (`action`), 守りの結果 (`status`), 理由 (`reasons`) を返す. 結果は残さない |
| `POST /api/policies/{id}/batch` | 観測のファイル (`source`. `.csv` は 1 行に 1 つの観測, `.npy` は先頭の次元を観測の並びに) の 1 件ずつに `act` と同じく守りを当て, 結果を置き場に残して, まとめ (件数, 守りの結果ごとの件数) を返す (下の「方策の一式」) |
| `GET /api/policy-results` | 方策の結果の一覧 (新しい順. `policy` で方策の一式の id で絞れる) |
| `GET /api/policy-results/{id}` | 方策の結果のまとめ (方策の名前と場所, 観測のファイル, 時刻, 件数, 守りの結果ごとの件数) |
| `GET /api/policy-results/{id}/rows` | 方策の結果の表の一部 (`offset`, `limit`, `status` で絞る. 観測と行動は JSON の文字) |
| `GET /api/policy-results/{id}/download` | 方策の結果の表の CSV |
| `DELETE /api/policy-results/{id}` | 方策の結果を消す |

- 推論は同時に 1 つだけ (大きなモデルでメモリを使い切らないように). 推論に使う一式は組み立てたモデルごと少しだけ覚えて使い回す (既定は 4 つ. 環境変数 `ML_PROVIDE_MODEL_CACHE` で変える. モデル 1 つ分のメモリ (重みと組み立てたモデル) を数の分だけ使い続けるので, 大きなモデルでは 1 にする). 一覧と一式の画面の説明はモデルを組み立てずに別に覚え (256 個まで), 推論に使う一式を追い出さない. 登録を消した一式は手放す. 一式のディレクトリの全てのファイル (`inference.yaml`, 定義, データセットの説明とレシピ) と重みのファイルの更新時刻と大きさのどれかが変わったら読み直す (写さない重みは学習し直すと変わるため). 学習済みの重みの警告は, モデルを手放した後も一式が変わるまで出す
- 結論の出し直しと結果の削除は 1 つずつ行い, 書き換えは隣に書いてから置き換える (読んでいる途中の表が壊れないように). 推論の直後も, 書いた表を読み直して結論を出す (出し直したときと同じ型の値でまとめ, まとめの名前が変わらないように)
- 渡したデータに `index` の列がある場合, 表の行の位置の列と重ならないように「`index (入力)`」にする
- 結果を読むときは版を確かめ, 知らない新しい版 (ML-Inference の `RESULT_FORMAT_VERSION` より大きい) の結果は「この版の結果は読めません」で止める (一覧では飛ばす)
- 結論の出し直し, 意思決定, 列の効き, 1 行の予測の理由, たどり直し, 外れ方の測り直しは列の出力の結果だけ. 他の結果では「列の出力でない一式の結果には使えません」で断る (版 2 までの結果は全て列の出力)

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| 一式 | 推論の一式. `inference.yaml` を持つディレクトリ (ML-Inference の形). モデルの定義, 重み, データセットの説明とレシピを持つ |
| 結果 | 1 回の推論で置き場に残すもの (予測の表 `predictions.csv`, `result.yaml`, 配列の `artifacts/`) |
| 結論 | 予測から出す判断の内訳とまとめの文 |
| 結論の決め方 | 保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列 |
| 意思決定 | 損得と制約から行ごとの行動を決めること. 型は量を決める, 対象を選ぶ, 振り分ける |
| 外れ方 | 一式が記録した予測の外れ方 (`uncertainty`). 意思決定の前提 |
| 方策の一式 | 強化学習で学習した方策 (`policy.json` と `policy.pt` を持つディレクトリ. ML-Inference の形) |
| 守り | 方策の一式が持つ, 観測で止める条件, 行動の範囲, 外れたときの動き |
| 列の出力 | 出力の形がクラス, 値, 分布の一式. 結論の決め方と意思決定はこれだけに使う |
| 既製のモデル | 学習せずにそのまま使う, ライブラリの学習済みの重みのモデル (torchvision の ResNet18 など). 一式は版 6 |

## 6. 置き場

既定は `~/.ml-provide` (環境変数 `ML_PROVIDE_HOME` で変えられる).

```
~/.ml-provide/
├── bundles.json        # 登録した一式 (id, 名前, 場所, 置き場で作ったか, 登録した時刻, つないだ問題の設定の場所と作った時刻)
├── policies.json       # 登録した方策の一式 (id, 名前, 場所, 登録した時刻)
├── bundles/<id>/       # 画面で作った一式 (ML-Inference の形. 既製のモデルの一式は重みを持たない)
├── policy_results/<id>/  # 方策の結果 (このアプリの形. 版 1)
│   ├── actions.csv     # 1 件ずつの位置 (index), 観測と行動 (JSON の文字), 守りの結果, 理由
│   └── policy_result.yaml # 版, 方策の一式の id (policy_id), 名前と場所, 観測のファイル, 時刻, 件数 (rows), 守りの結果ごとの件数 (counts)
├── samples/sample<n>/  # 見本 (学習用のデータ, 一式, 推論を試す新しいデータと過去のデータ. 領域の見本はデータセットと新しい画像)
└── results/<id>/       # 推論の結果 (ML-Inference の write_result の形. 結果の形の版 1 か 2)
    ├── predictions.csv # 予測と判断の表 (結論を出し直すときは, 判断の列を除いて読み直す)
    ├── result.yaml     # 一式, 入力, 時刻, 決め方, まとめ, 文
    └── artifacts/      # 表に収まらない中身 (配列の出力の一式の結果だけ. 版 2)
```

- 一式の登録は場所だけを覚える (学習のスクリプトが実験の中に作った一式を, 写さずに使う). 置き場で作った一式は, 登録を消すと一式も消す
- 結果は一式ごとに新しい順に並べる. 一式を消しても結果は残す (一式の名前を結果にも書く)

## 7. 安全

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

- 推論は手元のファイルだけを読む. ただし既製のモデルの一式は, 出どころの重みが PyTorch の置き場に無ければ, 作るときと推論のときに出どころ (ライブラリが決めた URL) から取りに行く. 読んだ重みは記録した hash と比べ, 違えば誤りにする (ML-Inference の決まり). 置き場に手で置く重みのファイルは, 信頼できるものだけにする (hash を比べる前にライブラリが読み込むため)
- 実験の一覧は, 問題の設定の置き場とプロジェクトの `outputs` を読むだけ (リンクはたどらず, 深さと件数に上限を置く)
- 自作の手順と部品は, 起動の設定で明示したモジュールだけを読み込む. 一式やファイルに書かれた名前からは何も読み込まない (下の「8. 受け持ちと出力の形 (一式の版 3 と 4)」)
- 方策は観測から行動と守りの結果を返すだけで, 環境や機械には触れない. 方策の一式は ML-Inference が重みの sha256 を確かめてから読み, 組み立て方は一式に写したモデルの定義だけ (クラスの名前からコードを読み込まない)
- 実験のディレクトリには書かない. 書き戻しが要るときは置き場に写してから書く (上の「4. API」の `remeasure`)

## 8. 受け持ちと出力の形 (一式の版 3 と 4)

ML-Inference の一式の版 3 は, 受け持ち (`role`), 出力の形 (`output.form`), 正解の種類と出どころ (`target`), 繰り返しの手順 (`procedure`), 学習済みの重みの置き方 (`model.pretrained`) を持つ. 版 4 は版 3 に 1 件の扱い (`items`) を足した, ファイルの組のデータセットの一式 (下の「ファイルの組のデータセットの一式」). 版 1 と 2 の一式も読み, 受け持ちは予測する, 出力の形はタスクから, 正解の種類は列として扱う.

- 一式の画面に, 版, 受け持ち, 出力の形 (形ごとの欄: 分布の水準, 領域のクラスの名前, 雑音から始まる手順の 1 件の形), 正解の種類と出どころ, 手順 (名前, 回数, 乱数の種, 設定. 設定と読み込みの設定は「名前 値」の並びで出す. 入れ子の値と, 空, 空白, カンマ, 括弧を含む文字, 引用符か [ { で始まる文字, 数や真偽や null に見える文字 (0, 1e3, 0x1, inf, nan, yes, on, ~, 2026-11-22 など. 大文字と小文字を区別しない) は JSON の引用符を付ける. 文字の "0" と数の 0 を見分け, YAML 1.1 で読んでも型が変わらないようにするため), 学習済みの重みの置き方 (ノードごとの出どころ, 版, ライセンス, 置き場) を出す. `describe_bundle` の `target` は目的の列の名前で, 正解の種類と出どころは `target_info`
- 列の出力か (`column_output`) で推論の流れを分ける. 列の出力 (`class`, `value`, `distribution`) は表の流れ (`infer` → `write_result` → 書いた表を読み直して `conclude`). 列の出力でないものは, 結論の決め方と意思決定の欄を隠し, `infer` の件数だけの結論 (ML-Inference の `conclude_outputs`) を使う. 書いた表を読み直して件数を数え直すときは `conclude` をかけず, `read_result` で読んだ結果をそのまま `write_result` に渡す (配列は持ち越す)
- 結果には一式の受け持ち, 出力の形, 列の出力か, 正解の種類と出どころ, 学習済みの重みの警告を残す (一式を消しても結果の画面で分かるように)
- 配列の見せ方 (`GET /api/results/{id}/artifacts/{row}`. `read_result` で読み, `artifact_path` で結果のディレクトリの中に解決する): 領域は行と列を間引いた (最大 256 × 256) 整数の格子を返し, 画面はクラスごとの色で描く. 画像は (高さ, 幅), (高さ, 幅, チャンネル), (チャンネル, 高さ, 幅) を最小と最大で 0 から 255 にした格子で返し, 画面は描く. 点群は最大 2,000 点を間引いて最初の 3 つの次元を返し, 画面は 2 つの次元を選ぶ散布図にする. ベクトルは形, 長さ (L2), 最初の 16 個の値. どの形も `.npy` を落とせる. 配列は `mmap_mode` で開き, 先に間引いた分だけを数にする (長さと領域の画素の数は区切って数える). 見本を作るのは同時に 2 つまで. 値が 2 億個を超える配列と, 実数, 整数, 真偽でない配列 (複素数, 構造のある型, 文字. オブジェクトの配列は pickle を読まないので読めない) は見せずに理由を返す. CSV のダウンロードは表だけで, 配列の列は結果の中の相対パス
- 文を出す一式 (`text`) の結果は表に収まる (`prediction` に一式のレシピの語彙で戻した文, `tokens` に番号を空白でつないだ文字. ML-Inference の決まり) ので結果の形は版 1. 結論は件数だけ. 予測の表は ML-Inference の `read_result` で読む (文と番号を文字のまま読み, 予測した行の空の文と番号は空の文字. 番号 1 つの並びや数と `NA` に見える文を数や欠損にしないため. 決まりを 2 か所に持たないように自分では解釈しない). `read_result` は `tokens` の列で文の出力かを見分けるので, `tokens` の列の無い古い文の結果 (`result.yaml` の出力の形が `text`) だけは, `read_result` がこの形を見分けられない例外として, 予測の列を同じ欠損の決まりで文字のまま読み直す (全ての行が番号 1 つの予測でも `5.0` のような数にしないため). 渡したデータの `tokens` の列は「`tokens (入力)`」になる
- 正解の出どころが今の処理 (`target_info.origin.type` が `process`) の一式は, 一式の画面に「正解は … の出力なので, 予測はその処理との一致までしか分からず, その処理を超えられません」を出す. 結果の画面にも出す. 結論の文には混ぜず, 結果の `origin_note` に分ける (まとめる列ごとの文と全体の文の分け目を崩さないため. 全体の文の数は結果の `overall_count`)
- 学習済みの重みの注意 (`notes`) と警告 (`pretrained_warnings`. 出どころから読んだ重みの hash が記録と違うなど) は必ず出す. 警告はモデルを組み立てた後に分かるので, 一式の画面は組み立てる前ならそう書き, 推論の後は結果にも残す

### ファイルの組のデータセットの一式 (一式の版 4)

ML-EDA の書き出しの約束の版 2 と版 3 のデータセット (`load_items` で読むファイルの組. 画像と領域, 撮影と点群. 版 3 は版 2 に, 書き出しでかけた項目ごとの中身の手順 (`steps`) を足した版) からも, 「学習の結果から作る」で一式を作る. 版 2 と版 3 は同じ画面と同じ欄で扱う. ML-Inference の `make_bundle` が, 学習のスクリプトがした 1 件の扱い (画像を 0 から 1 にする, 深度から点に戻して決まった数を選ぶ) を `items` に書いた版 4 の一式を作り, 推論で同じ扱いをかける. 版 1 のデータセットからは今のまま版 3 までの一式を作る.

- データセットを選ぶと `GET /api/datasets/describe` で版を読み, 版 2 と版 3 なら受け持ち, 正解の種類と出どころ, 入力と正解の項目 (名前と種類), 版 3 なら項目ごとの中身の手順 (`resize (width 64, height 64)` など), 分割ごとの件数を出す. 読むのは ML-Inference の `describe_items` (ML-EDA の `load_items` で読む) で, 読めないデータセットと知らない新しい版は ML-EDA の誤りの文をそのまま出す. 作れる組 (予測するで, 正解の種類が領域か点群) かどうかは `make_bundle` が確かめる. 説明を読めなかったデータセットでは「作る」を押せない (作る段階で分かりにくい誤りになるため)
- 版 3 の中身の手順は ML-Inference が一式のデータセットの写しから読み, 推論で新しい 1 件に同じ手順をかけてから 1 件の扱いをかける (大きさの違う画像も学習と同じ大きさにそろう). 元の画像の領域は件ごとに元の画像の大きさに戻して返り, データセットのディレクトリの件はデータセットの大きさのまま返る (ML-Inference の決まり. 戻すときに値を混ぜないので, 領域は領域の値だけのまま). このアプリは手順を見せるだけで, 欄は足さない
- 入力の項目が撮影か点群なら, 選ぶ点の数 (`items.options.points`) が要る (学習と違う数だと黙って違う予測になり, 一式の確かめでも気付けないことがあるため). 確かめで正解から選ぶ点の数 (`target_points`. 空なら正解の全ての点) と点を選ぶ乱数の種 (`seed`. 空なら 0) は任意. ML-Quest の骨組みで学習した実験なら, config の `data.input_points`, `data.target_points` と, 検証用の分割の種 (`data.seed` + 1) を書く (骨組みが実験の中に作る一式と同じ値になり, 一式の確かめが学習の記録と合う). 入力の項目が複数あれば選ぶ. 正解の項目, 扱い方, 領域の値, 点群の戻し方はデータセットから決める (ML-Inference の決まり)
- ファイルの組のデータセットでは, 前処理の外でしたこと (並びの先頭の番号, 目的の値の標準化) と, 受け持ちと出力の形の欄を出さない (前処理のレシピを持たず, 出力の形は正解の種類から決まるため). 出力が複数のモデルの出力の名前の欄は出す
- 一式の画面は, 列の一式の読み込みと前処理の代わりに 1 件の扱い (入力の項目と種類, 扱い方, 設定, 正解の項目, 点群の戻し方) を出し, 出力の形の欄に領域の値ごとの名前を出す. 一式での評価は, 領域は IoU (背景を除くクラスの平均), 点群は Chamfer 距離で, 実験の記録 (`valid/iou`, `valid/chamfer`) と比べた結果を添える
- 推論するデータは, 入力の項目と同じ種類の元のファイル (画像のファイルかディレクトリ, 撮影のディレクトリかそれを並べたディレクトリ, 点群のファイルかディレクトリ) か, ファイルの組のデータセットのディレクトリ (入力の項目の中身の手順が一式と同じもの. 違えば ML-Inference が止める). 元の撮影には学習と同じ正規化 (と中身の手順) をかけ, 読めない件は理由を付けて飛ばす (ML-Inference の `predict`)
- 結果の領域は領域の値 (データセットの領域のファイルと同じ値) の格子で, 凡例は値ごとの名前 (一式の `items.values` と `output.classes` を並べた組). 点群は元の座標 (戻し方が `shift` なら, 正規化の平行移動を戻した撮影の世界の座標. メートル) の散布図で, そう書き添える
- 実験の一覧は, ML-Quest の骨組み (領域と点群) が実験の中に作った版 4 の一式も同じく並べる (一覧は `inference.yaml` の版を見ない. 読めるかは登録のときに確かめる)

### 雑音だけの一式 (一式の版 5)

ML-Inference の雑音だけの一式 (`dataset: null`) は, 条件の無い生成のモデル (拡散やフローのモデル) の一式で, データセットを持たず, データの行の代わりに件数と種から生成する. 説明の `kind` は `noise` で, 画面では「雑音だけ」と出す.

- 作り方: `POST /api/bundles/create` で `dataset` を省くか空にし, 雑音から始まる手順 (`procedure`), 1 件の形 (`output_options.shape`), 配列の出力の形 (`form`), 入力の出どころ (`inputs`. `state` と `time` だけ) を渡す. 要る欄と組の確かめ (手順の 2 件の生成も) は ML-Inference の `make_bundle` がする
- 推論: `POST /api/bundles/{id}/predict` に件数 (`count`) と種 (`seed`) を渡し, ML-Inference の `infer` に `{"count": n, "seed": s}` を渡す. ファイルか文を一緒に渡すと断り, 雑音だけの一式でない一式に件数か種を渡しても断る. 結果の入力の文は ML-Inference の「件数 n, 種 s」(種を省けば一式の手順の種)
- 件数の上限: 1 回に 1,000 件まで, かつ件数 × 1 件の形の値の数が 1 億 (float32 で 400 MB) まで. ML-Inference は始まりの雑音を全ての件の分を一度に作り, 出力も件ごとに記憶に持ってから書くため, 大きな件数で記憶を使い切らないように画面が決める. 上を超えると, 1 件の形と受け付ける件数を書いて断る. 1 件だけで値の数の上限を超える形は「1 件の形が大きすぎます」で断る. 作るときの 1 件の形の誤り (`output.shape` の誤りと, モデルの入力と形が合わない実行時の誤り) には, 1 件の形の欄を見直す案内を添える. 重みが定義と合わない誤り (`state_dict` の誤り) には添えない (形の欄では直らないため). 雑音だけの一式を作るときも, ML-Inference が確かめで 2 件を作るので, `output_options.shape` の 2 件が上限を超えれば作る前に断る (データセットのある一式は確かめの件数が決まらないので当てない)
- 同じ一式, 同じ件数, 同じ種なら同じ出力 (ML-Inference の決まり). 結果の表は件ごとの番号 (`sample`), 使った種 (`seed`), 配列の列で, 配列の見せ方は他の列の出力でない一式と同じ
- 画面: 一式を作る対話の「雑音だけから作る」で作る (入力の欄には手順の中身と時刻の 2 つの行を用意する. 名前はモデルの定義の入力の名前. 選ぶと候補から外れる手順と出力の形を空にし, 前からある行の表の列か中身の出どころは問題として出す. 選ぶのをやめると, 畳む欄に見えない値を残して送らないように, 自動で足した行 (書き換えていないもの), 手順, 受け持ち, 出力の形と形ごとの欄を空に戻す. 先頭に足した番号は, 番号を足せる出どころ (中身, 手順の中身) の行だけ送る. 名前の無い入力の行と重なる名前があれば送らずに知らせる (名前は Map で数え, `constructor` や `__proto__` も名前として扱う). 畳んだ欄の誤りは見出しと同じ欄の名前を添えて出し, 欄の誤りの数が 0 から 1 以上になったときだけ欄を開く (開き閉じは利用者の操作を写して持ち, 自動では閉じない. 打っている途中に誤りが消えて欄が閉じないように). 誤りの文は polite で読み上げる. 手順を選んでいないのに出どころが手順の中身か時刻の行があれば, 手順を選ぶか出どころを変えるよう知らせる. 雑音だけの一式の行には先頭に足した番号の欄を出さず, 番号も送らない. 手順の設定の欄には既定値を薄い字で出す. 送った後に欄を変えたら, 前の誤りは出さない). 一式の画面は「データ」に雑音だけと出し, 読み込みと前処理の行と「問題の設定」の欄を出さない (データも正解も無く, 問題の設定の推論の結論と意思決定を使えないため. 問題の設定も読まない. 一覧で種類が分かれば要求もしない). 推論の欄は作る件数 (上限は `GET /api/info` の `max_samples`) と乱数の種 (空なら一式の手順の種)
- 正解も検証の分割も無いので, 一式の確かめ, 外れ方, 列の効き, 何段も先の予測, たどり直し, 測り直しは無い

### 既製のモデルの一式 (一式の版 6)

ML-Inference の既製のモデルの一式 (`ready`) は, 学習せずにそのまま使うライブラリの学習済みの重みの一式で, データセットと実験を持たず, 出どころ (ライブラリ, モデルの名前, 重みの名前), 種類の名前の表, 前処理を持つ. 今は画像の分類だけで, 出どころは torchvision だけ (ML-Inference の決まり). 説明の `kind` は `ready` で, 画面では「既製のモデル」と出す. 最初の実例は torchvision の ImageNet で学習した ResNet18 (`resnet18`, `IMAGENET1K_V1`. 1,000 の種類).

- 作り方: 一式の一覧の「既製のモデルから作る」の対話で, 出どころ (`GET /api/info` の `ready_libraries`), モデルの名前, 重みの名前を選ぶ (初めは ResNet18 の値). 打つのが止まってから少し待って下見 (`GET /api/ready/preview`) し, 種類の数と先頭の名前, 重みの版, 前処理 (短い辺をそろえる大きさと補い方, 真ん中を切り出す大きさ, 正規化の平均と標準偏差), 重みのファイルの名前, ライセンスの警告を出す. 下見できない間と, 一式の名前が空の間は「作って登録」を押せない. 重みの hash (sha256 の 16 進の 64 文字. 大文字と前後の空白はそろえる) は任意で, 書くと読んだ重みと違えば作らない (問題の設定や前に作った一式で決めておいた値)
- ライセンス: 下見でも作るときも, ML-ModelControl の `pretrained_info` で読んだ情報を `make_ready_bundle` に渡す (下見と一式の記録が同じ情報になるように). 読めなければ (登録されていない部品など), 「読めなかった」と警告の付いた情報を渡す (警告の無い記録にしないため). 画面は警告の印 (`alert`) が真なら `message` と `source` を並べて警告する. 印の無い記録は, 商用で使えると分かったもの (`commercial`) の他を警告する
- 重み: 一式に写さず, 使うときに出どころから読む (ML-Inference の決まり). 初めて作るときは出どころから取りに行くので, 作るのは 1 つずつにする (同じファイルを同時に取りに行かないように). torchvision の重み (URL から PyTorch の置き場の `checkpoints` にファイルの名前で置き, そこから読む) が置き場に無ければ, このアプリが `make_ready_bundle` の前に時間の上限 (全体で 600 秒, 読み込みが途切れて 30 秒) を付けて取り, 超えたら止めて誤りにする (ぶら下がった取得が鍵を持ったまま, 他の既製のモデルの作成を待たせないため). 届いた分だけ小さく読み, 読むたびに全体の上限を見る (細く流れ続ける接続も止めるため). 取るのは https の URL だけで, https でない URL への転送も断る. 隣の一時ファイルに書き (取れなかったときは消す), ファイルの名前に hash の頭があれば torch.hub と同じく比べてから置く. 取れないもの (ネットワークの誤り, 時間の上限, 壊れた中身) は 502 で返す (入力の誤りの 400 と分けるため). 一式の画面は重みのファイルの場所と, そこにあるか (`weights_cached`) を出す. 出どころの重みは一式の外 (PyTorch の置き場) にあり, 覚えた説明の印に入らないので, あるかは説明を返すたびに確かめ直す
- 一式の画面: 「データ」に画像 (既製のモデル), 出どころ, 前処理, 重みのファイルを出し, 読み込みと前処理の行を出さない. 「問題の設定」の欄は出す (下の「問題の設定」). クラスは数と先頭の 10 だけ. ライセンスの警告は推論の欄の上に出す. 推論の欄は画像のファイルか画像を並べたディレクトリで, 結論の決め方の欄を出す. 意思決定の欄の代わりに, 意思決定, たどり直し, 外れ方の確かめ, 列の効き, 何段も先の予測を使えないと書く (データセットと外れ方の記録を持たないため. API に渡しても ML-Inference が理由付きで断る)
- 推論: `POST /api/bundles/{id}/predict` に画像のファイルかディレクトリの場所 (`source`) と結論の決め方を渡す (意思決定は渡さない). 表は読み込みの表 (`path` など) と, `prediction` (種類の名前), `confidence`, `p:<種類>`. 読めない画像は理由を付けて飛ばす
- 問題の設定: ML-Quest の受け渡しの推論の `ready` (作り方が既製のモデルをそのままの予測だけが持つ. 出どころ, モデル, 重みの名前, 重みのハッシュ値) を持つ問題の設定をつなげる. 結論の決め方は, 一式の既定値に受け渡しの結論の決め方を重ねて推論の既定にする. 意思決定は使えないと書き, 問題の設定の意思決定は読まない (既製のモデルの一式は外れ方の記録を持たないため). 決めておいた `library`, `model`, `weights`, `sha256` のうち書いたものが一式と違えば, 食い違いとして出す (重みの名前は `READY_LIBRARIES` で版の決まった名前に直して比べる. `DEFAULT` と一式の `IMAGENET1K_V1` を違うと言わないため. 重みのハッシュ値は両方を小文字にして, 一式が読んだ重みのハッシュ値と比べる. 一式に記録が無ければ, 確かめられないと出す). 作り方が既製のモデルをそのままでない問題の設定は, つなげるが使わないと書き, 既定は一式の既定値のまま. 候補は, 一式の上のディレクトリにある作り方が既製のモデルをそのままの問題の設定だけ (ML-Quest の既製のモデルの骨組みは, プロジェクトの中に一式を作るため)
- 結果の画面: 意思決定と外れ方の確かめの欄を出さず, 使えないと書く. 結論の決め方を変えて出し直せる. 種類ごとの確率の列 (`p:<種類>`) が 20 を超えると予測の表には出さず, CSV にだけ入れると書く (ImageNet の 1,000 列を表に並べないため)

### 繰り返しの手順と起動の設定

- 一式の手順は ML-Inference の登録簿 (`ml_inference.procedures`) から名前で引く. 組み込みは `ddim`, `euler`, `greedy`, `sample`
- 研究の自作の手順は, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --procedures pkg.module,...` か環境変数 `ML_PROVIDE_PROCEDURES` (`,` で区切る) に書いたモジュールを起動のときに import し, モジュールが import のときに `register_procedure` で登録する. 読めないモジュールは起動を止める
- 一式やファイルに書かれたコードは自動では読まない. 登録簿に無い手順の一式は「手順 … は登録簿にありません. 自作の手順なら, 登録するモジュールを起動の設定 (`--procedures` か `ML_PROVIDE_PROCEDURES`) に足してから起動し直してください」で止める

### 自作の部品と起動の設定

- 研究の自作の部品 (ML-ModelControl の `register_unit` で登録する部品) も手順と同じく, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --units pkg.units,...` か環境変数 `ML_PROVIDE_UNITS` (`,` で区切る. 引数が環境変数より先) に書いたモジュールを, 起動のときに手順のモジュールの前 (手順のモジュールが部品を使えるように) で ML-Inference の `register_units` (ML-ModelControl の `register_units_from`) に渡す. モジュールは `UNITS` か `register_units(register)` で部品を宣言する (書き方は ML-ModelControl の docs/DESIGN.md の「自作の部品のモジュール」). 読めないモジュール, 部品を宣言していないモジュールは起動を止める
- `GET /api/info` の `unit_modules` に, 読んだモジュールと登録した部品の名前 (`[{"name": "pkg.units", "units": ["my.Block"]}]`) を返す
- 一式のモデルの定義に書かれた部品の名前からは何も読み込まない. 登録されていない部品を使う一式は, ML-Inference の `UnregisteredUnitError` (部品の名前とノード) に「自作の部品なら, 部品を宣言したモジュールを起動の設定 (`--units` か `ML_PROVIDE_UNITS`) に足してから起動し直してください」を添えて, 一式の画面 (一覧と一式の欄の誤り), 場所での登録, 画面で作る一式, 推論の誤りに出す

## 9. 問題の設定とのつなぎ

問題の設定 (ML-Quest の `problem.yaml`) は, 7 の「損得」で意思決定の型と損得と制約と根拠を, 5 の「機械学習の受け持ち」で当たりのクラス, 系列を分ける列, 何期先までを決める. 骨組みから学習した一式は, 学習した時点の値を一式の既定値に持つ. ただし, 画面で作った一式は既定値を持たず, 学習の後に問題の設定の損得を見直すと一式の既定値は古くなる. そこで, 一式に問題の設定をつなぎ, 推論の既定を問題の設定の今の値にする.

- つなぐと, 一式の画面の推論の意思決定と結論の決め方の既定を, ML-Quest の受け渡し (`handoff` の `inference`) から読む. 結論の決め方は, 一式の既定値に問題の設定の値 (まとめる列) を重ねる. 推論のたびに読み直す (問題の設定を ML-Pathfinder で直せば, 次の推論から使う)
- 今のやり方: 量を決める型で, 問題の設定に今のやり方 (`action.current`) があれば, 意思決定の `current` を ML-Inference の決まりにする. k 期前と平均は, 時刻の列 (問題の設定の予測の時刻の列, 分割の時刻の列, 一式の過去の値の手順の時刻の列の順. 一式の手順の列なら, 系列を分ける列も ML-Inference が一式の手順から補う), 問題の設定の系列を分ける列, データを入れたときに求めた 1 期の間隔 (`data.interval_seconds`. 無ければ ML-Inference が推論するデータの時刻の差から求める) を足す. 列は列の決まり (置いた後の量. 今ある量があっても問題の設定と同じ意味). 時刻の列がどこにも無ければ入れず, 一式との食い違いの欄で知らせる. 決まりの列 (時刻, 系列, 今のやり方の列) が一式の学習のデータに無ければ, 食い違いの欄で知らせる (ML-Inference の `check_baseline`). たどり直しは, 推論するデータに今のやり方の列が無くても, 決まりから行ごとの値を作って比べる (利用者が列を足さずに済むように). 選ぶと振り分けは受け渡しの列の名前のまま
- 意思決定の欄の「今のやり方の列」は, 決まりがあれば, 空のまま決まりで比べると書き, 「使わない」で外せる. 列を書けば, その列で比べる
- 損得の根拠 (`action.basis`) と, 意思決定の文 (ML-Quest の `describe` と同じ) を出す. 根拠の無い損得はそう知らせる
- 一式との食い違いを出す: 目的の列が違う, 意思決定の型が一式のタスクに合わない (ML-Inference の `check_decision`), 結論の決め方が合わない (`check_rules`). 食い違いがあっても既定にはするが, 推論の前に気付けるようにする
- 一式の学習のデータの列 (意思決定, 今のやり方, まとめる列の列が無いことを知らせるため) は, 一式のデータセットの説明から次の順で取る. 1. 元のデータの場所 (`source.path`. 手元の場所を残す版 1 の書き出し) が読めれば, そのファイルの列 2. 説明に残る入力の列 (`source.columns`. 表の書き出しだけ) 3. 説明とレシピから集めた列 (学習に使う列, 目的の列, 手順が読む列, 読み込みの設定の列). 3 は自動で見つけた時刻の列などが抜けて全てとは限らないので, 列が無いことを知らせない (誤って知らせないため). どれも無い一式 (文や画像) も知らせない
- つなぐときは, 渡せる問題の設定か (`handoff` が通るか) を確かめる. 機械学習を使わない問題の設定や, 直すところのある問題の設定は理由付きで断る
- つないだ後に問題の設定のファイルが別の問題の設定に置き換わった (作った時刻が違う) か, 読めなくなった場合は, 理由を出し, 既定は一式の既定値に戻す. つなぎは外さない (直せば戻る)
- 候補: 骨組みのプロジェクトは `problem.yaml` を持ち, 学習の実験の中に一式を作る. つないでいない一式は, 一式の場所から 4 つ上のディレクトリまでたどり, 最初に見つけた推論に渡せる問題の設定のファイル (`problem.yaml`) を候補に出す (つなぐかは利用者が決める)
- 元の問題の設定: 見つけたファイルは, 骨組みが写した学習の時点の写し. 写しが元の場所 (ML-Quest の `problem_origin`. ML-Pathfinder の置き場の `problem.yaml`) を持ち, 元があって推論に渡せるなら, 元を候補にする (写しをつなぐと, ML-Pathfinder で直した損得が届かないため). 元の場所を持たない写しと, 元が無いか推論に渡せない写しは, 写しを候補にし, 直した損得が届かないことを文で添える. つないだ問題の設定は推論のたびに読み直すので, 元をつなげば ML-Pathfinder で直した損得が次の推論の既定に入る
- 問題の設定への書き戻しはしない (推論の画面で変えた損得は, その結果の決め方として残す. 問題の設定を直すのは ML-Pathfinder)
- 問題の設定の版: ML-Quest の版 2 (受け持ちの並び `ml.parts`. 今は 1 つ) を読む. 版 1 のファイルは ML-Quest が読んだ後に版 2 に移す (ファイルは変えない) ので, 版 1 と版 2 で同じ値になる. 知っている版より新しいファイルは, 読めない理由を出して止まる (読める項目だけで読み違えないため)
- 受け持ちが列の予測 (予測するで, 正解の種類が表の列) の問題の設定だけ, 意思決定と結論の決め方を既定にする (既製のモデルの一式は, 作り方が既製のモデルをそのままの問題の設定の結論の決め方だけ. 8 の「既製のモデルの一式」). 他の受け持ち (作る, 並べる, まとめる, 効果を見積もる, 予測するで正解が点群や画像の領域など) は受け渡しの `inference` が空 (意思決定は無い) なので, つなげるが「この問題の設定の受け持ち (作る, 正解の種類は画像) の推論の結論はまだ扱いません. 意思決定と結論の決め方は一式の既定値のままです」(括弧の中は受け持ちごと)と出し, 推論の既定は一式の既定値のままにする. 候補には出さない

## 10. 実験の一覧

学習した実験の一式を, 場所を打たずに登録するための一覧. 骨組みのプロジェクトの学習のスクリプトは, 実験のディレクトリ (`outputs/<名前>/<日付>/<時刻>`) の中に推論の一式 (`inference`) か, 方策の骨組みなら方策の一式 (`policy`) を作る. 推論の一式と方策の一式は別の一覧にし, 同じ探し方で並べる.

- プロジェクトは, ML-Pathfinder の問題の設定の置き場 (環境変数 `ML_PATHFINDER_HOME`. 無ければ ML-Pathfinder と同じ既定の場所. その中の `problems/<id>/problem.yaml`) の問題の設定が記録したプロジェクト (`project.path`. ML-Quest の `record_project` が書く) から得る. 読めない問題の設定, 記録の無い問題の設定, 無いディレクトリは飛ばし, 同じプロジェクトは 1 つにまとめる
- 実験は, プロジェクトの `outputs` の下を 5 つ下のディレクトリまで探し (リンクはたどらない), `inference.yaml` を持つ `inference` を推論の一式, `policy.json` を持つ `policy` を方策の一式とする. 一式の更新の時刻の新しい順に並べ, 500 件で打ち切る (打ち切ったことを画面に出す)
- 行は, 問題の設定の名前, 出力先からの実験の場所 (名前/日付/時刻), 一式の場所, 一式を作った時刻. 登録済みの一式 (登録の場所か, 外れ方を書き戻したときに写した元の場所が同じもの. 方策の一式は登録の場所が同じもの) は「登録済み」として一式か方策の画面へつなぐ
- 一覧から登録すると, 名前を「問題の設定の名前 (実験の場所)」にして場所で登録し (同じ `POST /api/bundles` か `POST /api/policies`), 一式か方策の画面に移る. 一式は写さない. 場所で選ぶ登録も残す (置き場に記録の無いプロジェクトと, 骨組みでない一式のため)

## 11. 方策の一式

強化学習で学習した方策の一式 (ML-Found が書き出す `policy/`) を, ML-Inference の `load_policy` で読み, 画面に入れた観測から守りを当てた行動を見る. 形と守りの決まりは ML-Inference の docs/DESIGN.md の「方策の一式」が持ち, このアプリは自分で解釈しない.

- 登録: 推論の一式と別に `policies.json` に場所だけを覚える (一式は写さない). 登録の前に重みまで読み, 読めない一式は ML-Inference の誤りの文で断る. 同じ場所の二重の登録は断る
- 組み立て: 一式に写したモデルの定義 (`metadata.model.spec`) を持つ一式だけを読める. クラスの名前と引数 (`metadata.model.class`, `args`) だけの一式は, 名前からコードを読み込まない決まりのため, ML-Inference の誤りの文 (`metadata.model.spec` が無い) で断る
- 読み直し: 読んだ方策は 4 つまで覚えて使い回し, `policy.json`, 重み (`weights`), 写したモデルの定義 (`metadata.model.spec`) の更新時刻と大きさのどれかが変わったら読み直す (学習し直して書き出し直すと変わるため). 登録を外すと手放す
- 観測: 形や値の誤り (数でない, 形が違う, 有限でない, 止める条件の外) は断らずに, ML-Inference の守りの外れたときの動きとして返す (画面で守りの働きを確かめられるように). float にできない桁の大きな整数も, 数の配列にできない観測と同じ外れたときの動きにする. 要素 (入れ子のリストの中の値とリスト. 空のリストを並べた観測も上限に掛かるように) が 100,000 を超える観測だけは読まずに断る. 無い一式は観測を見る前に 404 にする
- 方策を動かすのは 1 つずつ. 推論とは鍵を分ける (大きな推論の間も行動を待たせないように)
- 観測のファイル: `.npy` は先頭の次元を観測の並びにする (pickle の配列は読まない). 値の型は小数, 整数, 真偽値だけ (文字, 複素数, 構造の型は理由を付けて断る). `.csv` は 1 行に 1 つの観測で, 1 行目に空でない数にできない欄があれば列の名前として読む (空の欄は見ない. 値の欠けた観測の行を列の名前と読まないため). 欄は整数, 小数 (`nan`, `inf` も) の順に読み, 数にできない欄は文字のまま渡して守りの外れたときの動きにする. 観測の空間が 1 つの値なら 1 つの欄をその値に, 多次元の box なら要素の数が合う行をその形に並べ直す. 1 つのファイルで 10,000 件, 値は全てで 1,000,000 個まで (1 件ずつ方策を動かすので, 長く止まらないように). 読む前にも止める: `.csv` はファイルが 32,000,000 バイト (約 32 MB. 1 つの値に 32 バイト) まで, `.npy` はファイルが 8,065,536 バイト (1 つの値に 8 バイトとヘッダの分) までで, ヘッダだけを読んで形の値の数と型を確かめてから中身を読む (ヘッダだけが巨大な形のファイルで記憶を使い切らないため). 方策を動かす鍵は件ごとに取り直す (長いファイルの間も 1 件ずつの行動を待たせないように) 1 件の観測の要素の上限は 1 件ずつのときと同じで, 超えた件は止めた (`stop`) として理由を残す
- 方策の結果: 置き場の `policy_results/<id>/` に, 1 件ずつの表 (`actions.csv`. 列は `index` (ファイルの中の観測の位置. 0 から), `observation` と `action` (JSON の文字. 行動なしは `null`), `status`, `reasons` (「 / 」で並べた理由)) とまとめ (`policy_result.yaml`. `format_version`, `policy_id` (方策の一式の id), `policy` (名前と場所), `source`, `created_at`, `rows` (件数), `counts` (守りの結果ごとの件数)) を隣に書いてから置き換えて残す. 持ち出しの CSV は, `=`, `+`, `-`, `@` で始まる数でない欄の頭に `'` を付ける (表計算のソフトが式として読まないように). 消している途中に表を読むと 404 形はこのアプリが持つ (推論の結果の形 (ML-Inference の `write_result`) は列の予測の表と結論のためのもので, 方策の行動と守りの結果を入れないため). 知らない新しい版は読まずに一覧から飛ばす. 方策の登録を外しても結果は残す (方策の名前と場所を結果にも書く)

## 12. 1 行の予測の理由

結果の画面で選んだ 1 行について, ML-Inference の `explain_rows` で元の列ごとの効き (`effect:<列>`. その列の値を他の行の値に替えたら予測がどれだけ変わるか. 正ならその行の値が予測を上げた) と理由の文 (`reason`) を求める.

- `explain_rows` は渡した全ての行で求め, 推論の回数は列の数 × 回数 (10 回) なので, 入力の全ての行ではなく, 選んだ行と比べる行だけを渡す. 比べる行は, 過去の値の列を作らない一式では入力から等しい間隔で選んだ 200 行 (効きは他の行の値に替えたときの変わり方なので, 選んだ行だけでは 0 になるため), 過去の値の列を作る一式では選んだ行の前の続いた 999 行 (過去の値に前の行が要るため)
- 入力は結果に残した入力のファイルを, 推論と同じ読み込み (学習のときの読み込みと設定に, 推論のときの設定を上書き) で読み直す. 行の数が推論したときと違えば, 行を合わせられないので断る
- 押すまで求めない (推論を繰り返すため). 求めた理由は結果に残さない

## 13. 課題の型への広げ方

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる. 推論と結論の中身は ML-Inference に足し, この画面はそれを使う. 列の出力でない一式は 1 件ごとの配列を見せる (上の「受け持ちと出力の形」) が, 結論と意思決定は列の出力 (確信, クラスの確率) と 3 つの意思決定を前提にしている.
