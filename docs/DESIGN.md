# 設計

ML-Provide の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

学習したモデルで新しいデータを推論し, 予測から結論を出す手元の Web アプリ. 推論と結論の中身は ML-Inference が持ち, このアプリは画面と, 画面のための API と置き場を持つ.

- 推論の一式 (ML-Inference の約束) を登録するか, 学習の結果 (モデルの定義, データセット, 実験) から画面で作る
- 新しいデータのファイルか, 画面に書いた文を推論し, 予測の表と結論 (判断の内訳, まとめの文) を見る
- 結論の決め方 (保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列) を画面で変え, 推論し直さずに結論だけを出し直す
- 結果を保存し, 後から開き, 予測の表を CSV で持ち出す
- 列の予測 (クラス, 値, 分布) でない一式 (領域, 点群, ベクトル, 画像, 文を出す一式. ML-Inference の一式の版 3 と 4) も推論し, 1 件ごとの配列を見る (下の「受け持ちと出力の形」)
- ML-EDA の版 2 のデータセット (画像と領域, 撮影と点群) からも一式を作り, 新しい画像や撮影の領域と, 元の座標の点群を見る (下の「版 2 のデータセットの一式」)

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「推論」の段階で画面を受け持つ. ライブラリは ML-Inference.

- ML-Inference は submodule. 推論, 結論, 一式の形など, 画面の外でも使う仕組みは ML-Inference に足す. 画面と API に固有のもの (置き場, 結果の一覧, ページ分け) はこのリポジトリに置く
- 構成と道具は ML-Dashboard, ML-CreateArchitecture, ML-Fathom にそろえる (将来の統合のため). バックエンドは FastAPI, 画面は React と Vite, 起動ごとのトークンと Origin の確認も同じ
- 意思決定 (損得と制約) と結論の決め方は, 本来は問題の設定の段階 (ML-Quest, ML-Pathfinder) が決める. 一式に問題の設定をつなぐと, 推論の既定値を問題の設定の今の値にする (下の「問題の設定とのつなぎ」). つないでいない一式は, 一式の既定値と画面で選んだ値を使う

## 2. 使うライブラリと約束

ML-Inference と ML-Quest は submodule. 形の決まりを 2 か所に持たないため, 一式, 結果, 問題の設定のファイルは自分で解釈せず, それぞれのライブラリの関数で読み書きする.

| ファイル | 持ち主 | このアプリの扱い | 読む版 |
| --- | --- | --- | --- |
| 推論の一式 (`inference.yaml` と, モデルの定義, 重み, データセットの説明とレシピ) | ML-Inference | 登録した場所から読む (`load_bundle`, `describe_bundle`). 画面で作る一式は `make_bundle` で置き場に書く. 測り直した外れ方は一式に書き戻す (`remeasure`. 下の API の表) | 1 から 4 |
| 推論の結果 (`predictions.csv`, `result.yaml`, `artifacts/`) | ML-Inference | 置き場に書いて読む (`write_result`, `read_result`) | 1 と 2. `RESULT_FORMAT_VERSION` より新しい版は「この版の結果は読めません」で止める (一覧では飛ばす) |
| 問題の設定 (`problem.yaml`) | ML-Quest | 読むだけ (受け渡しの `handoff` の `inference` と, 今のやり方 `action.current`, 写しの元の場所 `problem_origin`, 書き出したプロジェクトの記録 `project`). 書き戻さない | 1 と 2. 新しい版は読めない理由を出して止まる |
| データセット | ML-EDA (ML-Fathom で書き出す) | 一式を作るときに `make_bundle` に渡す. 読めるのは `make_bundle` が読む形 (版 1 の列のデータセットと, 版 2 のファイルの組). 一式を作る画面で版 2 のデータセットの項目を見せるために, ML-EDA の `load_items` で読む (書かない). 見本の一式は ML-Inference の `make_sample_bundle` が作る (このアプリは ML-ModelControl を直接使わない) | ML-Inference に従う |
| モデルの定義 | ML-ModelControl (ML-CreateArchitecture で組む) | 一式を作るときに `make_bundle` に渡す | ML-Inference に従う |
| 実験のディレクトリ (重み, `run.json`) | ML-Found | 一式を作るときに読む. 書かない |  |

- 実験のディレクトリには書かない (ML-Found の約束). 画面で作る一式は, このアプリの置き場に作る
- ML-Quest は submodule. 問題の設定のファイルは ML-Quest を通して読む (YAML を自分で解釈しない)

## 3. 画面

| 画面 | 内容 |
| --- | --- |
| 一式 | 登録した一式の一覧 (名前, データの種類, タスク, クラス, 実験の状態とベストの値). 実験の一覧から選んで登録するか (下の「実験の一覧」), 場所で登録するか, 学習の結果から作る (版 2 のデータセットなら入力と正解の項目を見せ, 点を選ぶ数と種の欄を出す). 試すための見本の一式を入れる (見本は学習の基盤を使わずに, ML-Inference の `make_sample_bundle` で小さなモデルを全ての行で 300 回更新して作る. 実験の記録は無い) |
| 一式の詳細 | 一式の説明 (データの種類, タスク, 目的の列, クラス, 学習に使う列, 読み込み, 前処理の手順, モデルの入力, 実験, 検証用の分割を一式で推論した評価と実験の記録が合うか, 外れ方の記録 (測り直した一式は作ったときの記録に戻せる), 注意. 版 3 と 4 の一式は受け持ち, 出力の形, 正解の種類と出どころ, 手順, 学習済みの重みの置き方と警告も. 版 4 の一式は 1 件の扱いも). 列の出力でない一式は結論の決め方と意思決定の欄を出さず, 件数だけを出すと書く. 問題の設定 (つないだ問題の設定の名前, 意思決定の文, 損得の根拠, 一式との食い違い. つないでいなければ候補 (元の問題の設定か学習の時点の写しかの文を添える) とつなぐ場所の欄). 推論するデータ (ファイルを選ぶか, 文の一式なら文を書く) と結論の決め方を選んで推論する (つないだ一式は問題の設定の値が既定). 過去の結果の一覧 |
| 結果 (列の出力でない一式) | 件数だけの結論の文, 正解の出どころの注意, 学習済みの重みの警告, 予測の表 (配列の出力は行を選ぶと, 領域と画像は絵, 点群は散布図, ベクトルは形と最初の値. `.npy` を落とせる), CSV のダウンロード |
| 結果 | 意思決定 (行動の文, 前提, 決め直し, 過去のデータでのたどり直しと差の幅), 外れ方の確かめ (目的の列のある入力の結果だけ. 今の記録がこの実績を覆った割合と測り直した幅を見て, 確認の上で一式に書き戻す. 何段も先まで予測できる一式では, 何段先までと予測を始める時刻の列を選ぶと段ごとの外れ方も測る. 書き戻した後の推論と決め直しから使う. 一式の画面で作ったときの記録に戻せる), 結論の文, 判断の内訳 (帯グラフ), まとめる列ごとの表, 列の効き (押すと求める), 予測の表 (ページ分け, 予測しなかった行と判断で絞る), 決め方を変えて出し直す, CSV のダウンロード |

## 4. API

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/auth` | 起動したときのトークンを Cookie に保存して画面に移る |
| `GET /api/info` | ML-Inference の版, 結論の決め方の項目, 繰り返しの手順の登録簿の名前 (組み込みか), 起動の設定で読んだ手順のモジュール (`procedure_modules`) と部品のモジュール (`unit_modules`) |
| `GET /api/browse` | ディレクトリの中身 (ファイルとディレクトリを選ぶため) |
| `GET /api/bundles` | 登録した一式の一覧 (読めない一式は理由付き) |
| `POST /api/samples` | 見本の一式 (表の分類, 表の回帰, 時系列の先の予測, 文の分類) を, 見本のデータでその場で学習して作り登録する. 意思決定の既定値と, たどり直しを試す目的の列のある過去のデータも付ける (時系列は 120 日. 7 段先までの外れ方を段ごとに測れる長さ) |
| `GET /api/experiments` | 問題の設定の置き場 (ML-Pathfinder) に記録したプロジェクトの, 推論の一式を持つ実験の一覧 (下の「実験の一覧」) |
| `POST /api/bundles` | 場所を指定して登録 (`inference.yaml` を持つディレクトリ. 名前は省略すると一式の名前) |
| `GET /api/datasets/describe` | データセットのディレクトリ (`path`) の版と, 版 2 なら受け持ち, 正解の種類と出どころ, 項目 (名前, 種類, 役), 入力と正解の項目, 分割, 領域の値の名前, 点を選ぶ欄が要るか (下の「版 2 のデータセットの一式」) |
| `POST /api/bundles/create` | モデルの定義, データセット, 実験 (か重み) から置き場に作って登録. 版 2 のデータセットは 1 件の扱い (`items`) も渡せる |
| `GET /api/bundles/{id}` | 一式の説明 (ML-Inference の `describe_bundle`) と, モデルを組み立てたか (`model_loaded`. 学習済みの重みの警告は組み立てた後に出る). 手順が登録簿に無い一式は, 起動の設定に足すよう案内を添えた誤り |
| `GET /api/bundles/{id}/problem` | つないだ問題の設定から読んだ推論の値 (名前, 場所, 中身の印, 受け持ち, 推論の結論を扱う受け持ちか, 意思決定, 結論の決め方, 何期先まで, 損得の根拠, 一式との食い違い). つないでいなければ, 一式の場所から上にたどって見つけた問題の設定の候補 (`hint`. 写しが元の場所を持てば元) と, 元か写しかの文 (`hint_note`). 読めなくなっていれば理由 |
| `PUT /api/bundles/{id}/problem` | 問題の設定をつなぐ (`path` は problem.yaml かそのディレクトリ. 渡せない問題の設定は理由付きで断る). `path` が空ならつなぎを外す |
| `DELETE /api/bundles/{id}` | 登録を消す (置き場で作った一式は一式も消す) |
| `POST /api/bundles/{id}/restore-uncertainty` | 測り直した外れ方を, 一式を作ったときの記録に戻す (ML-Inference の `restore_uncertainty`) |
| `POST /api/bundles/{id}/predict` | ファイルの場所か文の並びを推論し, 結論を出して結果を保存. `forecast` で何段も先の予測 (目的の列の過去の値を使う回帰と予測の一式. 結果は先の行だけ). `decision` で意思決定もする (省略は一式の既定値, 空の辞書で意思決定しない). 列の出力でない一式では, 結論の決め方, 意思決定, 何段も先の予測を渡すと断り, 結論は件数だけ |
| `GET /api/results` | 結果の一覧 (`bundle` で絞れる) |
| `GET /api/results/{id}` | 結果のまとめ, 文, 決め方, 列 |
| `GET /api/results/{id}/rows` | 予測の表の一部 (`offset`, `limit`, `status`, `decision` で絞る) |
| `GET /api/results/{id}/artifacts/{row}` | 配列の出力の結果の, 行の位置の配列の見本 (形, 型, 出力の形ごとの見せ方. 下の「受け持ちと出力の形」) |
| `GET /api/results/{id}/artifacts/{row}/file` | 行の位置の配列のファイル (`.npy`) |
| `POST /api/results/{id}/conclude` | 決め方を変えて結論だけを出し直す (結果を書き換える) |
| `POST /api/results/{id}/explain` | 入力の列ごとの効き (ML-Inference の `explain`) を求めて結果に残す (表と時系列のファイルの結果だけ) |
| `POST /api/results/{id}/decide` | 意思決定の決め方を変えて決め直す (推論はし直さない. 空で外す) |
| `POST /api/results/{id}/backtest` | 結果の入力 (目的の列を持つファイル) で, 意思決定の方針と素朴なやり方の実際の得と損を比べる |
| `POST /api/results/{id}/remeasure` | 結果の入力 (目的の列を持つファイル) で一式の予測の外れ方を測り直す (ML-Inference の `remeasure`). `write` が偽なら確かめるだけ, 真なら一式に書き戻す (置き場の外の一式なら, 登録した場所のファイルを書き換える. ただし学習の実験のディレクトリの中の一式 (一式か上の 2 つのディレクトリに `run.json` がある) は, 実験を書き換えないという ML-Found の約束に合わせて, 置き場に写してから書き戻し, 登録を写した方に移す. 応答の `copied_to` に写した場所. 「作ったときの記録に戻す」も同じ. 写しの登録は `copied_from` に元の場所を持ち, 元の場所を同じ登録として二重に登録しない. 写しを消しても元の実験の一式は残る. 写すか書き戻すかに失敗したら写しを消し, 登録は移さない). `horizon` と `time` で何段も先の外れ方も段ごとに測る (目的の列の過去の値を使う一式だけ. 画面は確かめたときの段の数と時刻の列で書き戻す). 結果には残さない |
| `GET /api/results/{id}/download` | 予測と判断の CSV |
| `DELETE /api/results/{id}` | 結果を消す |

- 推論は同時に 1 つだけ (大きなモデルでメモリを使い切らないように). 推論に使う一式は組み立てたモデルごと少しだけ覚えて使い回す (既定は 4 つ. 環境変数 `ML_PROVIDE_MODEL_CACHE` で変える. モデル 1 つ分のメモリ (重みと組み立てたモデル) を数の分だけ使い続けるので, 大きなモデルでは 1 にする). 一覧と一式の画面の説明はモデルを組み立てずに別に覚え (256 個まで), 推論に使う一式を追い出さない. 登録を消した一式は手放す. 一式のディレクトリの全てのファイル (`inference.yaml`, 定義, データセットの説明とレシピ) と重みのファイルの更新時刻と大きさのどれかが変わったら読み直す (写さない重みは学習し直すと変わるため). 学習済みの重みの警告は, モデルを手放した後も一式が変わるまで出す
- 結論の出し直しと結果の削除は 1 つずつ行い, 書き換えは隣に書いてから置き換える (読んでいる途中の表が壊れないように). 推論の直後も, 書いた表を読み直して結論を出す (出し直したときと同じ型の値でまとめ, まとめの名前が変わらないように)
- 渡したデータに `index` の列がある場合, 表の行の位置の列と重ならないように「`index (入力)`」にする
- 結果を読むときは版を確かめ, 知らない新しい版 (ML-Inference の `RESULT_FORMAT_VERSION` より大きい) の結果は「この版の結果は読めません」で止める (一覧では飛ばす)
- 結論の出し直し, 意思決定, 列の効き, たどり直し, 外れ方の測り直しは列の出力の結果だけ. 他の結果では「列の出力でない一式の結果には使えません」で断る (版 2 までの結果は全て列の出力)

## 5. 用語

| 用語 | 意味 |
| --- | --- |
| 一式 | 推論の一式. `inference.yaml` を持つディレクトリ (ML-Inference の形). モデルの定義, 重み, データセットの説明とレシピを持つ |
| 結果 | 1 回の推論で置き場に残すもの (予測の表 `predictions.csv`, `result.yaml`, 配列の `artifacts/`) |
| 結論 | 予測から出す判断の内訳とまとめの文 |
| 結論の決め方 | 保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列 |
| 意思決定 | 損得と制約から行ごとの行動を決めること. 型は量を決める, 対象を選ぶ, 振り分ける |
| 外れ方 | 一式が記録した予測の外れ方 (`uncertainty`). 意思決定の前提 |
| 列の出力 | 出力の形がクラス, 値, 分布の一式. 結論の決め方と意思決定はこれだけに使う |

## 6. 置き場

既定は `~/.ml-provide` (環境変数 `ML_PROVIDE_HOME` で変えられる).

```
~/.ml-provide/
├── bundles.json        # 登録した一式 (id, 名前, 場所, 置き場で作ったか, 登録した時刻, つないだ問題の設定の場所と作った時刻)
├── bundles/<id>/       # 画面で作った一式 (ML-Inference の形)
├── samples/sample<n>/  # 見本 (学習用のデータ, 一式, 推論を試す新しいデータと過去のデータ)
└── results/<id>/       # 推論の結果 (ML-Inference の write_result の形. 結果の形の版 1 か 2)
    ├── predictions.csv # 予測と判断の表 (結論を出し直すときは, 判断の列を除いて読み直す)
    ├── result.yaml     # 一式, 入力, 時刻, 決め方, まとめ, 文
    └── artifacts/      # 表に収まらない中身 (配列の出力の一式の結果だけ. 版 2)
```

- 一式の登録は場所だけを覚える (学習のスクリプトが実験の中に作った一式を, 写さずに使う). 置き場で作った一式は, 登録を消すと一式も消す
- 結果は一式ごとに新しい順に並べる. 一式を消しても結果は残す (一式の名前を結果にも書く)

## 7. 安全

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

- 推論は手元のファイルだけを読む
- 実験の一覧は, 問題の設定の置き場とプロジェクトの `outputs` を読むだけ (リンクはたどらず, 深さと件数に上限を置く)
- 自作の手順と部品は, 起動の設定で明示したモジュールだけを読み込む. 一式やファイルに書かれた名前からは何も読み込まない (下の「8. 受け持ちと出力の形 (一式の版 3 と 4)」)
- 実験のディレクトリには書かない. 書き戻しが要るときは置き場に写してから書く (上の「4. API」の `remeasure`)

## 8. 受け持ちと出力の形 (一式の版 3 と 4)

ML-Inference の一式の版 3 は, 受け持ち (`role`), 出力の形 (`output.form`), 正解の種類と出どころ (`target`), 繰り返しの手順 (`procedure`), 学習済みの重みの置き方 (`model.pretrained`) を持つ. 版 4 は版 3 に 1 件の扱い (`items`) を足した, 版 2 のデータセットの一式 (下の「版 2 のデータセットの一式」). 版 1 と 2 の一式も読み, 受け持ちは予測する, 出力の形はタスクから, 正解の種類は列として扱う.

- 一式の画面に, 版, 受け持ち, 出力の形 (形ごとの欄: 分布の水準, 領域のクラスの名前, 雑音から始まる手順の 1 件の形), 正解の種類と出どころ, 手順 (名前, 回数, 乱数の種, 設定), 学習済みの重みの置き方 (ノードごとの出どころ, 版, ライセンス, 置き場) を出す. `describe_bundle` の `target` は目的の列の名前で, 正解の種類と出どころは `target_info`
- 列の出力か (`column_output`) で推論の流れを分ける. 列の出力 (`class`, `value`, `distribution`) は表の流れ (`infer` → `write_result` → 書いた表を読み直して `conclude`). 列の出力でないものは, 結論の決め方と意思決定の欄を隠し, `infer` の件数だけの結論 (ML-Inference の `conclude_outputs`) を使う. 書いた表を読み直して件数を数え直すときは `conclude` をかけず, `read_result` で読んだ結果をそのまま `write_result` に渡す (配列は持ち越す)
- 結果には一式の受け持ち, 出力の形, 列の出力か, 正解の種類と出どころ, 学習済みの重みの警告を残す (一式を消しても結果の画面で分かるように)
- 配列の見せ方 (`GET /api/results/{id}/artifacts/{row}`. `read_result` で読み, `artifact_path` で結果のディレクトリの中に解決する): 領域は行と列を間引いた (最大 256 × 256) 整数の格子を返し, 画面はクラスごとの色で描く. 画像は (高さ, 幅), (高さ, 幅, チャンネル), (チャンネル, 高さ, 幅) を最小と最大で 0 から 255 にした格子で返し, 画面は描く. 点群は最大 2,000 点を間引いて最初の 3 つの次元を返し, 画面は 2 つの次元を選ぶ散布図にする. ベクトルは形, 長さ (L2), 最初の 16 個の値. どの形も `.npy` を落とせる. 配列は `mmap_mode` で開き, 先に間引いた分だけを数にする (長さと領域の画素の数は区切って数える). 見本を作るのは同時に 2 つまで. 値が 2 億個を超える配列と, 実数, 整数, 真偽でない配列 (複素数, 構造のある型, 文字. オブジェクトの配列は pickle を読まないので読めない) は見せずに理由を返す. CSV のダウンロードは表だけで, 配列の列は結果の中の相対パス
- 文を出す一式 (`text`) の結果は表に収まる (`prediction` に番号の並び) ので結果の形は版 1. 結論は件数だけ
- 正解の出どころが今の処理 (`target_info.origin.type` が `process`) の一式は, 一式の画面に「正解は … の出力なので, 予測はその処理との一致までしか分からず, その処理を超えられません」を出す. 結果の画面にも出す. 結論の文には混ぜず, 結果の `origin_note` に分ける (まとめる列ごとの文と全体の文の分け目を崩さないため. 全体の文の数は結果の `overall_count`)
- 学習済みの重みの注意 (`notes`) と警告 (`pretrained_warnings`. 出どころから読んだ重みの hash が記録と違うなど) は必ず出す. 警告はモデルを組み立てた後に分かるので, 一式の画面は組み立てる前ならそう書き, 推論の後は結果にも残す

### 版 2 のデータセットの一式 (一式の版 4)

ML-EDA の書き出しの約束の版 2 のデータセット (`load_items` で読むファイルの組. 画像と領域, 撮影と点群) からも, 「学習の結果から作る」で一式を作る. ML-Inference の `make_bundle` が, 学習のスクリプトがした 1 件の扱い (画像を 0 から 1 にする, 深度から点に戻して決まった数を選ぶ) を `items` に書いた版 4 の一式を作り, 推論で同じ扱いをかける. 版 1 のデータセットからは今のまま版 3 までの一式を作る.

- データセットを選ぶと `GET /api/datasets/describe` で版を読み, 版 2 なら受け持ち, 正解の種類と出どころ, 入力と正解の項目 (名前と種類), 分割ごとの件数を出す. 読むのは ML-EDA の `load_items` で, 読めないデータセットと知らない新しい版は ML-EDA の誤りの文をそのまま出す. 作れる組 (予測するで, 正解の種類が領域か点群) かどうかは `make_bundle` が確かめる
- 入力の項目が撮影か点群なら, 選ぶ点の数 (`items.options.points`) が要る (学習と違う数だと黙って違う予測になり, 一式の確かめでも気付けないことがあるため). 確かめで正解から選ぶ点の数 (`target_points`. 空なら正解の全ての点) と点を選ぶ乱数の種 (`seed`. 空なら 0) は任意. ML-Quest の骨組みで学習した実験なら, config の `data.input_points`, `data.target_points` と, 検証用の分割の種 (`data.seed` + 1) を書く (骨組みが実験の中に作る一式と同じ値になり, 一式の確かめが学習の記録と合う). 入力の項目が複数あれば選ぶ. 正解の項目, 扱い方, 領域の値, 点群の戻し方はデータセットから決める (ML-Inference の決まり)
- 版 2 のデータセットでは, 前処理の外でしたこと (並びの先頭の番号, 目的の値の標準化) と, 受け持ちと出力の形の欄を出さない (前処理のレシピを持たず, 出力の形は正解の種類から決まるため). 出力が複数のモデルの出力の名前の欄は出す
- 一式の画面は, 列の一式の読み込みと前処理の代わりに 1 件の扱い (入力の項目と種類, 扱い方, 設定, 正解の項目, 点群の戻し方) を出し, 出力の形の欄に領域の値ごとの名前を出す. 一式での評価は, 領域は IoU (背景を除くクラスの平均), 点群は Chamfer 距離で, 実験の記録 (`valid/iou`, `valid/chamfer`) と比べた結果を添える
- 推論するデータは, 入力の項目と同じ種類の元のファイル (画像のファイルかディレクトリ, 撮影のディレクトリかそれを並べたディレクトリ, 点群のファイルかディレクトリ) か, 版 2 のデータセットのディレクトリ. 元の撮影には学習と同じ正規化をかけ, 読めない件は理由を付けて飛ばす (ML-Inference の `predict`)
- 結果の領域は領域の値 (データセットの領域のファイルと同じ値) の格子で, 凡例は値ごとの名前 (一式の `items.values` と `output.classes` を並べた組). 点群は元の座標 (戻し方が `shift` なら, 正規化の平行移動を戻した撮影の世界の座標. メートル) の散布図で, そう書き添える
- 実験の一覧は, ML-Quest の骨組み (領域と点群) が実験の中に作った版 4 の一式も同じく並べる (一覧は `inference.yaml` の版を見ない. 読めるかは登録のときに確かめる)

### 繰り返しの手順と起動の設定

- 一式の手順は ML-Inference の登録簿 (`ml_inference.procedures`) から名前で引く. 組み込みは `ddim`, `euler`, `greedy`, `sample`
- 研究の自作の手順は, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --procedures pkg.module,...` か環境変数 `ML_PROVIDE_PROCEDURES` (`,` で区切る) に書いたモジュールを起動のときに import し, モジュールが import のときに `register_procedure` で登録する. 読めないモジュールは起動を止める
- 一式やファイルに書かれたコードは自動では読まない. 登録簿に無い手順の一式は「手順 … は登録簿にありません. 自作の手順なら, 登録するモジュールを起動の設定 (`--procedures` か `ML_PROVIDE_PROCEDURES`) に足してから起動し直してください」で止める

### 自作の部品と起動の設定

- 研究の自作の部品 (ML-ModelControl の `register_unit` で登録する部品) も手順と同じく, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --units pkg.units,...` か環境変数 `ML_PROVIDE_UNITS` (`,` で区切る. 引数が環境変数より先) に書いたモジュールを, 起動のときに手順のモジュールの前 (手順のモジュールが部品を使えるように) で ML-Inference の `register_units` (ML-ModelControl の `register_units_from`) に渡す. モジュールは `UNITS` か `register_units(register)` で部品を宣言する (書き方は ML-ModelControl の docs/DESIGN.md の「自作の部品のモジュール」). 読めないモジュール, 部品を宣言していないモジュールは起動を止める
- `GET /api/info` の `unit_modules` に, 読んだモジュールと登録した部品の名前 (`[{"name": "pkg.units", "units": ["my.Block"]}]`) を返す
- 一式のモデルの定義に書かれた部品の名前からは何も読み込まない. 登録されていない部品を使う一式は, ML-Inference の `UnregisteredUnitError` (部品の名前とノード) に「自作の部品なら, 部品を宣言したモジュールを起動の設定 (`--units` か `ML_PROVIDE_UNITS`) に足してから起動し直してください」を添えて, 一式の画面 (一覧と一式の欄の誤り), 場所での登録, 画面で作る一式, 推論の誤りに出す

## 9. 問題の設定とのつなぎ

問題の設定 (ML-Quest の `problem.yaml`) は, 7 の「損得」で意思決定の型と損得と制約と根拠を, 5 の「機械学習の受け持ち」で当たりのクラス, 系列を分ける列, 何期先までを決める. 骨組みから学習した一式は, 学習した時点の値を一式の既定値に持つ. ただし, 画面で作った一式は既定値を持たず, 学習の後に問題の設定の損得を見直すと一式の既定値は古くなる. そこで, 一式に問題の設定をつなぎ, 推論の既定を問題の設定の今の値にする.

- つなぐと, 一式の画面の推論の意思決定と結論の決め方の既定を, ML-Quest の受け渡し (`handoff` の `inference`) から読む. 結論の決め方は, 一式の既定値に問題の設定の値 (まとめる列) を重ねる. 推論のたびに読み直す (問題の設定を ML-Pathfinder で直せば, 次の推論から使う)
- 今のやり方: 量を決める型で, 問題の設定に今のやり方 (`action.current`) があれば, 意思決定の `current` を ML-Inference の決まりにする. k 期前と平均は, 時刻の列 (問題の設定の予測の時刻の列, 分割の時刻の列, 一式の過去の値の手順の時刻の列の順. 一式の手順の列なら, 系列を分ける列も ML-Inference が一式の手順から補う), 問題の設定の系列を分ける列, データを入れたときに求めた 1 期の間隔 (`data.interval_seconds`. 無ければ ML-Inference が推論するデータの時刻の差から求める) を足す. 列は列の決まり (置いた後の量. 今ある量があっても問題の設定と同じ意味). 時刻の列がどこにも無ければ入れず, 一式との食い違いの欄で知らせる. 決まりの列 (時刻, 系列, 今のやり方の列) が一式の学習のデータに無ければ, 食い違いの欄で知らせる (ML-Inference の `check_baseline`). たどり直しは, 推論するデータに今のやり方の列が無くても, 決まりから行ごとの値を作って比べる (利用者が列を足さずに済むように). 選ぶと振り分けは受け渡しの列の名前のまま
- 意思決定の欄の「今のやり方の列」は, 決まりがあれば, 空のまま決まりで比べると書き, 「使わない」で外せる. 列を書けば, その列で比べる
- 損得の根拠 (`action.basis`) と, 意思決定の文 (ML-Quest の `describe` と同じ) を出す. 根拠の無い損得はそう知らせる
- 一式との食い違いを出す: 目的の列が違う, 意思決定の型が一式のタスクに合わない (ML-Inference の `check_decision`), 結論の決め方が合わない (`check_rules`). 食い違いがあっても既定にはするが, 推論の前に気付けるようにする
- つなぐときは, 渡せる問題の設定か (`handoff` が通るか) を確かめる. 機械学習を使わない問題の設定や, 直すところのある問題の設定は理由付きで断る
- つないだ後に問題の設定のファイルが別の問題の設定に置き換わった (作った時刻が違う) か, 読めなくなった場合は, 理由を出し, 既定は一式の既定値に戻す. つなぎは外さない (直せば戻る)
- 候補: 骨組みのプロジェクトは `problem.yaml` を持ち, 学習の実験の中に一式を作る. つないでいない一式は, 一式の場所から 4 つ上のディレクトリまでたどり, 最初に見つけた推論に渡せる問題の設定のファイル (`problem.yaml`) を候補に出す (つなぐかは利用者が決める)
- 元の問題の設定: 見つけたファイルは, 骨組みが写した学習の時点の写し. 写しが元の場所 (ML-Quest の `problem_origin`. ML-Pathfinder の置き場の `problem.yaml`) を持ち, 元があって推論に渡せるなら, 元を候補にする (写しをつなぐと, ML-Pathfinder で直した損得が届かないため). 元の場所を持たない写しと, 元が無いか推論に渡せない写しは, 写しを候補にし, 直した損得が届かないことを文で添える. つないだ問題の設定は推論のたびに読み直すので, 元をつなげば ML-Pathfinder で直した損得が次の推論の既定に入る
- 問題の設定への書き戻しはしない (推論の画面で変えた損得は, その結果の決め方として残す. 問題の設定を直すのは ML-Pathfinder)
- 問題の設定の版: ML-Quest の版 2 (受け持ちの並び `ml.parts`. 今は 1 つ) を読む. 版 1 のファイルは ML-Quest が読んだ後に版 2 に移す (ファイルは変えない) ので, 版 1 と版 2 で同じ値になる. 知っている版より新しいファイルは, 読めない理由を出して止まる (読める項目だけで読み違えないため)
- 受け持ちが列の予測 (予測するで, 正解の種類が表の列) の問題の設定だけ, 意思決定と結論の決め方を既定にする. 他の受け持ち (作る, 並べる, まとめる, 効果を見積もる, 予測するで正解が点群や画像の領域など) は受け渡しの `inference` が空 (意思決定は無い) なので, つなげるが「この問題の設定の受け持ち (作る, 正解の種類は画像) の推論の結論はまだ扱いません. 意思決定と結論の決め方は一式の既定値のままです」(括弧の中は受け持ちごと)と出し, 推論の既定は一式の既定値のままにする. 候補には出さない

## 10. 実験の一覧

学習した実験の一式を, 場所を打たずに登録するための一覧. 骨組みのプロジェクトの学習のスクリプトは, 実験のディレクトリ (`outputs/<名前>/<日付>/<時刻>`) の中に一式 (`inference`) を作る.

- プロジェクトは, ML-Pathfinder の問題の設定の置き場 (環境変数 `ML_PATHFINDER_HOME`. 無ければ ML-Pathfinder と同じ既定の場所. その中の `problems/<id>/problem.yaml`) の問題の設定が記録したプロジェクト (`project.path`. ML-Quest の `record_project` が書く) から得る. 読めない問題の設定, 記録の無い問題の設定, 無いディレクトリは飛ばし, 同じプロジェクトは 1 つにまとめる
- 実験は, プロジェクトの `outputs` の下を 5 つ下のディレクトリまで探し (リンクはたどらない), `inference.yaml` を持つ `inference` を一式とする. 一式の更新の時刻の新しい順に並べ, 500 件で打ち切る (打ち切ったことを画面に出す)
- 行は, 問題の設定の名前, 出力先からの実験の場所 (名前/日付/時刻), 一式の場所, 一式を作った時刻. 登録済みの一式 (登録の場所か, 外れ方を書き戻したときに写した元の場所が同じもの) は「登録済み」として一式の画面へつなぐ
- 一覧から登録すると, 名前を「問題の設定の名前 (実験の場所)」にして場所で登録し (同じ `POST /api/bundles`), 一式の画面に移る. 一式は写さない. 場所で選ぶ登録も残す (置き場に記録の無いプロジェクトと, 骨組みでない一式のため)

## 11. 課題の型への広げ方

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる. 推論と結論の中身は ML-Inference に足し, この画面はそれを使う. 列の出力でない一式は 1 件ごとの配列を見せる (上の「受け持ちと出力の形」) が, 結論と意思決定は列の出力 (確信, クラスの確率) と 3 つの意思決定を前提にしている.
