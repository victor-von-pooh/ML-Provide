# 設計

ML-Provide の設計の方針をまとめる.

## 目的

学習したモデルで新しいデータを推論し, 予測から結論を出す手元の Web アプリ. 推論と結論の中身は ML-Inference が持ち, このアプリは画面と, 画面のための API と置き場を持つ.

- 推論の一式 (ML-Inference の約束) を登録するか, 学習の結果 (モデルの定義, データセット, 実験) から画面で作る
- 新しいデータのファイルか, 画面に書いた文を推論し, 予測の表と結論 (判断の内訳, まとめの文) を見る
- 結論の決め方 (保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列) を画面で変え, 推論し直さずに結論だけを出し直す
- 結果を保存し, 後から開き, 予測の表を CSV で持ち出す

## 全体の中での役割

「機械学習を全て GUI 上で行う」アプリ (問題の設定, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「推論」の段階で画面を受け持つ. ライブラリは ML-Inference.

- ML-Inference は submodule. 推論, 結論, 一式の形など, 画面の外でも使う仕組みは ML-Inference に足す. 画面と API に固有のもの (置き場, 結果の一覧, ページ分け) はこのリポジトリに置く
- 構成と道具は ML-Dashboard, ML-CreateArchitecture, ML-Fathom にそろえる (将来の統合のため). バックエンドは FastAPI, 画面は React と Vite, 起動ごとのトークンと Origin の確認も同じ
- 実験のディレクトリには書かない (ML-Found の約束). 画面で作る一式は, このアプリの置き場に作る
- 結論の決め方は, 本来は問題の設定の段階が決める. 今は一式の既定値と, 画面で選んだ値を使う

## 置き場

既定は `~/.ml-provide` (環境変数 `ML_PROVIDE_HOME` で変えられる).

```
~/.ml-provide/
├── bundles.json        # 登録した一式 (id, 名前, 場所, 置き場で作ったか, 登録した時刻)
├── bundles/<id>/       # 画面で作った一式 (ML-Inference の形)
├── samples/sample<n>/  # 見本 (学習用のデータ, データセット, 重み, 一式, 推論を試す新しいデータ)
└── results/<id>/       # 推論の結果 (ML-Inference の write_result の形)
    ├── predictions.csv # 予測と判断の表 (結論を出し直すときは, 判断の列を除いて読み直す)
    └── result.yaml     # 一式, 入力, 時刻, 決め方, まとめ, 文
```

- 一式の登録は場所だけを覚える (学習のスクリプトが実験の中に作った一式を, 写さずに使う). 置き場で作った一式は, 登録を消すと一式も消す
- 結果は一式ごとに新しい順に並べる. 一式を消しても結果は残す (一式の名前を結果にも書く)

## API

| メソッドとパス | 内容 |
| --- | --- |
| `GET /api/auth` | 起動したときのトークンを Cookie に保存して画面に移る |
| `GET /api/info` | ML-Inference の版, 結論の決め方の項目 |
| `GET /api/browse` | ディレクトリの中身 (ファイルとディレクトリを選ぶため) |
| `GET /api/bundles` | 登録した一式の一覧 (読めない一式は理由付き) |
| `POST /api/samples` | 見本の一式 (表の分類, 表の回帰, 時系列の先の予測, 文の分類) を, 見本のデータでその場で学習して作り登録する. 意思決定の既定値と, たどり直しを試す目的の列のある過去のデータも付ける |
| `POST /api/bundles` | 場所を指定して登録 (`inference.yaml` を持つディレクトリ) |
| `POST /api/bundles/create` | モデルの定義, データセット, 実験 (か重み) から置き場に作って登録 |
| `GET /api/bundles/{id}` | 一式の説明 (ML-Inference の `describe_bundle`) |
| `DELETE /api/bundles/{id}` | 登録を消す (置き場で作った一式は一式も消す) |
| `POST /api/bundles/{id}/predict` | ファイルの場所か文の並びを推論し, 結論を出して結果を保存. `forecast` で何段も先の予測 (目的の列の過去の値を使う回帰と予測の一式. 結果は先の行だけ). `decision` で意思決定もする (省略は一式の既定値, 空の辞書で意思決定しない) |
| `GET /api/results` | 結果の一覧 (`bundle` で絞れる) |
| `GET /api/results/{id}` | 結果のまとめ, 文, 決め方, 列 |
| `GET /api/results/{id}/rows` | 予測の表の一部 (`offset`, `limit`, `status`, `decision` で絞る) |
| `POST /api/results/{id}/conclude` | 決め方を変えて結論だけを出し直す (結果を書き換える) |
| `POST /api/results/{id}/explain` | 入力の列ごとの効き (ML-Inference の `explain`) を求めて結果に残す (表と時系列のファイルの結果だけ) |
| `POST /api/results/{id}/decide` | 意思決定の決め方を変えて決め直す (推論はし直さない. 空で外す) |
| `POST /api/results/{id}/backtest` | 結果の入力 (目的の列を持つファイル) で, 意思決定の方針と素朴なやり方の実際の得と損を比べる |
| `GET /api/results/{id}/download` | 予測と判断の CSV |
| `DELETE /api/results/{id}` | 結果を消す |

- 推論は手元のファイルだけを読む. 起動ごとのトークンが無い呼び出し, 別のサイトからの書き込み, 他のホスト名での接続は拒否する (ML-Fathom と同じ)
- 推論は同時に 1 つだけ (大きなモデルでメモリを使い切らないように). 読み込んだ一式は少しだけ覚えて使い回す (`inference.yaml` と重みのファイルの更新時刻と大きさが変わったら読み直す. 写さない重みは学習し直すと変わるため)
- 結論の出し直しと結果の削除は 1 つずつ行い, 書き換えは隣に書いてから置き換える (読んでいる途中の表が壊れないように). 推論の直後も, 書いた表を読み直して結論を出す (出し直したときと同じ型の値でまとめ, まとめの名前が変わらないように)
- 渡したデータに `index` の列がある場合, 表の行の位置の列と重ならないように「`index (入力)`」にする

## 画面

| 画面 | 内容 |
| --- | --- |
| 一式 | 登録した一式の一覧 (名前, データの種類, タスク, クラス, 実験の状態とベストの値). 場所で登録するか, 学習の結果から作る. 試すための見本の一式を入れる (見本は学習の基盤を使わずに, 小さなモデルを全ての行で 300 回更新して作る. 実験の記録は無い) |
| 一式の詳細 | 一式の説明 (データの種類, タスク, 目的の列, クラス, 学習に使う列, 読み込み, 前処理の手順, モデルの入力, 実験, 検証用の分割を一式で推論した評価と実験の記録が合うか, 注意). 推論するデータ (ファイルを選ぶか, 文の一式なら文を書く) と結論の決め方を選んで推論する. 過去の結果の一覧 |
| 結果 | 意思決定 (行動の文, 前提, 決め直し, 過去のデータでのたどり直しと差の幅), 結論の文, 判断の内訳 (帯グラフ), まとめる列ごとの表, 列の効き (押すと求める), 予測の表 (ページ分け, 予測しなかった行と判断で絞る), 決め方を変えて出し直す, CSV のダウンロード |

## 段階

| 段階 | 内容 |
| --- | --- |
| 1 | 一式の登録と作成, 推論, 結論と出し直し, 結果の保存と一覧 |
| 2 | 画像と点群の結果の見本の表示, 結果どうしの比べ |
| 3 | 問題の設定の段階から結論の決め方を受け取る |
