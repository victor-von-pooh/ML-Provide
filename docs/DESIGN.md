ML-Provide の今の設計と決まりをまとめる. まだやっていないことは [TODO.md](../TODO.md) に置く.

## 1. 役割と位置づけ

学習したモデルで新しいデータを推論し, 予測から結論を出す手元の Web アプリ. 推論と結論の中身は ML-Inference が持ち, このアプリは画面と, 画面のための API と置き場を持つ.

- 推論の一式 (ML-Inference の約束) を登録するか, 学習の結果 (モデルの定義, データセット, 実験) から画面で作る
- 新しいデータのファイルか, 画面に書いた文を推論し, 予測の表と結論 (判断の内訳, まとめの文) を見る
- 結論の決め方 (保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列) を画面で変え, 推論し直さずに結論だけを出し直す
- 結果を保存し, 後から開き, 予測の表を CSV で持ち出す
- 強化学習の方策の一式 (ML-Inference が読む `policy.json` と `policy.pt`) を登録し, 画面に入れた観測か観測のファイルから守りを当てた行動と守りの結果を見る (下の「方策の一式」)
- 列の予測 (クラス, 値, 分布) でない一式 (領域, 点群, ベクトル, 画像, 文を出す一式. ML-Inference の一式の版 3 と 4) も推論し, 1 件ごとの配列を見る (下の「受け持ちと出力の形」)
- データセットを持たない雑音だけの一式 (拡散やフローのモデル. 一式の版 5) を作り, 件数と種から生成して 1 件ごとの配列を見る (下の「雑音だけの一式」). 表を作る雑音だけの一式 (一式の版 7) は登録して, 作った表を見て CSV で持ち出す (下の「表の出力の雑音だけの一式」)
- 学習しない既製のモデル (ライブラリの学習済みの重み. 一式の版 6) の一式を作り, 画像から種類の名前と確信度を出す (下の「既製のモデルの一式」)
- 学習しない既製のモデルの埋め込みで似た写真を探す検索の一式 (一式の版 15) を登録し, 問いの写真ごとに索引の写真から見た目の近い上位 K 件 (縮小画像, 種類, 余弦の近さ) と 1 件の問いの待ち時間を見て, 待ち時間の上限を超えた問いの数と骨組みの評価 (Recall@K, NDCG@K) を見る (下の「検索の一式」)
- 利用者と品物の 2 塔のモデルの並べるの一式 (一式の版 8) を登録し, 利用者ごとの上位 K 件の品物と点数を見て, 正解の反応の表から Recall@K と NDCG を数える (下の「並べるの一式」)
- 表の行の埋め込みと群の中心の群分けの一式 (一式の版 9. 群の中心から遠い行の上限を持てば版 16) を登録し, 新しい行を最も近い群に割り当て, 群ごとの件数と列の特徴 (群の要約), 群の中心に近い行 (群の代表の行), 学習のときより群の中心から遠い行と, 学習の群の安定性を見る (下の「群分けの一式」)
- 正常の行が多い表の行ごとに異常の度合いを出す一式 (一式の版 11) を登録し, 度合いの分布と上位の行を見て, 度合いの高い順に人が確かめる件数の上限までの行を人の確かめに回し, 1 件ずつ付けた異常か正常かの判断を結果の隣の記録に残す (下の「異常の度合いの一式」)
- 過去に処置 (クーポンを配るなど) を無作為に配った記録から学んだ行ごとの効果 (処置したときの結果 − しないときの結果) の一式 (一式の版 12) を登録し, 効果の分布と上位の行を見て, 効果の高い順に配る数の上限までの配る行の一覧と, 実験の Qini の係数, 上位 K 割の効果の差, Qini の曲線を見る (下の「効果の一式」)
- 試しに値段を変えた売れ行きの記録から学んだ, 値段を入力に入れて売れた数を予測する一式 (一式の版 13) を登録し, 値段の候補 (今の値段に対する変える割合) と変える幅の上限を決めて, 行ごとに上限の中で見込みの利益が最も大きい値段を選び, 選んだ値段と今の値段の見込みの利益の比べ, 弾力性の分布, 実験の評価を見る (下の「値段の一式」)
- 商品ごとの日ごとの売れた数の記録から学んだ, 先の期間の需要の分位点を予測する一式 (一式の版 14) を登録し, 品切れの損, 売れ残りの損, 発注の数の上限を決めて, 商品ごとに損の比から決まる水準 τ の分位点から在庫を引いた数を上限の中で発注し, 見込みの損と前の期間と同じ数の発注の損の比べ, 上限に当たった商品, 需要の分位点の幅, 実験の評価を見る (下の「需要の一式」)
- ML-EDA の版 1 の音声のデータセットで学習した一式も推論する (読み込み `audio_folder` と中身の手順 (周波数, チャンネル, 長さをそろえる) は, 列の一式と同じく「読み込み」と「前処理」の行に出す). 一式の種類は「音声」と出し, 推論するデータの欄は音声のファイルか, 音声を並べたディレクトリを案内する (列のファイルを案内しても音声の一式では読めないため)
- ML-EDA のファイルの組のデータセット (版 2 と, 中身の手順をかけた版 3. 画像と領域, 撮影と点群) からも一式を作り, 新しい画像や撮影の領域と, 元の座標の点群を見る (下の「ファイルの組のデータセットの一式」)

「機械学習を全て GUI 上で行う」アプリ (問題, データの分析, モデルの作成・選定, モデルの学習・評価, 推論の段階に分けて作ることを目指している) のうち, 「推論」の段階で画面を受け持つ. ライブラリは ML-Inference.

- ML-Inference は submodule. 推論, 結論, 一式の形など, 画面の外でも使う仕組みは ML-Inference に足す. 画面と API に固有のもの (置き場, 結果の一覧, ページ分け) はこのリポジトリに置く
- 構成と道具は ML-Dashboard, ML-CreateArchitecture, ML-Fathom にそろえる (将来の統合のため). バックエンドは FastAPI, 画面は React と Vite, 起動ごとのトークンと Origin の確認も同じ
- 意思決定 (損得と制約) と結論の決め方は, 本来は問題の設定の段階 (ML-Quest, ML-Pathfinder) が決める. 一式に問題をつなぐと, 推論の既定値を問題の今の値にする (下の「問題とのつなぎ」). つないでいない一式は, 一式の既定値と画面で選んだ値を使う

### 役割

構想 (全体で 1 つのアプリ) の中で「推論」の段階を受け持つ (最後の段階).

- 前の段階から受け取るもの: 学習の結果 (モデルの定義, データセットの説明, 実験のディレクトリ) か, 推論の一式 (ML-Inference の約束). 問題 (ML-Pathfinder の置き場の `problem.yaml`. ML-Quest の受け渡しから損得と結論の決め方)
- 後の段階へ渡すもの: 無し (最後の段階). 結果は置き場に保存し, 予測の表を CSV で持ち出す

### 要件

| 要件 | 今できていること | 足りないこと |
| --- | --- | --- |
| 学習の結果から一式を作る, か一式を登録する | `GET /api/experiments` (問題の設定の置き場に記録した学習のプロジェクトの推論の一式を持つ実験. 殻で選んだ問題の実験に絞る. 「3. 画面」の「殻で選んだ問題」), 一式の登録と画面の作成 | 無し |

| 問題の損得と結論の決め方を既定にする | 一式に問題をつなぐ (「問題とのつなぎ」). 候補の探し方 (一式の上に無ければ殻で選んだ問題) と食い違いの表示 | 無し |
| 置き場, トークン, 待ち受けを外から決められる | `create_app(data_dir, token, allowed_hosts, procedures, units)` と環境変数 `ML_PROVIDE_HOME`, `ML_PROVIDE_TOKEN`. ポートは `--port` (起動のコマンドだけ). 確かめを持たない API だけのアプリ (`create_api`) を殻の頭の下に mount できる (「4. API」). 画面の根の部品 (`StageApp`) に経路の頭, API の頭, 殻で選んだ問題を渡して載せられる (「3. 画面」の「根の部品」) | 下の「統合に向けて足りないこと」 |

### 統合に向けて足りないこと

殻 (ML-Studio) は 5 つのアプリを submodule で持ち, 1 つのコマンドで 1 つのポートを開く. 起動ごとのトークンと Origin の確かめは殻が 1 つだけ持つ. 各アプリは自分のバックエンドを `/api/<段階>`, 画面を `/<段階>` の下に載せられる形にし, 単独でも今まで通り動く.

- 共通の部品: 見出し, 段階の並び, 誤りの出し方は各アプリの画面が別々に持つ. 殻の段階の並びと共通の部品にそろえる (画面の言葉は殻の表にそろえてある. 下の「用語」)

## 2. 使うライブラリと約束

ML-Inference と ML-Quest は submodule. 形の決まりを 2 か所に持たないため, 一式, 結果, 問題のファイルは自分で解釈せず, それぞれのライブラリの関数で読み書きする.

| ファイル | 持ち主 | このアプリの扱い | 読む版 |
| --- | --- | --- | --- |
| 推論の一式 (`inference.yaml` と, モデルの定義, 重み, データセットの説明とレシピ) | ML-Inference | 登録した場所から読む (`load_bundle`, `describe_bundle`). 画面で作る一式は `make_bundle` (既製のモデルの一式は `make_ready_bundle`) で置き場に書く. 並べるの一式は `make_rank_bundle`, 群分けの一式は `make_group_bundle`, 異常の度合いの一式は `make_anomaly_bundle`, 効果の一式は `make_uplift_bundle`, 値段の一式は `make_price_bundle`, 需要の一式は `make_demand_bundle` で作ったものを登録する. 測り直した外れ方は一式に書き戻す (`remeasure`. 下の API の表) | 1 から 17 (版 16 と 17 は群の中心から遠い行の上限を持つ群分けの一式. 下の「群分けの一式」. 版 15 は検索の一式. 下の「検索の一式」. 版 14 は需要の一式. 下の「需要の一式」. 版 13 は値段の一式. 下の「値段の一式」. 版 12 は効果の一式. 下の「効果の一式」. 版 11 は異常の度合いの一式. 下の「異常の度合いの一式」. 版 10 は既製の埋め込みの群分けの一式. 下の「既製の埋め込みの群分けの一式」). 既製のモデルの一式の埋め込み (出力の形 `vector`) は列の出力でない一式として扱う |

- 実験のディレクトリには書かない (ML-Found の約束). 画面で作る一式は, このアプリの置き場に作る
- ML-Quest は submodule. 問題のファイルは ML-Quest を通して読む (YAML を自分で解釈しない)
- ML-EDA と ML-ModelControl は git の依存 (`backend/pyproject.toml` の `tool.uv.sources`. 版は `backend/uv.lock` が決める). 2 つ以上のアプリが使うライブラリは, ML-Quest の submodule と ML-EDA の lock の版を殻 (ML-Studio) の設計の「共通のライブラリの版」の表の版にそろえる (殻の 1 つの環境には 1 つの版しか入らず, 表の版でこのアプリのテストを通しておくため. 上げるときは `uv lock --upgrade-package ml-eda` で表の版になったことを確かめる). ML-ModelControl の lock も, 殻がその表に足す版にそろえる (上げるときは `uv lock --upgrade-package ml-modelcontrol`). ML-Inference は ML-ModelControl を版を決めない git の依存で求めるので, このアプリの環境の版は lock が決める. ML-Inference はまだ表に無いので submodule の版のまま
- 予測の表 (`predictions.csv`) は ML-Inference の `read_result` で 1 回だけ読む (読み方の決まりは ML-Inference の「書き出し」). このアプリは次の列の型を `read_result` の引数で渡す (読んだ後に列を読み直すと, 行の多い結果で表を 2 回読むため). 1. `override_types` (`column_types` より強い). 画面の都合: `status`, `reason`, `decision` は文字 (理由と判断の空を空の文字で出すため), 表の出力の `table_columns` の種類の列は文字 (欠けた行の有無に依らず種類の値を文字で出すため), 群分けの `grouping.texts` は文字 (推論したときの値のまま, 割り当てた行の表と代表の行に出すため). 引く都合: 並べるの `user` と `item` は文字 (番号の表と同じく文字にして引くため). 結論の都合: 分類の `prediction` は文字 (数字のクラスも, 決め方のクラスの名前と合わせるため. 文の出力を除く) 2. `fallback_types` (`column_types` に無い列だけ). 版 1 と 2 の補い: 表の出力の `table_columns` の整数の列, 並べるの `rank`, 群分けの `group` は欠損を持てる整数 (版 1 と 2 の結果は列の型を持たないので, このアプリが結果に残した型で補う). 型は `result.yaml` の中身から決めるので, 推論の直後に結論を出し直すときも, 書いた `result.yaml` を読んで渡す (`column_types` は `write_result` が書くときに決めるため)

## 3. 画面

| 画面 | 内容 |

### 根の部品

画面のパッケージ (`frontend`) は, 段階の画面の根の部品 `StageApp` (`src/StageApp.tsx`) と, 段階に固有の CSS (`src/stage.css`) を公開する (`package.json` の `exports` の `.` と `./stage.css`). 殻は自分の画面のビルドにこの 2 つを取り込む (ML-Studio の設計の「画面: 根の部品」). 単独の起動では `main.tsx` が既定の値で `StageApp` を描く.

| props | 型 | 意味 | 単独の値 |
| --- | --- | --- | --- |
| `basename` | `string` | 画面の経路の頭 (例 `/infer`). 部品の中の経路と移動先はこの下に置く | `""` |
| `apiBase` | `string` | API の頭 (例 `/api/infer`). API の呼び出しは全てこの下に送る | `/api` |
| `project` | `string \| null` | 殻で選んだ問題の識別子 (ML-Pathfinder の問題の設定の置き場の `<識別子>` ディレクトリの名前). null なら選んでいない | `null` |
| `onProjectChange` | `(project: string \| null) => void` | 一式に置き場の別の問題をつないだときに, その識別子で呼ぶ (下の「殻で選んだ問題」) | 何もしない |
| `onProjectsChange` | `() => void` | 問題の一覧が変わったときに呼ぶ. このアプリは問題を作らず消さないので呼ばない | 何もしない |
| `embedded` | `boolean` | 殻の下か. true なら左の欄のアプリの名前と明暗の切り替えを出さない (左の欄の「推論の一式」, 「結果」, 「方策の一式」は出す) | `false` |

- 部品は自分のルーター (`BrowserRouter` に `basename`) と TanStack Query の client を持つ (殻に中の作りを出さないため). API の頭は部品の中で 1 度決めて context で渡し, 画面の部品は `useApi()` で呼び出しの一式を取る (`createApi(base)`. 呼び出しごとに頭を渡し忘れないため)
- 画面のソースでは根から始まる絶対パスを使わない. 移動は `Link` と `navigate` で `basename` の下にし, ダウンロードと画像の場所も API の頭の下に作る (殻の下では根が殻の画面を指すため). `index.html` の `/favicon.svg` は単独の起動のためのもの
- 画面の高さは親の高さ (`h-full`) に合わせる. 単独では `html`, `body`, `#root` が画面の高さで, 殻の下では殻の上の帯の下の高さになる
- 明暗は `html` 要素のクラス `dark` と `localStorage` の `theme` で持つ. 単独では切り替えで両方を書き, `index.html` が描画の前に読む. `embedded` では書かずに読むだけにし, `html` のクラスの変化を見て読み直す. グラフの色は CSS の変数 (`--series-1` など) から読むので, 殻の切り替えでそのまま替わる
- `stage.css` は段階に固有の CSS (Tailwind の読み込みと色のトークン以外. 数の桁をそろえる `.tabular`). 単独では `index.css` が Tailwind と色のトークンと一緒に読む
- 部品の範囲の要素に `data-stage-root` を付ける (箱を作らない `display: contents`). このアプリは `window` と `document` でキーを聞かず, キーの操作は全て欄やボタンの要素で扱うので, 殻の上の帯で押したキーで中身を変えない. 対話の枠は `dialog` の要素を部品の中に置き, `createPortal` で範囲の外に出さない (出すと, その中のキーを扱えなくなるため)

### 殻で選んだ問題

殻の `project` は問題の識別子で, このアプリでは ML-Pathfinder の問題の設定の置き場の `<識別子>/problem.yaml` に対応させる (識別子は置き場のディレクトリの名前のため). 一式は問題を一式ごとにつなぐので, 殻の選びは一式の選び直しをせず, 実験の一覧と問題の候補の既定に使う. 1 つの問題から一式がいくつもできるので, 殻で問題を選んでも一式の画面は自動では開かない. 今は実験の一覧だけを絞り, 登録した一式の一覧は絞らない. 学習の結果から作るときも, 殻で選んだ問題を既定にしない (問題は作った一式につなぐ候補の既定にするだけ).

- 実験の一覧 (推論の一式と方策の一式. 下の「実験の一覧」): `project` があれば, その識別子の問題が記録した学習のプロジェクトの実験 (行の `problem_ids` に識別子を含むもの) に絞る. 絞りは API に識別子 (`project`) を渡し, 上限 (500 件) で打ち切る前に効かせる (後ろの問題の実験を打ち切りで落とさないため). 「全ての問題の実験を出す」で絞りを外せる (他の問題の実験も登録できるように). 外したのはそのときの問題だけで, 殻で選び直すとまた絞る
- 問題の候補: つないでいない一式で, 一式の場所から上にたどって候補が見つからなければ, `project` の問題 (置き場の `<識別子>/problem.yaml`. 推論に渡せるものだけ) を候補に出し, 殻で選んだ問題であることを添える (`GET /api/bundles/{id}/problem?project=` の `hint_project`). 上で見つけた候補は殻の選びより先にする (一式を作った学習の問題の方が一式に合うため). 識別子が区切りを含むか `.` で始まる場合は候補にしない (置き場の外を指さないため)
- 一式に置き場の問題をつないだら (候補か場所の欄から), その識別子で `onProjectChange` を呼ぶ. 識別子が `project` と同じなら呼ばない (殻と部品の間で知らせが行き来し続けないため). 置き場の外の問題 (学習の時点の写しなど) をつないだときは, 同じ名前のディレクトリでも呼ばない (殻の問題の一覧に無い識別子を渡さないため). 置き場にあるかは API が, つないだ場所 (実際のパス) と置き場の各 `<識別子>/problem.yaml` の実際のパスを比べて決め, 識別子を `problem_id` で返す (`<識別子>` がリンクでも, リンクの先のファイルをつなげば識別子を返す). 一式を開いただけ, 実験の一覧から登録しただけでは呼ばない (殻の選びを, 利用者が問題を選んだときだけ替えるため)
- 殻が `project` を替えても画面は移さない. 一式の画面の問題の候補と, 開いている実験の一覧の絞りは新しい値で読み直す. 読み直す間も同じ一式の前の値を出し続ける (推論の欄を外して打ちかけの値を消さないため)

### 書きかけの下書き

置き場にまだ作っていない欄の書きかけは, ブラウザ (`localStorage` の `ml-provide:drafts`) に欄の種類ごとの下書きとして残す (殻の要求 R10). 残すのは打ち直すのに手間のかかる欄だけで, 今は次の 1 つ.

| 残す欄 | 中身 | 残す理由 |
| --- | --- | --- |
| 一式の画面の「学習の結果から作る」 | 名前, モデルの定義とデータセットと実験の場所, 入力と正解の項目, 繰り返しの手順の並びと手順の設定, 受け持ちと出力の形と形ごとの欄, モデルの入力ごとの出どころの行, 点を選ぶ数と種などの全ての欄 | 欄の数が多く, 手順と入力の行の並びを組み直す手間が大きいため |

残さない欄と理由は次のとおり.

- 場所で登録, 既製のモデルから作る (出どころとモデルを選び, 名前と場所を書く), 問題をつなぐ場所: 選ぶだけか場所 1 つで, 打ち直せるため
- 推論するデータ (ファイル, 推論する文, 並べる利用者, 作る件数と種), 結論の決め方, 意思決定の欄 (損得, 値の帯の並び), 方策の観測: 推論や決め直しの引数で, 前の値のまま推論を押す誤りを避けるため. 推論する文と並べる利用者と観測は 1 行ずつの並びだが, 推論するたびに貼り替える値として扱う

- 書きかけは少し (1 秒) 待ってから書く. 保存場所にある中身 (戻した下書きか, 最後に書いた中身) と同じ中身に戻したら, 待っている書き込みを捨てる (前の中身を書いて, 最後に見ていた値と違う下書きを残さないため). 部品が外されるとき (殻の中で段階を移る, 同じ段階を押し直す, 対話を閉じる) と, 殻で選んだ問題 (`project`) が替わるときは待たずに書く (殻の中の移動ではページを閉じないので `beforeunload` の確かめが出ず, 部品は移動を止められないため)
- 次に対話を開いたとき, 14 日より新しい下書きがあれば欄に戻し, 「作っていない書きかけを欄に戻しました」と「書きかけを捨てる」を出す (捨てると空の欄にする). 形の合わない欄は空の値で戻す. 戻しただけでは書き直さない (下書きの時刻と 14 日の期限を, 最後に書いた時刻から数えるため)
- 一式を作り終えたとき, 書きかけを捨てたとき, 全ての欄を空に戻したときに下書きを消す. 書けない環境では古い下書きを残さないように消す
- 下書きは画面 (タブ) で分けず, 最後に書いたものを戻す (1 つの手元のアプリで, 同時に 2 つの画面で一式を作ることは少ないため)

## 4. API

単独の起動では全て `/api` の下. 起動ごとのトークン (Cookie か `x-provide-token` ヘッダー) が要る. 殻の下では下の表の `/api` が殻の頭 (`/api/infer`) に替わる.

### アプリの組み立て

API と, 確かめと画面の配信を, 2 つの FastAPI のアプリに分ける (殻の下では確かめを殻の 1 つだけにするため).

- `create_api(data_dir=None, *, problems_dir=None, procedures=None, units=None)`: API だけのアプリ. 殻はこれを `/api/infer` の頭の下に mount する
    - router (`api`, `problems`, `experiments`, `datasets`, `policies`, `policy_results`, `reviews`, `treated`, `prices`, `demands`, `searches`) は全て頭なし (`APIRouter()`) で, このアプリに加える. mount の下の経路の照合は mount の頭を除いた経路で行われるため
    - トークン, Origin, ホスト名の確かめ, `/api/auth`, 画面の配信を持たない (載せる側が持つ). 仕様の画面 (`/docs`, `/redoc`, `/openapi.json`) も閉じる
    - 置き場は `app.state.store` (一式と結果) と `app.state.problems_dir` (ML-Pathfinder の問題の設定の置き場), 読んだ自作の部品と手順のモジュールは `app.state.unit_modules` と `app.state.procedure_modules` に持ち, ルートは `request.app.state` から取る. Starlette では mount した sub-app の中の `request.app` は sub-app を指すので, 殻の下でもルートはそのまま動く
    - `data_dir` はこのアプリの置き場 (無ければ既定. 下の「6. 置き場」). `problems_dir` は問題の設定の置き場. 渡さなければ作ったときの `ML_PATHFINDER_HOME` (無ければ既定) の下の `problems`. 殻は ML-Pathfinder と同じ置き場を渡す. `procedures` と `units` は起動の設定の自作の手順と部品のモジュール (無ければ `ML_PROVIDE_PROCEDURES` と `ML_PROVIDE_UNITS`. 下の「8. 受け持ちと出力の形 (一式の版 3 と 4)」)
    - lifespan と startup, shutdown の処理を使わず, 自作の部品と手順のモジュールの読み込みも呼んだときに済ませる (mount した sub-app の lifespan は動かないため). 読めないモジュールがあれば `ValueError` で止める (起動のコマンドは理由の 1 行を出して終わる. 殻も同じ型を受けて理由を出す)
    - 部品と手順の登録簿はプロセスで 1 つで, 同じプロセスの他のアプリ (ML-CreateArchitecture が入れる自作の部品など) と共有する. 読み込み済みのモジュールは前の結果を使うので, `create_api` を何度呼んでも, 他のアプリが先に同じモジュールを読み込んでいても重ねて登録しない (下の「8. 受け持ちと出力の形 (一式の版 3 と 4)」の「繰り返しの手順と起動の設定」と「自作の部品と起動の設定」)
    - 呼ぶたびに新しいアプリを返す (テストと殻で別の置き場を渡せるように)
- `create_app(data_dir=None, token=None, allowed_hosts=None, procedures=None, units=None)`: 単独で起動するアプリ. 確かめ (トークン, Origin, ホスト名), `/api/auth`, 画面の配信を持つ外側のアプリに, `create_api(data_dir, procedures=procedures, units=units)` を `/api` で mount する. 確かめは外側の middleware なので, mount した API にも効く. トークンを確かめないのは `GET /api/auth` だけ (他のメソッドの `/api/auth` も確かめる). Cookie の名前はトークンから作る (`ml_provide_token_<印>`. 同じ端末の別の起動と重ならないように). `/api/auth` は mount より先に登録し, 画面の配信 (他のパスは index.html) は最後に置く. `/api` ちょうどと `/api/` の下の無いパスは画面でなく 404 を返す. 仕様の画面 (`/docs`, `/redoc`, `/openapi.json`) は外側のアプリでも閉じる (トークン無しで API の形を見せないため)
    - `token` が `None` か空の場合は, 環境変数 `ML_PROVIDE_TOKEN` (無いか空ならランダム) を使う. 環境変数も無いか空の場合は開き方の URL (`/api/auth?token=...`) を表示する (空のトークンでは誰でも API を呼べるため)
    - 画面の配信は GET と HEAD を受け付ける. 画面の置き場にあるファイルはそのまま返し, それ以外の経路は `index.html` を返す (画面の中の移動先のため). NUL の字を含む経路や長すぎる名前のように, ファイルとして調べられない経路も `index.html` にする
- 仕様の書き出し (`ml-provide --openapi`) は `create_api` の仕様のパスに `/api` を付けて書き出す (外側のアプリの仕様には mount した API が入らないため). 自作の部品と手順のモジュールは読み込まない
- ポートはアプリが持たず, 起動の `ml-provide --port` (か殻) が決める

| `GET /api/results/{id}/orders` | 需要の結果の, 発注の数を決めた商品 (表の `order` が空でない行) を発注の数の大きい順に, `offset` と `limit` (1 から 500) で区切って. 行ごとに行の位置, 行の id, 商品の id, 学んだ水準の小さい順の分位点, 発注を決める日, 在庫の数, 前の期間の合計, 0.5 の点, 水準 τ の分位点, 発注の数, 上限で切ったか, 見込みの損, 前の期間と同じ数の発注とその見込みの損. 決めた行の数 (`total`), 行の id と商品の id の列 (`id`, `product`), 学んだ水準 (`levels`), 損と上限 (`shortage_cost`, `holding_cost`, `max_order`. 決めていなければ空). 需要の結果でなければ 400 (下の「需要の一式」) |
| `GET /api/results/{id}/artifacts/{row}` | 配列の出力の結果の, 行の位置の配列の見本 (形, 型, 出力の形ごとの見せ方. 下の「受け持ちと出力の形」) |
| `GET /api/results/{id}/artifacts/{row}/file` | 行の位置の配列のファイル (`.npy`) |
| `POST /api/results/{id}/conclude` | 決め方を変えて結論だけを出し直す (結果を書き換える) |
| `POST /api/results/{id}/explain` | 入力の列ごとの効き (ML-Inference の `explain`) を求めて結果に残す (表と時系列のファイルの結果だけ) |
| `POST /api/results/{id}/rows/{row}/reason` | 結果の 1 行の, 元の列ごとにその行の値が予測を動かした向きと大きさ (`effects`) と, 効きの大きい 3 列の文 (`reason`) を求める (ML-Inference の `explain_rows`. 下の「1 行の予測の理由」). 表と時系列の, ファイルを 1 つ先まで予測した結果の, 予測した行だけ. 結果には残さない |
| `POST /api/results/{id}/decide` | 意思決定の決め方を変えて決め直す (推論はし直さない. 空で外す) |
| `POST /api/results/{id}/backtest` | 結果の入力 (目的の列を持つファイル) で, 意思決定の方針と素朴なやり方の実際の得と損を比べる. 一式につないだ問題の守る指標も, この方針の行動で数える (下の「問題とのつなぎ」) |
| `POST /api/results/{id}/remeasure` | 結果の入力 (目的の列を持つファイル) で一式の予測の外れ方を測り直す (ML-Inference の `remeasure`). `write` が偽なら確かめるだけ, 真なら一式に書き戻す (置き場の外の一式なら, 登録した場所のファイルを書き換える. ただし学習の実験のディレクトリの中の一式 (一式か上の 2 つのディレクトリに `run.json` がある) は, 実験を書き換えないという ML-Found の約束に合わせて, 置き場に写してから書き戻し, 登録を写した方に移す. 応答の `copied_to` に写した場所. 「作ったときの記録に戻す」も同じ. 写しの登録は `copied_from` に元の場所を持ち, 元の場所を同じ登録として二重に登録しない. 写しを消しても元の実験の一式は残る. 写すか書き戻すかに失敗したら写しを消し, 登録は移さない). `horizon` と `time` で何段も先の外れ方も段ごとに測る (目的の列の過去の値を使う一式だけ. 画面は確かめたときの段の数と時刻の列で書き戻す). `groups` で外れ方を分ける列の種類ごとにも測る (回帰と予測の一式だけ. 20 行より少ない種類は全ての行の外れ方. 空は分けない. 予測と判断の列と種類ごとの確率の列 (`p:<種類>`) は画面と同じく 400 で断る. 画面は確かめたときの列で書き戻す). 結果には残さない |
| `GET /api/results/{id}/download` | 予測と判断の CSV |
| `DELETE /api/results/{id}` | 結果を消す |
| `GET /api/policies` | 登録した方策の一式の一覧 (`policy.json` の中身 `spec`. 重みは読まない. 読めない一式は理由付き) |
| `POST /api/policies` | 場所を指定して方策の一式を登録する (重みまで読めることを確かめる. 名前は省略するとディレクトリの名前) |
| `GET /api/policies/{id}` | 方策の一式の中身と, 重みのうち読まなかったキー (`unused_keys`). 重みを読めなくなっていれば理由 |
| `DELETE /api/policies/{id}` | 登録を外す (一式のファイルは消さない) |
| `POST /api/policies/{id}/act` | 観測 (`observation`) から, ML-Inference の `GuardedPolicy.act` で守りを当てた行動 (`action`), 守りの結果 (`status`), 理由 (`reasons`) を返す. 結果は残さない |
| `POST /api/policies/{id}/batch` | 観測のファイル (`source`. `.csv` は 1 行に 1 つの観測, `.npy` は先頭の次元を観測の並びに) の 1 件ずつに `act` と同じく守りを当て, 結果を置き場に残して, まとめ (件数, 守りの結果ごとの件数) を返す (下の「方策の一式」) |
| `GET /api/policy-results` | 方策の結果の一覧 (新しい順. `policy` で方策の一式の id で絞れる) |
| `GET /api/policy-results/{id}` | 方策の結果のまとめ (方策の名前と場所, 観測のファイル, 時刻, 件数, 守りの結果ごとの件数) |
| `GET /api/policy-results/{id}/rows` | 方策の結果の表の一部 (`offset`, `limit`, `status` で絞る. 観測と行動は JSON の文字) |
| `GET /api/policy-results/{id}/download` | 方策の結果の表の CSV |
| `DELETE /api/policy-results/{id}` | 方策の結果を消す |

- 推論は同時に 1 つだけ (大きなモデルでメモリを使い切らないように). 推論に使う一式は組み立てたモデルごと少しだけ覚えて使い回す (既定は 4 つ. 環境変数 `ML_PROVIDE_MODEL_CACHE` で変える. モデル 1 つ分のメモリ (重みと組み立てたモデル) を数の分だけ使い続けるので, 大きなモデルでは 1 にする). 一覧と一式の画面の説明はモデルを組み立てずに別に覚え (256 個まで), 推論に使う一式を追い出さない. 登録を消した一式は手放す. 一式のディレクトリの全てのファイル (`inference.yaml`, 定義, データセットの説明とレシピ) と重みのファイルの更新時刻と大きさのどれかが変わったら読み直す (写さない重みは学習し直すと変わるため). 学習済みの重みの警告は, モデルを手放した後も一式が変わるまで出す
- 結論の出し直しと結果の削除は 1 つずつ行い, 書き換えは隣に書いてから置き換える (読んでいる途中の表が壊れないように). 推論の直後も, 書いた表を読み直して結論を出す (出し直したときと同じ型の値でまとめ, まとめの名前が変わらないように)
- 渡したデータに `index` の列がある場合, 表の行の位置の列と重ならないように「`index (入力)`」にする
- 結果を読むときは版を確かめ, 知らない新しい版 (ML-Inference の `RESULT_FORMAT_VERSION` より大きい) の結果は「この版の結果は読めません」で止める (一覧では飛ばす)
- 結論の出し直し, 意思決定, 列の効き, 1 行の予測の理由, たどり直し, 外れ方の測り直しは列の出力の結果だけ. 他の結果では「列の出力でない一式の結果には使えません」で断る (版 2 までの結果は全て列の出力)

## 5. 用語

画面の文 (見出し, ボタン, 欄の名前, aria-label, 説明, 確かめの窓, 誤りの文. API の誤りの文で画面に出るものも) は, 段階をまたいで出る物と操作を殻 (ML-Studio) の docs/DESIGN.md の 5 の節「段階をまたぐ言葉」の表の語で呼ぶ (殻の要求 R11). 表はそこだけが持ち, この段階に関わる主なものは次のとおり.

- 問題: 殻の上の帯で選ぶ 1 つの問題の設定 (`problem.yaml` 1 つ). 一式に「つなぐ」もの. 1 つを指して「問題の設定」「プロジェクト」「課題」とは呼ばない
- 学習のプロジェクト: 問題の設定の段階が書き出す学習の骨組み 1 つ. この段階では縮めずに必ず「学習のプロジェクト」と書く
- 他の段階は段階の名前 (問題の設定, データの分析, モデルの作成・選定, 学習・評価) で呼び, アプリやライブラリの名前で呼ばない. 単独の起動の帯のアプリの名前と, ファイルや config の項目の名前はそのまま出す
- 一式は, 一覧の見出しと段階の並びで初めて出る所では「推論の一式」と書く
- 操作は, 登録する (一式を一覧に載せる), 登録を外す (ファイルは残す), 消す, 書き戻す (一式の `inference.yaml` に測り直した外れ方を書く), 確かめる (確認とは呼ばない), 誤りと失敗の語に合わせる. 異常の度合いの一式で人が 1 件ずつ判断するのは「人の確かめ」と呼ぶ
- 内部の名前 (`project`, `onProjectChange`, API の経路, `hint_project` など) は替えない. 殻の `project` は画面の「問題」を指す

この段階だけの語は次のとおり.

| 用語 | 意味 |
| --- | --- |
| 一式 | 推論の一式. `inference.yaml` を持つディレクトリ (ML-Inference の形). モデルの定義, 重み, データセットの説明とレシピを持つ |
| 結果 | 1 回の推論で置き場に残すもの (予測の表 `predictions.csv`, `result.yaml`, 配列の `artifacts/`) |
| 結論 | 予測から出す判断の内訳とまとめの文 |
| 結論の決め方 | 保留にする確信の下限, 陽性とする確率, 値の帯, まとめる列 |
| 意思決定 | 損得と制約から行ごとの行動を決めること. 型は量を決める, 対象を選ぶ, 振り分ける |
| 外れ方 | 一式が記録した予測の外れ方 (`uncertainty`). 意思決定の前提 |
| 方策の一式 | 強化学習で学習した方策 (`policy.json` と `policy.pt` を持つディレクトリ. ML-Inference の形) |
| 守り | 方策の一式が持つ, 観測で止める条件, 行動の範囲, 外れたときの動き |
| 列の出力 | 出力の形がクラス, 値, 分布の一式. 結論の決め方と意思決定はこれだけに使う |
| 異常の度合い | 異常の度合いの一式が行ごとに出す, 学習用の正常の行からの外れ方の値. 大きいほど異常で, 確率ではない (ML-Inference の用語) |
| 人の確かめの記録 | 人の確かめに回した行を人が確かめた結果の 1 件 (行の id, 異常か正常か, 確かめた人, 時刻. ML-Inference では人の確認の記録 `reviews.csv`) |
| 効果 (uplift) | 効果の一式が行ごとに出す, 処置したときの結果の予測 − しないときの結果の予測. 結果が 0 と 1 なら確率の差, 量なら値の差. 処置を無作為に配った記録から学んだ見積もり (ML-Inference の用語) |
| 処置の群と対照の群 | 学習の記録のうち, 処置した行 (クーポンを配った顧客など) と, しなかった行. 効果は 2 つの群の結果の違いから学び, 評価も 2 つの群の結果の差で数える |
| Qini の曲線と係数 | Qini の曲線は, 効果の高い順に配る行を増やしたときの, 配ったことで増えた結果の積み上げ (上位の処置の群の結果の和 − 対照の群の結果の和 × 処置の群の行の数 / 対照の群の行の数). でたらめに配る線は始めと終わりを結ぶ直線. Qini の係数は, 曲線とでたらめに配る線の間の面積を, 理想の並びの面積で割った値 (1 に近いほど効果の高い行を上に並べている. 0 はでたらめと同じ) |
| 値段, 売れた数, 原価 | 値段の一式の行ごとの, 商品 1 つあたりの売り値 (表の値段の列. 推論ではその行の今の値段), その値段で売れる数 (モデルの予測. 学習の記録では売れた数の列), 商品 1 つあたりの仕入れや作る費用 (原価の列. 無ければ 0 として利益を売上で比べる) |
| 利益 (見込みの利益) | (値段 − 原価) × 予測した売れた数. 予測から数えた見込みで, 売れた実績ではない (ML-Inference の用語) |
| 弾力性 | 値段を 1 % 上げたときに予測した売れた数が何 % 変わるか. 負なら値上げで売れる数が減る. 今の値段での予測した数が 0 の行は数えない (ML-Inference の用語) |
| 変える割合と変える幅の上限 | 変える割合は今の値段に対する値段の変え方 (0.1 は 10 % 上げる, -0.05 は 5 % 下げる). 値段の候補はこの割合の並びで, 今の値段 (0) を含む. 変える幅の上限は, 選んでよい値上げと値下げの大きさの限度 (割合の絶対値の上限. 値段を急に大きく変えないための決まりで, ML-Quest の守る指標. 上限を超える候補は利益が大きくても選ばない). 画面では「守る指標」の語を使わずに, 値段を急に大きく変えないための決まりと書く (初めての利用者に分かるように) |
| 需要と分位点 | 需要は, 発注を決める日の次の日からの先の決めた期間 (一式の `horizon` 日. 届くまでの日数と発注の周期を合わせた日数) に売れる数の合計. 水準 q の分位点は, 需要がその数以下になる見込みが q になる数で, 需要の一式は学んだ水準ごとに分位点を予測する (ML-Inference の用語) |
| 品切れの損と売れ残りの損 | 商品 1 つあたりの, 1 つ足りないときの損 (売り逃した利益など) と, 1 つ余ったときの損 (捨てる原価か持ち越す費用). 同じお金の単位で書く正の数 (どちらかが 0 だと水準 τ が 0 か 1 になり, 分位点で決まらないため) |
| 水準 τ | 品切れの損 / (品切れの損 + 売れ残りの損). 書いた損と需要の分位点の予測が正しいとすれば, 見込みの損が最も小さいのは水準 τ の分位点から在庫を引いた数を発注すること (新聞売りの問題の答え). 学んだ水準の範囲の外なら端の水準の分位点を使う |
| 発注の数の上限 | 1 つの商品で 1 度に発注してよい数の限度 (置き場所の限りなど. ML-Quest の守る指標). 上限を超える数は見込みの損が小さくても発注せず, 上限で切った商品を上限に当たった商品として数える. 画面では「守る指標」の語を使わずに, 置き場所などの決まりと書く (値段の変える幅の上限と同じ) |
| 見込みの損 | 予測した分位点から決まる需要の分布での, 品切れの損と売れ残りの損の和の期待値. 予測から数えた見込みで, 実際の損ではない. 比べる決め方は前の期間と同じ数 (前の期間の合計から在庫を引いた数) の発注 (ML-Inference の用語) |
| 余弦の近さ | 検索の一式の, 問いの写真と索引の写真の埋め込みの向きの近さ. 1 に近いほど見た目が近い (ML-Inference の用語) |
| 索引 | 検索の一式が持つ, 登録した写真の並びと埋め込み. 問いの写真に近いものをここから返す |
| 待ち時間 | 検索の一式の, 1 枚の問いの写真を読んで埋め込み, 上位 K 件が決まるまでの時間 (ミリ秒). 守る指標の上限と比べる |
| 既製のモデル | 学習せずにそのまま使う, ライブラリの学習済みの重みのモデル (torchvision の ResNet18 など). 一式は版 6 |

## 6. 置き場

既定は `~/.ml-provide` (環境変数 `ML_PROVIDE_HOME` で変えられる).

```
~/.ml-provide/
├── bundles.json        # 登録した一式 (id, 名前, 場所, 置き場で作ったか, 登録した時刻, つないだ問題の場所と作った時刻)
├── policies.json       # 登録した方策の一式 (id, 名前, 場所, 登録した時刻)
├── bundles/<id>/       # 画面で作った一式 (ML-Inference の形. 既製のモデルの一式は重みを持たない)
├── policy_results/<id>/  # 方策の結果 (このアプリの形. 版 1)
│   ├── actions.csv     # 1 件ずつの位置 (index), 観測と行動 (JSON の文字), 守りの結果, 理由
│   └── policy_result.yaml # 版, 方策の一式の id (policy_id), 名前と場所, 観測のファイル, 時刻, 件数 (rows), 守りの結果ごとの件数 (counts)
├── samples/sample<n>/  # 見本 (学習用のデータ, 一式, 推論を試す新しいデータと過去のデータ. 領域の見本はデータセットと新しい画像)
└── results/<id>/       # 推論の結果 (ML-Inference の write_result の形. 結果の形の版 1 から 5)
    ├── predictions.csv # 予測と判断の表 (結論を出し直すときは, 判断の列を除いて読み直す)
    ├── result.yaml     # 一式, 入力, 時刻, 決め方, まとめ, 文
    ├── artifacts/      # 表に収まらない中身 (配列の出力の一式の結果だけ. 版 2)
    └── reviews.csv     # 人の確かめの記録 (異常の度合いの結果だけ. ML-Inference の record_review の形)
```

- 作っていない欄の書きかけの下書きは置き場に置かず, ブラウザ (`localStorage`) に残す (上の「3. 画面」の「書きかけの下書き」)
- 一式の登録は場所だけを覚える (学習のスクリプトが実験の中に作った一式を, 写さずに使う). 置き場で作った一式は, 登録を消すと一式も消す
- 結果は一式ごとに新しい順に並べる. 一式を消しても結果は残す (一式の名前を結果にも書く)
- 実験の一覧は ML-Pathfinder の置き場 (`ML_PATHFINDER_HOME`. 無ければ `~/.ml-pathfinder`) の `problems/<識別子>/problem.yaml` を読む (2 つのアプリを同じ置き場で使うため, 環境変数も同じもの). 殻の下では `create_api` の `problems_dir` で問題の設定の置き場を渡す (上の「4. API」)

## 7. 安全

確かめ (トークン, Origin, ホスト名) と `/api/auth` は `create_app` の外側のアプリだけが持ち, `create_api` は持たない. 殻の下では殻が 1 つだけ持つ (段階ごとに確かめが重ならないように). `create_api` を確かめの無いアプリに載せて待ち受けない.

既定では `127.0.0.1` だけで待ち受ける (他のホストを指定すると警告を出す). 起動ごとのトークン (Cookie かヘッダー) を持つ要求だけを API で受け付け, 他のサイトからの書き込み (Origin が接続先と違うもの) と別のホスト名での接続を断る. 手元のファイルを読めるので, トークンは他の人に渡さない.

- 推論は手元のファイルだけを読む. ただし既製のモデルの一式は, 出どころの重みが PyTorch の置き場に無ければ, 作るときと推論のときに出どころ (ライブラリが決めた URL) から取りに行く. 読んだ重みは記録したハッシュ値と比べ, 違えば誤りにする (ML-Inference の決まり). 置き場に手で置く重みのファイルは, 信頼できるものだけにする (ハッシュ値を比べる前にライブラリが読み込むため)
- 実験の一覧は, 問題の設定の置き場と学習のプロジェクトの `outputs` を読むだけ (リンクはたどらず, 深さと件数に上限を置く)
- 元のデータセットのテスト用の分割は, 画面から場所を受け取らず, 一式の実験の記録から見つけた学習のプロジェクトの中のデータセットだけを読む (リンクをたどった後に学習のプロジェクトの外を指すデータセットと, データセットの外を指す分割のファイルは選ばない. 下の「元のデータセットのテスト用の分割」)
- 自作の手順と部品は, 起動の設定で明示したモジュールだけを読み込む. 一式やファイルに書かれた名前からは何も読み込まない (下の「8. 受け持ちと出力の形 (一式の版 3 と 4)」)
- 方策は観測から行動と守りの結果を返すだけで, 環境や機械には触れない. 方策の一式は ML-Inference が重みの sha256 を確かめてから読み, 組み立て方は一式に写したモデルの定義だけ (クラスの名前からコードを読み込まない)
- 実験のディレクトリには書かない. 書き戻しが要るときは置き場に写してから書く (上の「4. API」の `remeasure`)

## 8. 受け持ちと出力の形 (一式の版 3 と 4)

ML-Inference の一式の版 3 は, 受け持ち (`role`), 出力の形 (`output.form`), 正解の種類と出どころ (`target`), 繰り返しの手順 (`procedure`), 学習済みの重みの置き方 (`model.pretrained`) を持つ. 版 4 は版 3 に 1 件の扱い (`items`) を足した, ファイルの組のデータセットの一式 (下の「ファイルの組のデータセットの一式」). 版 1 と 2 の一式も読み, 受け持ちは予測する, 出力の形はタスクから, 正解の種類は列として扱う.

- 一式の画面に, 版, 受け持ち, 出力の形 (形ごとの欄: 分布の水準, 領域のクラスの名前, 雑音から始まる手順の 1 件の形, 表の列の名前と型), 正解の種類と出どころ, 手順 (名前, 回数, 乱数の種, 設定. 設定と読み込みの設定は「名前 値」の並びで出す. 入れ子の値と, 空, 空白, カンマ, 括弧を含む文字, 引用符か [ { で始まる文字, 数や真偽や null に見える文字 (0, 1e3, 0x1, inf, nan, yes, on, ~, 2026-11-22 など. 大文字と小文字を区別しない) は JSON の引用符を付ける. 文字の "0" と数の 0 を見分け, YAML 1.1 で読んでも型が変わらないようにするため), 学習済みの重みの置き方 (ノードごとの出どころ, 版, ライセンス, 置き場) を出す. `describe_bundle` の `target` は目的の列の名前で, 正解の種類と出どころは `target_info`
- 列の出力か (`column_output`) で推論の流れを分ける. 列の出力 (`class`, `value`, `distribution`) は表の流れ (`infer` → `write_result` → 書いた表を読み直して `conclude`). 列の出力でないものは, 結論の決め方と意思決定の欄を隠し, `infer` の件数だけの結論 (ML-Inference の `conclude_outputs`) を使う. 書いた表を読み直して件数を数え直すときは `conclude` をかけず, `read_result` で読んだ結果をそのまま `write_result` に渡す (配列は持ち越す)
- 結果には一式の受け持ち, 出力の形, 列の出力か, 正解の種類と出どころ, 学習済みの重みの警告を残す (一式を消しても結果の画面で分かるように)
- 配列の見せ方 (`GET /api/results/{id}/artifacts/{row}`. `read_result` で読み, `artifact_path` で結果のディレクトリの中に解決する): 領域は行と列を間引いた (最大 256 × 256) 整数の格子を返し, 画面はクラスごとの色で描く. 画像は (高さ, 幅), (高さ, 幅, チャンネル), (チャンネル, 高さ, 幅) を最小と最大で 0 から 255 にした格子で返し, 画面は描く. 点群は最大 2,000 点を間引いて最初の 3 つの次元を返し, 画面は 2 つの次元を選ぶ散布図にする. ベクトルは形, 長さ (L2), 最初の 16 個の値. どの形も `.npy` を落とせる. 配列は `mmap_mode` で開き, 先に間引いた分だけを数にする (長さと領域の画素の数は区切って数える). 見本を作るのは同時に 2 つまで. 値が 2 億個を超える配列と, 実数, 整数, 真偽でない配列 (複素数, 構造のある型, 文字. オブジェクトの配列は pickle を読まないので読めない) は見せずに理由を返す. CSV のダウンロードは表だけで, 配列の列は結果の中の相対パス
- 文を出す一式 (`text`) の結果は表に収まる (`prediction` に一式のレシピの語彙で戻した文, `tokens` に番号を空白でつないだ文字. ML-Inference の決まり) ので結果の形は版 1 (列の型を残す結果は版 3 か 4). 結論は件数だけ. 予測の表は ML-Inference の `read_result` で読む (文と番号を文字のまま読み, 予測した行の空の文と番号は空の文字. 番号 1 つの並びや数と `NA` に見える文を数や欠損にしないため. 2. の「予測の表」の決まり). 古い文の結果は `tokens` の列を持たないので, 版の補いとして, `result.yaml` の出力の形が `text` の結果は `override_types` で予測を文字で読み, 予測した行の空の文を空の文字に戻す (全ての行が番号 1 つの予測でも `5.0` のような数にしないため). 渡したデータの `tokens` の列は「`tokens (入力)`」になる
- 正解の出どころが今の処理 (`target_info.origin.type` が `process`) の一式は, 一式の画面に「正解は … の出力なので, 予測はその処理との一致までしか分からず, その処理を超えられません」を出す. 結果の画面にも出す. 結論の文には混ぜず, 結果の `origin_note` に分ける (まとめる列ごとの文と全体の文の分け目を崩さないため. 全体の文の数は結果の `overall_count`)
- 学習済みの重みの注意 (`notes`) と警告 (`pretrained_warnings`. 出どころから読んだ重みのハッシュ値が記録と違うなど) は必ず出す. 警告はモデルを組み立てた後に分かるので, 一式の画面は組み立てる前ならそう書き, 推論の後は結果にも残す

### ファイルの組のデータセットの一式 (一式の版 4)

ML-EDA の書き出しの約束の版 2 と版 3 のデータセット (`load_items` で読むファイルの組. 画像と領域, 撮影と点群. 版 3 は版 2 に, 書き出しでかけた項目ごとの中身の手順 (`steps`) を足した版) からも, 「学習の結果から作る」で一式を作る. 版 2 と版 3 は同じ画面と同じ欄で扱う. ML-Inference の `make_bundle` が, 学習のスクリプトがした 1 件の扱い (画像を 0 から 1 にする, 深度から点に戻して決まった数を選ぶ) を `items` に書いた版 4 の一式を作り, 推論で同じ扱いをかける. 版 1 のデータセットからは今のまま版 3 までの一式を作る.

- データセットを選ぶと `GET /api/datasets/describe` で版を読み, 版 2 と版 3 なら受け持ち, 正解の種類と出どころ, 入力と正解の項目 (名前と種類), 版 3 なら項目ごとの中身の手順 (`resize (width 64, height 64)` など), 分割ごとの件数を出す. 読むのは ML-Inference の `describe_items` (ML-EDA の `load_items` で読む) で, 読めないデータセットと知らない新しい版は ML-EDA の誤りの文をそのまま出す. 作れる組 (予測するで, 正解の種類が領域か点群) かどうかは `make_bundle` が確かめる. 説明を読めなかったデータセットでは「作る」を押せない (作る段階で分かりにくい誤りになるため)
- 版 3 の中身の手順は ML-Inference が一式のデータセットの写しから読み, 推論で新しい 1 件に同じ手順をかけてから 1 件の扱いをかける (大きさの違う画像も学習と同じ大きさにそろう). 元の画像の領域は件ごとに元の画像の大きさに戻して返り, データセットのディレクトリの件はデータセットの大きさのまま返る (ML-Inference の決まり. 戻すときに値を混ぜないので, 領域は領域の値だけのまま). このアプリは手順を見せるだけで, 欄は足さない
- 入力の項目が撮影か点群なら, 選ぶ点の数 (`items.options.points`) が要る (学習と違う数だと黙って違う予測になり, 一式の確かめでも気付けないことがあるため). 確かめで正解から選ぶ点の数 (`target_points`. 空なら正解の全ての点) と点を選ぶ乱数の種 (`seed`. 空なら 0) は任意. ML-Quest の骨組みで学習した実験なら, config の `data.input_points`, `data.target_points` と, 検証用の分割の種 (`data.seed` + 1) を書く (骨組みが実験の中に作る一式と同じ値になり, 一式の確かめが学習の記録と合う). 入力の項目が複数あれば選ぶ. 正解の項目, 扱い方, 領域の値, 点群の戻し方はデータセットから決める (ML-Inference の決まり)
- ファイルの組のデータセットでは, 前処理の外でしたこと (並びの先頭の番号, 目的の値の標準化) と, 受け持ちと出力の形の欄を出さない (前処理のレシピを持たず, 出力の形は正解の種類から決まるため). 出力が複数のモデルの出力の名前の欄は出す
- 一式の画面は, 列の一式の読み込みと前処理の代わりに 1 件の扱い (入力の項目と種類, 扱い方, 設定, 正解の項目, 点群の戻し方) を出し, 出力の形の欄に領域の値ごとの名前を出す. 一式での評価は, 領域は IoU (背景を除くクラスの平均), 点群は Chamfer 距離で, 実験の記録 (`valid/iou`, `valid/chamfer`) と比べた結果を添える
- 推論するデータは, 入力の項目と同じ種類の元のファイル (画像のファイルかディレクトリ, 撮影のディレクトリかそれを並べたディレクトリ, 点群のファイルかディレクトリ) か, ファイルの組のデータセットのディレクトリ (入力の項目の中身の手順が一式と同じもの. 違えば ML-Inference が止める). 元の撮影には学習と同じ正規化 (と中身の手順) をかけ, 読めない件は理由を付けて飛ばす (ML-Inference の `predict`)
- 結果の領域は領域の値 (データセットの領域のファイルと同じ値) の格子で, 凡例は値ごとの名前 (一式の `items.values` と `output.classes` を並べた組). 点群は元の座標 (戻し方が `shift` なら, 正規化の平行移動を戻した撮影の世界の座標. メートル) の散布図で, そう書き添える
- 実験の一覧は, ML-Quest の骨組み (領域と点群) が実験の中に作った版 4 の一式も同じく並べる (一覧は `inference.yaml` の版を見ない. 読めるかは登録のときに確かめる)

### 雑音だけの一式 (一式の版 5)

ML-Inference の雑音だけの一式 (`dataset: null`) は, 条件の無い生成のモデル (拡散やフローのモデル) の一式で, データセットを持たず, データの行の代わりに件数と種から生成する. 説明の `kind` は `noise` で, 画面では「雑音だけ」と出す.

- 作り方: `POST /api/bundles/create` で `dataset` を省くか空にし, 雑音から始まる手順 (`procedure`), 1 件の形 (`output_options.shape`), 配列の出力の形 (`form`), 入力の出どころ (`inputs`. `state` と `time` だけ) を渡す. 要る欄と組の確かめ (手順の 2 件の生成も) は ML-Inference の `make_bundle` がする
- 推論: `POST /api/bundles/{id}/predict` に件数 (`count`) と種 (`seed`) を渡し, ML-Inference の `infer` に `{"count": n, "seed": s}` を渡す. ファイルか文を一緒に渡すと断り, 雑音だけの一式でない一式に件数か種を渡しても断る. 結果の入力の文は ML-Inference の「件数 n, 種 s」(種を省けば一式の手順の種)
- 件数の上限: 1 回に 1,000 件まで, かつ件数 × 1 件の形の値の数が 1 億 (float32 で 400 MB) まで. ML-Inference は始まりの雑音を全ての件の分を一度に作り, 出力も件ごとに記憶に持ってから書くため, 大きな件数で記憶を使い切らないように画面が決める. 上を超えると, 1 件の形と受け付ける件数を書いて断る. 1 件だけで値の数の上限を超える形は「1 件の形が大きすぎます」で断る. 作るときの 1 件の形の誤り (`output.shape` の誤りと, モデルの入力と形が合わない実行時の誤り) には, 1 件の形の欄を見直す案内を添える. 重みが定義と合わない誤り (`state_dict` の誤り) には添えない (形の欄では直らないため). 雑音だけの一式を作るときも, ML-Inference が確かめで 2 件を作るので, `output_options.shape` の 2 件が上限を超えれば作る前に断る (データセットのある一式は確かめの件数が決まらないので当てない)
- 同じ一式, 同じ件数, 同じ種なら同じ出力 (ML-Inference の決まり). 結果の表は件ごとの番号 (`sample`), 使った種 (`seed`), 配列の列で, 配列の見せ方は他の列の出力でない一式と同じ (表の出力は下の「表の出力の雑音だけの一式」)
- 画面: 一式を作る対話の「雑音だけから作る」で作る (入力の欄には手順の中身と時刻の 2 つの行を用意する. 名前はモデルの定義の入力の名前. 選ぶと候補から外れる手順と出力の形を空にし, 前からある行の表の列か中身の出どころは問題として出す. 選ぶのをやめると, 畳む欄に見えない値を残して送らないように, 自動で足した行 (書き換えていないもの), 手順, 受け持ち, 出力の形と形ごとの欄を空に戻す. 先頭に足した番号は, 番号を足せる出どころ (中身, 手順の中身) の行だけ送る. 名前の無い入力の行と重なる名前があれば送らずに知らせる (名前は Map で数え, `constructor` や `__proto__` も名前として扱う). 畳んだ欄の誤りは見出しと同じ欄の名前を添えて出し, 欄の誤りの数が 0 から 1 以上になったときだけ欄を開く (開き閉じは利用者の操作を写して持ち, 自動では閉じない. 打っている途中に誤りが消えて欄が閉じないように). 誤りの文は polite で読み上げる. 手順を選んでいないのに出どころが手順の中身か時刻の行があれば, 手順を選ぶか出どころを変えるよう知らせる. 雑音だけの一式の行には先頭に足した番号の欄を出さず, 番号も送らない. 手順の設定の欄には既定値を薄い字で出す. 送った後に欄を変えたら, 前の誤りは出さない). 一式の画面は「データ」に雑音だけと出し, 読み込みと前処理の行と「問題」の欄を出さない (データも正解も無く, 問題の推論の結論と意思決定を使えないため. 問題も読まない. 一覧で種類が分かれば要求もしない). 推論の欄は作る件数 (上限は `GET /api/info` の `max_samples`) と乱数の種 (空なら一式の手順の種)
- 正解も検証の分割も無いので, 一式の確かめ, 外れ方, 列の効き, 何段も先の予測, たどり直し, 測り直しは無い

### 表の出力の雑音だけの一式 (一式の版 7)

ML-Inference の表の出力の雑音だけの一式 (`output.form: table`) は, 表を作る生成のモデル (列ごとに符号化した行を拡散で学んだモデル) の一式で, 列の符号化 (`output.columns`. 列の順の名前と型. 数の列は平均, 標準偏差, 整数か. 種類の列は値の種類) を持つ. 他は雑音だけの一式と同じで, 推論は件数と種.

- 作り方: ML-Quest の表の生成の骨組みの学習が実験の中に作る一式 (`inference`) を, 実験の一覧か場所で登録する (下の「実験の一覧」). 一式を作る対話の出力の形には表を出さない (列の符号化の欄が要り, 学習のスクリプトが書く `table_columns.json` を写すのが確かなため. データセットのある一式では使えない)
- 一式の画面: 出力の形に「表」と列の数と 1 件の幅 (符号化した行の幅) を出し, 「表の列」に学習のときの列の並びで名前と型 (数は平均と標準偏差, 整数, 種類は種類の数と, 先頭の 10 個の値) を出す. 画面の文では「符号化」の言葉を使わない
- 推論: 結果は配列を持たない (結果の形の版 1 か, 列の型を残す版 3 か 4. `artifacts` は無い) 表で, 件ごとの番号 (`sample`), 使った種 (`seed`), `status`, `reason` の後に, 列の符号化の順の列が並ぶ. 結論は件数だけ. 予測の後に表を読み直して件数を数え直すことはしない (数え直しても件数は同じため)
- 予測の表を読むときは, 空の欄だけを欠損にする (種類の値の `NA`, `null`, `None`, `n/a` を文字のまま読むため. 2. の「予測の表」の決まり)
- 結果には列の名前と型 (`table_columns`. 名前, `number` か `category`, 数の列は整数か, 種類の列は種類の数) を残す (一式を消しても列の順と型が分かるように). 予測の表を読むときは, 種類の列を文字 (`column_types` に依らない), `column_types` に無い整数の列を欠損を持てる整数で読む (推論しなかった行の値は欠損. 列の型を持たない版 1 の結果のため)
- 結果の画面: 「作った表」に, 行の位置, 件の番号, 種, 状態, 理由 (見出しは日本語. CSV の見出しは `sample`, `seed`, `status`, `reason` のまま), 列の符号化の順の列 (見出しは列の名前のまま) を並べ, 列の型を表の上に書く. 判断の列 (列の出力でないので空) は出さない. 「CSV」で表のまま持ち出す

### 並べるの一式 (一式の版 8)

ML-Inference の並べるの一式 (`rank`) は, 利用者と品物を別の塔で埋め込みにして内積を点数にする 2 塔のモデルの一式で, データセットを持たず, 利用者と品物の番号の表, 全ての品物の埋め込みの索引, 並べる件数の既定 (`rank.k`. 問題の件数), 反応の表の列の名前 (`rank.columns` の `user`, `item`, `reaction`) を持つ. 説明の `kind` は `rank` で, 画面では「並べる (利用者と品物)」と出す. 出力の形は `ranking` (画面は「順位 (利用者ごとの上位の品物)」).

- 作り方: ML-Quest の並べるの骨組みの学習が, 定義を置けば学習の後に実験の中に作る一式 (`inference`. ML-Inference の `make_rank_bundle` で, 件数と反応の表の列は問題の値) を, 実験の一覧か場所で登録する (下の「実験の一覧」). 骨組みの外で `make_rank_bundle` で作った一式も場所で登録できる. 一式を作る対話には並べるを出さない (件数と反応の表の列は骨組みが問題から渡すため)
- 一式の画面: 「データ」に番号の表と索引 (データセットなし), 番号の表の利用者と品物の数と埋め込みの幅, 並べる件数の既定, 反応の表の列 (利用者, 品物, 反応の強さ) と, どの行を反応とするか (反応の強さの列が 0 より大きい行) を出す. 読み込み, 前処理, モデルの入力の行は出さない (モデルの入力は利用者と品物の番号で, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と意思決定を使わず, 件数と列は一式が持つため)
- 推論の欄 (「利用者ごとに並べる」): 利用者の表は上の行の利用者から順に並べ, 結果の表もその順. 並べる利用者 (1 行に 1 人書くか, 利用者の列を持つ表のファイル), 並べる件数 K (既定は一式の `rank.k`. 1 から 1,000), 前に反応した品物を除くか (除くなら前に反応した品物の表), 正解の反応の表 (任意). 除くのに表が無ければ並べられない. 結論の決め方と意思決定の欄の代わりに, 利用者ごとの品物の一覧を出すので結論は並べた利用者の人数だけで, 結論の決め方と意思決定は数や種類を予測する一式で使うため使えないと書き, 問題の欄が無い理由 (件数と列は一式が問題から写して持つ) も書く (意思決定の型は一式の受け持ちと出力の形で決まり, 並べるに使える型は無いため. 型の名前は利用者の言葉でないので出さない)
- 推論: `POST /api/bundles/{id}/predict` に利用者 (`users`. 書いた値の並び. 前後の空白を除き, 空の行は飛ばす) か利用者の表のファイル (`source`), 件数 (`k`. 省くと `rank.k`), 前に反応した品物の表 (`seen`) と正解の反応の表 (`truth`) のファイルを渡す. 件数は整数だけで, 小数, 文字, 真偽は 400 で断る. 表は CSV, TSV, Parquet のファイル (ディレクトリは断る) で, CSV と TSV は全ての列を文字で読み, 空の欄だけを欠損にする (番号の表と文字にして引くので, `007` を 7 にしないため). 利用者と件数を ML-Inference の `infer` (`k`, `seen`) に渡し, 正解の反応の表があれば `rank_metrics` (前に反応した品物の表も渡し, その品物を正解から除く) で Recall@K と NDCG を数える. 文, 件数と種, 読み込みの設定, 結論の決め方, 意思決定を渡すと断り, 並べるの一式でない一式に `users`, `k`, `seen`, `truth` を渡しても断る. 利用者は 1 回に 10,000 人まで, 表の行 (利用者の数 × 件数と品物の数の小さい方) は 100 万行まで (結果の表を 1 つの CSV に書き, 画面で読み直すため). 前に反応した品物の表と正解の反応の表も 100 万行まで (利用者ごとの品物の集合を記憶に持つため). 結果の入力の文は, 書いた利用者は ML-Inference の「利用者 n 人」, 表のファイルは「場所 (利用者 n 人)」
- 結果: 表は利用者と順位ごとの 1 行 (`user`, `status`, `reason`, `rank`, `item`, `score` と, ML-Inference の `decision`) で, 配列を持たない (結果の形の版 1 か, 列の型を残す版 3 か 4. 並べられない利用者の欠けた順位, 0 で始まる利用者など). 結論は ML-Inference の利用者の人数の結論 (`summary` は `rows` (利用者の数), `predicted`, `skipped`, `k`, `excluded`) のまま. 予測の後に表を読み直して件数を数え直すことはしない (件数だけの結論は行を数え, 利用者ごとの数え方と違うため). 結果には `ranking` (件数, 除いたか, 反応の表の列, 使った前の反応と正解の反応の表の場所, Recall@K と NDCG (`users`, `k`, `recall_at_k`, `ndcg`. 正解の反応の表が無ければ空)) を残す. 予測の表を読むときは, 利用者と品物を文字, 順位を欠損を持てる整数で読み, 空の欄だけを欠損にする (2. の「予測の表」の決まり. 利用者と品物は画面の都合で `column_types` に依らず文字)
- 結果の画面: 結論の文, 利用者, 並べた利用者, 並べられなかった利用者, 並べた件数の数. 「並べ方と評価」に件数, 前に反応した品物を除いたか (除いた表の場所), 正解の反応の表, 反応の表の列と, 正解の反応の表があれば Recall@K, NDCG (見出しにそれぞれ「上位 K 件に入った正解の割合」「上位 K 件の正解の位置で見た並びの良さ」を添える), 数えた利用者 (正解のある利用者) の数. 「並べた品物」に, 行の位置, 利用者, 順位, 品物, 点数, 状態 (並べた, 並べられず), 理由を並べる (見出しと状態は日本語. CSV は英字の見出しのまま). 並べられなかった利用者 (番号の表に無い, 空, 除くと残らない) は 1 行で理由を出す. 判断の列と判断で絞る欄は出さず, 状態で絞る欄は「並べた利用者の行」と「並べられなかった利用者」. 結論の決め方, 意思決定, たどり直し, 外れ方の確かめ, 列の効きは出さない (API も列の出力の結果だけで断る)

### 群分けの一式 (一式の版 9 と 16)

ML-Inference の群分けの一式 (`group`) は, 表の行を埋め込みにする符号化器と埋め込みの空間の群の中心の一式で, データセットを持たず, 列の符号化と群の中心, 群の数 (`group.k`), 群を作る列 (`group.columns`. 群の要約の列の順), 学習で群に分けた行の数, 学習の群の安定性 (`group.stability`. 調整ランド指数 `ari` と最も低い値 `ari_min`, シルエット係数 `silhouette` と, それぞれの比べる相手の値 `_baseline` と差 `_diff`, 作り直し方 `method` と回数 `repeats`, 比べる相手の名前 `baseline`, エポック `epoch`), 学習のときの群の要約 (`group.summary`) を持つ. 学習の表を渡して作った一式は版 16 で, 群ごとの群の中心から遠い行の上限 (`group.far`) も持つ (下の「群の中心から遠い行」). 説明の `kind` は `group` で, 画面では「群分け」と出す. 出力の形は `cluster` (画面は「群 (行ごとに最も近い群)」).

- 作り方: ML-Quest のまとめるの骨組みの実験から ML-Inference の `make_group_bundle` で作った一式を, 場所で登録する. 実験の中に作った一式 (`inference`) は実験の一覧からも登録できる (下の「実験の一覧」). 一式を作る対話には群分けを出さない (列の符号化, 群の中心, 群の安定性は骨組みの実験の成果物から写すため)
- 一式の画面: 「データ」に列の符号化と群の中心 (データセットなし), 群を作る列, 群の数と学習で分けた行の数, 学習の群の安定性 (結果の画面と同じ表), 学習のときの群の要約 (結果の画面と同じ表) を出す. 読み込み, 前処理, モデルの入力の行は出さない (モデルの入力は群を作る列を一式の式で符号化したもので, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と意思決定を使わず, 群の数と列は一式が持つため)
- 推論の欄: 行の表のファイル (群を作る列を持つ, 学習のときと同じ形の表) を選ぶ. 結論の決め方と意思決定の欄の代わりに, 結論は群ごとの件数と特徴で, 結論の決め方と意思決定は数や種類を予測する一式で使うため使えないと書く
- 推論: `POST /api/bundles/{id}/predict` に行の表のファイル (`source`) を渡し, ML-Inference の `infer` で群に割り当てる. 文, 件数と種, 結論の決め方, 意思決定, 何段も先の予測, 並べるの欄を渡すと断る (列の出力でない一式と同じ)
- 結果: 表は元の列と `status`, `reason`, `group` (最も近い群の番号), `distance` (その中心までの埋め込みの空間の距離) と, ML-Inference の `decision` で, 配列を持たない (結果の形の版 1 か, 列の型を残す版 3 か 4). 結論は ML-Inference の群分けの結論 (`summary` は `rows`, `predicted`, `skipped`, `k`, `groups` (群の要約. ML-Inference の `group_summary` の行. 群の番号の順で最後が「全体」), `representatives` (群の代表の行. ML-Inference の `group_representatives` の並びで, 群ごとに中心に近い行を 3 件まで), `stability` (一式の群の安定性の写し)) のまま. 予測の後に表を読み直して件数を数え直すことはしない (件数だけの結論にすると群の要約, 群の代表の行, 群の安定性が消えるため). 結果には `grouping` (群を作る列, 学習のときの群の要約, 推論した表で値が全て文字だった元の列 `texts`) を残す (一式を消しても, 新しいデータと学習のときの群の大きさを比べられるように). 予測の表を読むときは, 群の番号を欠損を持てる整数で読み, `texts` の列は文字のまま読み, 空の欄だけを欠損にする (2. の「予測の表」の決まり. `column_types` の列はその型. 割り当てない行は欠損. 数に見える種類の値 `001` と種類の値の NA, null, None を, 推論したときの値のまま割り当てた行の表と代表の行に出すため. 数と文字の混ざる列は数を文字にしないよう `texts` に入れず, 版 4 の結果の `mixed` の型で値ごとに数か文字のまま読む)
- 代表の行の件数を変える: `GET /api/results/{id}/representatives` に件数 (`count`. 1 から 20. 群の数 × 件数の行を 1 度に返すので上限を置く) を渡すと, 置き場の予測の表を読み, 登録した一式で ML-Inference の `group_representatives` を呼ぶ (結果には残さない). 一式が登録されていないか読めない場合は 400 で, 結論の 3 件は残る.
- 結果の画面: 結論の文, 行, 割り当てた行, 割り当てられなかった行, 群の数. 「群の要約」に群ごとの行 (群, 件数, 割合と横棒, 学習のときの割合, 安定性 (学習のときの作り直した群との Jaccard 係数の平均), 群を作る列ごとの特徴) と, 最後に全体の行を並べる. 列の特徴の見出しは, 数の列は「平均」, 種類の列は「最も多い値 (割合)」を添える (ML-EDA の群の要約の決まり). 割り当てた行の無い群も件数 0 で並べる (群が消えたことに気付けるように). 「群の安定性」に調整ランド指数, 最も低い調整ランド指数, シルエット係数の, モデルの値, 比べる相手の値, 差 (モデル − 比べる相手) の表と, 作り直し方と回数, 比べる相手の名前, エポック, 値の読み方 (調整ランド指数は作り直しても同じ群になるか. 1 に近いほど安定. シルエット係数は群の間の離れ方. -1 から 1 で高いほど分かれている) を出す. 新しいデータでは群を作り直さないので, 群の安定性は学習のときの値と書く. 「割り当てた行」に, 行の位置, 群, 距離, 状態 (割り当てた, 割り当てられず), 理由, 元の列を並べる (見出しと状態は日本語. CSV は英字の見出しのまま). 判断の列と判断で絞る欄は出さず, 状態で絞る欄は「割り当てた行」と「割り当てられなかった行」, 群で絞る欄で 1 つの群の行だけを見る (群の要約の行の「行を見る」からも絞る). 「群の代表の行」を群の要約の次に置き, 群ごとに中心に近い順の行 (群, 順位, 行の位置, 距離, 群の要約の列の値) を並べる (群の平均や最も多い値だけでなく, 群らしい具体的な行から群を解釈できるように). 件数は既定が結論の 3 件で, 1, 3, 5, 10, 20 から選ぶ (3 件は結論のまま, 他は上の API で求め, 求め終わるまで読み込み中を出す (選んだ件数と違う件数の表を出さないため). 結論に代表の行が無い結果は 3 件も API で求める). 数の列 (群の要約が平均の列) の値は, 文字でも数に読めれば数として見せる (数にできない値を含む列は予測の表で文字の列になるため). 行の無い群も「割り当てた行はありません」で並べる. 代表の行の「行を見る」で, 割り当てた行の表をその行だけにし (群で絞る欄もその群にする), 「1 行の絞りを外す」でその群の行に戻す. 表の状態か群で絞る欄を変えても外れる. 代表の行が出せない場合 (一式を消したなど) は理由を出す. 結論の決め方, 意思決定, たどり直し, 外れ方の確かめ, 列の効きは出さない (API も列の出力の結果だけで断る)
- 群の中心から遠い行 (版 16 と 17): 最も近い群に割り当てるだけでは, 学習のときに無かった種類の行も似ていない群に入ったまま見落とすので, ML-Inference が付ける印と件数を出す. 一式の上限 (`group.far`) は, 学習の行の群の中心までの距離の, 群ごとの分位点 (`quantile`. 0.99) で, 学習の行の数 (`rows`) と群の番号の順の上限 (`thresholds`. 行の無かった群は null) を持つ. 表は `distance` の後に `far` (真偽値. 上限より遠い割り当てた行が真) を持ち, 結論は `summary.far` (`quantile`, 印の付いた行の数 `rows`, 群ごとの `group`, `rows`, `threshold` の `groups`) と, 群ごとの件数の文の後の遠い行の件数の文を持つ (ML-Inference の `group_far`). 群の要約の行 (ML-EDA の形) には足さない. 結果の `grouping` に一式の上限の写し (`far`) も残す (一式を消しても学習の行の数を出せるように). 上限を持たない一式 (版 9 と 10) の表, 結論, 結果は今までのまま (遠さの列, 文, 欄を持たない)
  - 一式の画面: 「遠い行の上限」に, 学習の行の数, 分位点, 群ごとの上限 (上限の無い群は –) と, 推論でこれより遠い行に印を付けることを出す
  - 結果の画面: 「群の代表の行」の次に「群の中心から遠い行」を置き, 群ごとの遠い行の件数と距離の上限 (最後に全体の件数) と, 上限の決め方 (学習の行の距離の 99 % 点) と読み方 (学習のときに無かった種類の行かもしれないので, 群の特徴で判断する前に確かめる) を出す. 群の行の「行を見る」で, 割り当てた行の表をその群の遠い行だけにする. 結論の「群の数」の欄に遠い行の数を添える. 「割り当てた行」の表は距離の次に「中心から遠い」の列 (遠い行は「遠い」, 他は空) を並べ, 遠さで絞る欄 (遠さを問わない, 中心から遠い行, 遠くない行) を出す. 遠さで絞る欄は群で絞る欄と状態で絞る欄と重ねて使え, 代表の行の 1 行の絞りは外す

### 既製の埋め込みの群分けの一式 (一式の版 10 と 17)

ML-Inference の既製の埋め込みの群分けの一式 (`group` と `ready`) は, 学習しない既製のモデル (版 6 の出どころ) の分類の最後の層の手前の出力を埋め込みにし, 写真を埋め込みの空間の群の中心に割り当てる一式 (商品の写真を見た目で群に分けるなど) で, 版 9 の群分けの一式の `group` に既製のモデルの出どころ (`ready`) を持たせたもの. 列を符号化しないので `group.features` は null, 写真を見分ける列 `group.id` は `path`, 群の要約の列 `group.columns` は写真の幅と高さ (`width`, `height`). 説明の `kind` は `group` で, 出力の形は `cluster`. 下に書かないことは版 9 の群分けの一式と同じ (群の中心, 群の安定性, 群の要約の形と画面を 1 つにするため).

- 作り方: ML-Quest の既製の埋め込みの群分けの骨組みの `bundle.py` が作る一式を場所で登録する. 一式を作る対話には出さない (群の中心と群の安定性は骨組みが写真から作るため)
- 一式の画面: 既製のモデルの出どころ, 重み, 前処理, ライセンスの行 (版 6 と同じ) に加えて, 群の要約の列 (符号化しない写真の列と書く), 群の数と骨組みが群に分けた写真の数と埋め込みの幅, 割り当て直しの一致, 遠い行の上限 (版 17. 骨組みが群に分けた写真で求めた上限. 版 16 と同じ行), 学習の群の安定性と学習のときの群の要約 (版 9 と同じ表) を出す
- 推論の欄: 群に分ける写真のファイルかディレクトリを選ぶ (重みの説明の前処理をかけて既製のモデルの埋め込みを最も近い群の中心に割り当て, 読めない画像は理由を付けて飛ばすと書く). 結論の決め方と意思決定の欄の代わりの文は版 9 と同じ
- 推論: `POST /api/bundles/{id}/predict` に写真のファイルかディレクトリ (`source`) を渡し, ML-Inference の `infer` で群に割り当てる. 読み込みの設定は渡せない (写真は一式の前処理で読むため. ML-Inference の誤りのまま 400). 他に渡せないものは版 9 と同じ
- 結果: 表は画像の読み込みの表 (`path`, `width`, `height` など) と `status`, `reason`, `group`, `distance` (版 17 は `far` も) (読めない写真は割り当てない行で, 理由は「画像を読めません (…)」). 結論, `grouping` (`columns` は群の要約の列の写真の幅と高さ. 群は埋め込みで作る. `photos` は true で, 写真の縮小画像を読める結果の印), 代表の行の件数を変える API は版 9 と同じ. 代表の行の値は写真の場所と幅と高さ (ML-Inference の `group_representatives`)
- 写真の縮小画像: `GET /api/results/{id}/group-photo` に `path` (結果の表の `path` の値) を渡すと, 検索の一式の問いの写真と同じく長い辺を 256 画素以下に縮めた PNG を返す. 読むのは結果の `source_path` (ディレクトリならその中, ファイルならそのファイルだけ) だけで, 外を指す (`..` やリンク), ファイルでない, 画像として読めない場合と, 形式, ファイルの大きさ, 画素の数の上限は検索の一式と同じく 400 (写真の場所は画面から送るので, 推論した写真の外のファイルを読ませないため). 結果が既製の埋め込みの群分けの結果でない (`grouping.photos` が無い) か写真の場所の記録が無い場合も 400, 結果が無ければ 404
- 結果の画面: 版 9 と同じ. 群の要約の列の特徴は写真の幅と高さの平均. 群の代表の行は, 群の列の次に写真の縮小画像を並べ (見た目で分けた群は, 場所と幅と高さでは何の群かを読み取りにくいため), 群を作る列に無い値 (写真の場所 `path`) を群を作る列の前に並べる (どの写真が群らしいかを場所で分かるように). 縮小画像は代わりの文に群, 順位と場所を持ち, 画面に入るときに読む. 読めない写真は画像の代わりに「読めません」と出す

### 異常の度合いの一式 (一式の版 11)

ML-Inference の異常の度合いの一式 (`anomaly`) は, 正常の行が多い表の行ごとに異常の度合いを出す一式で, データセットを持たず, 度合いの決め方 (自己符号化器の再構成の誤差 `autoencoder` か, 学習用の正常の行の中心からの距離 `distance`. どちらも大きいほど異常) と前処理のレシピ, 度合いに使う列 (`anomaly.features`. 前処理の後の列), 行の id の列 (`anomaly.id`), 人が 1 回に確かめる件数の上限 (`anomaly.capacity`), 実験の評価の上位 K 件の K (`anomaly.k`), 学習用の正常の行の度合いの分布 (`anomaly.normal`), 実験の上位 K 件の適合率と PR-AUC (`anomaly.evaluations`. 異常の行のある分割だけ), 元の表での確かめ (`anomaly.check`) を持つ. 説明の `kind` は `anomaly` で, 画面では「異常の度合い」と出す. 出力の形は `value` だが列の出力ではない (`column_output` が偽. 度合いは確率でも目的の列の値でもないため).

- 作り方: ML-Quest の異常の検知の骨組みの実験から ML-Inference の `make_anomaly_bundle` で作った一式を, 場所で登録する. 一式を作る対話には異常の度合いを出さない (度合いの決め方と前処理のレシピは骨組みの実験の成果物から写すため)
- 一式の画面: 「データ」に度合いの決め方と前処理のレシピ (データセットなし), 度合いの決め方, 度合いに使う列, 行の id の列, 前処理の手順, 人が 1 回に確かめる件数の上限, 学習用の正常の行の度合いの分布 (行, 平均, 中央, 90 %, 95 %, 99 % 点, 最大), 実験の評価 (分割ごとの行, 異常の行, K, 上位 K 件の適合率, PR-AUC. 無ければ異常の正解の無い実験と書く), 元の表での確かめ (比べた行, 実験の度合いと合う割合, 差の最大) を出す. 読み込みとモデルの入力の行は出さない (入力は度合いに使う列を一式のレシピで前処理したもので, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と損得を使わず, 件数の上限は一式が持つため)
- 推論の欄: 行の表のファイル (前処理に要る元の列を持つ, 学習のときと同じ形の表) と, 人の確かめに回す件数の上限 (既定は一式の既定の振り分けの `capacity`. 1 から 1,000. 確認の待ち行列を 1 度に返すため) を選ぶ. 結論の決め方と意思決定の欄の代わりに, 度合いは確率でないので損得から回すしきい値を決めず, 度合いの高い順に上限まで回すと書く
- 推論: `POST /api/bundles/{id}/predict` に行の表のファイル (`source`) と振り分け (`decision`. `{type: triage, capacity}` だけ. 省くと一式の既定, 空の辞書で振り分けない) を渡し, ML-Inference の `infer` で度合いを出して振り分ける. 振り分けの他の型と項目は ML-Inference が理由付きで断る. 件数の上限が 1,000 を超えると断る. 文, 件数と種, 結論の決め方, 何段も先の予測, 並べるの欄を渡すと断る (列の出力でない一式と同じ)
- 結果: 表は元の列と `status`, `reason`, `score` (度合い), `rank` (度合いの高い順の順位), `column` (最も外れた列), `column_share` (度合いのうちその列の分の割合) と, ML-Inference の `decision` と `action` (人の確かめに回すか) で, 配列を持たない (結果の形の版 1 か, 列の型を残す版 3 か 4). 結論は ML-Inference の異常の度合いの結論 (`summary` は `rows`, `predicted`, `skipped`, `score`, `id`, `distribution`, `normal`, `beyond_normal`, `top`, `evaluations`) のまま, 意思決定は振り分けの結論 (`decision` の `summary` は `rows`, `acted`, `capacity`, `lowest`, `normal_p99`, `left_beyond` と, 文と前提) のまま残す. 予測の後に表を読み直して件数を数え直すことはしない (件数だけの結論にすると度合いの分布, 上位の行, 実験の評価が消えるため). 予測の表は `column_types` の型で読む (0 で始まる行の id も文字のまま)
- 確認の待ち行列: `GET /api/results/{id}/queue` は置き場の予測の表を読み, `action` が真の行を順位の順に返す. 記録に使う行の id (`key`) は, 結果の `summary.id` の列の値を文字にしたもの (列の無い結果は行の位置の整数. ML-Inference の `record_review` の `row` の決まり). 今の判断は `read_reviews` の記録のうち, その行の id の最後の記録 (同じ行を何度確かめてもよく, 最後の記録が今の判断という ML-Inference の決まり). 予測の表の行の id の列に同じ値の行があれば, 記録がどの行を指すか決まらないので, 待ち行列を返さずに重なる値を挙げた理由を返し, 記録の書き足しも断る (ML-EDA の約束も id の重なりを断る). id の値の欠けた行は `key` を空にし, 記録を引かず足させない (行の位置の整数を id と取り違えないため)
- 確かめの記録: `POST /api/results/{id}/reviews` は ML-Inference の `record_review` に結果のディレクトリ, 行, 判断, 確かめた人を渡す. 時刻は渡さず ML-Inference の既定 (今の時刻. 時差付き) にする (画面で時刻を書き換えさせないため). 書き足しは結果の書き換えと同じく 1 つずつ. 確かめた人の名前は利用者が書く (空と改行は ML-Inference が断る). 記録は結果のディレクトリの中にあるので, 結果を消すと記録も消える
- 結果の画面: 結論の文, 行, 度合いを出した行, 出せなかった行, 人の確かめに回す行の数. 「度合いの分布」に中央, 90 % 点, 99 % 点, 最大を, 新しい行と学習用の正常の行で並べた表と, 学習用の正常の行の 99 % 点を超えた行の数を出す. 「実験の評価」に分割ごとの行, 異常の行, K, 上位 K 件の適合率, PR-AUC を出す (無ければ, 異常の正解の無い実験なので度合いの分布と上位の行を人が見て確かめると書く). 「度合いの上位の行」に一式の K 件 (順位, 行の位置, 行の id, 度合い, 最も外れた列, その割合) を並べる. 「人の確かめ」に振り分けの文と前提, 確かめた人の名前の欄 (この画面のブラウザに覚え, 次の結果でも使う), 待ち行列 (順位, 行の id, 度合い, 最も外れた列, 今の判断, 「異常」と「正常」のボタン) を出す. 名前が空の間と, 行の id の欠けた行はボタンを押せない. 行の id の重なる結果は, 名前の欄と待ち行列の代わりに理由を出す. 押すと 1 件の記録を足し, 待ち行列と記録を読み直す. 振り分けていない結果は, 人の確かめに回した行が無いと書く. 「確かめの記録」に書いた順の記録 (行の id, 判断, 確かめた人, 時刻) を並べる. 結論の決め方, 意思決定の決め直し, たどり直し, 外れ方の確かめ, 列の効きは出さない (API も列の出力の結果だけで断る)

### 効果の一式 (一式の版 12)

ML-Inference の効果の一式 (`uplift`) は, 過去に処置 (クーポンを配るなど) を無作為に配った記録から学んだ行ごとの効果 (処置したときの結果 − しないときの結果. 結果が 0 と 1 なら確率の差, 量なら値の差) を出す一式で, データセットを持たず, 効果の決め方 (処置の群と対照の群の 2 つの予測の差 `t_learner`) と前処理のレシピとモデル, 結果の種類 (`uplift.outcome`. `binary` か `amount`), 見積もりに使う列 (`uplift.features`. 前処理の後の列), 行の id の列 (`uplift.id`), 処置の列 (`uplift.treatment`), 配る数の上限 (`uplift.budget`), 評価の上位 K 割の K (`uplift.k`), 学習用の行の効果の分布 (`uplift.train`), 実験の Qini の係数と上位 K 割の効果の差 (`uplift.evaluations`), 実験の Qini の曲線 (`uplift.curves`), 元の表での確かめ (`uplift.check`) を持つ. 説明の `kind` は `uplift` で, 画面では「効果の見積もり」と出す. 受け持ちと出力の形は `effect` で, 列の出力ではない (`column_output` が偽. 効果は 2 つの予測の差で, 1 つの予測ではないため).

- 作り方: ML-Quest の効果の見積もりの骨組みの実験から ML-Inference の `make_uplift_bundle` で作った一式を, 場所で登録する. 一式を作る対話には効果の一式を出さない (効果の決め方と前処理のレシピは実験の成果物から写すため)
- 一式の画面: 「データ」に効果の決め方と前処理のレシピ (データセットなし), 効果の決め方, 結果の種類, 見積もりに使う列, 行の id の列, 処置の列, 前処理の手順, 配る数の上限 (実験の評価の上位 K 割の K を「上位 30 %」のように % で添える), 学習用の行の効果の分布 (行, 平均, 最小, 10 % 点, 中央, 90 % 点, 最大, 効果が正の行の割合), 元の表での確かめ (比べた行, 実験の効果と合う割合, 差の最大) を出す. 「実験の評価」に結果の画面と同じ, 分割ごとの Qini の係数と上位 K 割の効果の差の表と Qini の曲線を出す. 読み込みとモデルの入力の行は出さない (入力は見積もりに使う列を一式のレシピで前処理したもので, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と損得を使わず, 配る数の上限の既定は一式が実験の成果物から写して持つため)
- 推論の欄: 行の表のファイル (前処理に要る元の列と行の id の列を持つ, 学習のときと同じ形の表. 処置の列と結果の列は要らない) と, 配る数の上限 (既定は一式の既定の配る判断の `budget`. 無ければ空で, 1 から 100,000 の整数を書くまで推論できない. 100,000 は JSON の整数を丸めずに渡せる大きさで, 新しい行の数として十分な大きさ) を選ぶ. 結論の決め方と意思決定の欄の代わりに, 損得のしきい値を決めずに効果の高い順に上限まで配り, 効果が 0 以下の行は上限の中でも配らないことと, 効果は処置を無作為に配った記録を前提にした見積もりであることを書く
- 推論: `POST /api/bundles/{id}/predict` に行の表のファイル (`source`) と配る判断 (`decision`. `{type: treat, budget}` だけ. 省くと一式の既定, 空の辞書で配らない) を渡し, ML-Inference の `infer` で効果を見積もって配る行を決める. 配る判断の他の型と項目は ML-Inference が理由付きで断る. 配る数の上限が 100,000 を超えると断る (省いて一式の既定を使う場合も). 文, 件数と種, 結論の決め方, 何段も先の予測, 並べるの欄を渡すと断る (異常の度合いの一式と同じ)
- 結果: 表は元の列と `status`, `reason`, `effect` (効果), `treated`, `control` (処置したときとしないときの結果の予測. 確率か元の単位), `rank` (効果の高い順の順位) と, ML-Inference の `decision` と `action` (配るか) で, 配列を持たない. 結論は ML-Inference の効果の結論 (`summary` は `rows`, `predicted`, `skipped`, `outcome`, `id`, `distribution`, `train`, `top_k`, `top`, `evaluations`, `measured`) のまま, 意思決定は配る判断の結論 (`decision` の `summary` は `rows`, `acted`, `budget`, `lowest`, `gain`, `left_positive`, `nonpositive` と, 文と前提) のまま残す. 予測の後に表を読み直して件数を数え直すことはしない (件数だけの結論にすると効果の分布, 上位の行, 実験の評価が消えるため). 一式の Qini の曲線, 結果の種類, K は結果の `uplift` (`curves`, `outcome`, `k`) に写す (一式の登録を消しても結果の画面に曲線を出せるように)
- 配る行: `GET /api/results/{id}/treated` は置き場の予測の表を読み, `action` が真の行を順位の順に返す. 配る数の上限は大きくなり得るので, `offset` と `limit` で区切って 1 度に 500 行までにする. 行の id は結果の `summary.id` の列の値 (列の無い結果は空)
- 結果の画面: 結論の文, 行, 効果を見積もった行, 出せなかった行, 配る行の数 (上限を添える). 結論の文の下の「言葉の説明」に, 効果 (処置したときの結果 − しないときの結果. 結果の種類に合わせて確率の差か値の差), 処置の群と対照の群, Qini の曲線と係数, 上位 K 割の効果の差と, 効果は処置を無作為に配った記録を前提にした見積もりで, 配った効果は配る相手を無作為に分けた試験で確かめるという前提を書く (結論の文がこれらの言葉の初めて出る所のため. 一式の画面では効果の決め方の行に効果, 群, 前提を添え, 推論の欄にも前提を書く). 「効果の分布」に平均, 最小, 10 % 点, 中央, 90 % 点, 最大, 効果が正の行の割合を, 新しい行と学習用の行で並べた表と, 効果の高い上位 K 割 (「上位 30 %」のように % で) の行の数, 効果の平均, 最も低い効果を出す. 「実験の評価」に分割ごとの行, 処置の群と対照の群の行, Qini の係数, 上位 K 割の効果の差 (上位に片方の群が無ければ無しと書く), 分割の全ての行の結果の差, 全ての行の効果 (見積もり) の平均を出し, 分割ごとの Qini の曲線 (横は効果の高い順に配った行の割合, 縦は配ったことで増えた結果の積み上げ) を, でたらめに配る線 (点線) と並べた図にする. 指を置くか, 図を選んで左右の矢印のキーを押すと, その点の配った割合と行, 2 つの線の値を出す. 図の数は表でも読めるように, 図の下に配った割合ごとの値の表を畳んで置く. 一式の画面の「実験の評価」も同じ表と図. 実験の評価が無ければ, 効果の分布と上位の行を見て確かめると書く. 渡した表に処置と結果の列があれば, 数え直した Qini の係数と上位 K 割の効果の差を, 配る相手を無作為に分けた記録でだけ確かめになるという文と並べる. 「効果の上位の行」に上位 10 行 (順位, 行の位置, 行の id, 効果, 処置したとき, しないとき) を並べる. 「配る行」に配る判断の文と前提と, 配る行の一覧 (順位, 行の位置, 行の id, 効果, 処置したとき, しないとき. 100 行ずつページを送る) を出す. 配っていない結果は配る行が無いと書く. 結論の決め方, 意思決定の決め直し, たどり直し, 外れ方の確かめ, 列の効き, 人の確かめは出さない (API も列の出力の結果だけか異常の度合いの結果だけで断る)

### 値段の一式 (一式の版 13)

ML-Inference の値段の一式 (`price`) は, 試しに値段を変えた売れ行きの記録から学んだ, 値段を入力の最後の列に入れて売れた数を予測するモデルを使い, 新しい行 (1 行が 1 つの商品の今の状態) ごとに, 値段の候補 (今の値段に対する変える割合) の中から, 変える幅の上限の中で見込みの利益 ((値段 − 原価) × 予測した数) が最も大きい値段を選ぶ一式で, データセットを持たず, 値段の決め方と前処理のレシピとモデル, 予測に使う列 (`price.features`. 前処理の後の列. 最後が値段の列), 値段の列 (`price.price`), 売れた数の列 (`price.units`), 原価の列 (`price.cost`. 無ければ null), 商品の id の列 (`price.product`. 無ければ null), 行の id の列 (`price.id`), 値段の候補 (`price.candidates`), 変える幅の上限 (`price.max_change`), 弾力性を数える値段の上げ幅 (`price.elasticity_step`), 実験の今の値段の決め方 (`price.current`), 学習用の分割の要約 (`price.train`), 実験の評価 (`price.evaluations`), 元の表での確かめ (`price.check`) を持つ. 説明の `kind` は `price` で, 画面では「値段を変える判断」と出す. 受け持ちと出力の形は `effect` で, 列の出力ではない (`column_output` が偽. 値段は候補ごとの予測の比べから選び, 1 つの予測ではないため).

- 作り方: ML-Quest の値段を変える判断の骨組みの実験から ML-Inference の `make_price_bundle` で作った一式を, 場所で登録する. 一式を作る対話には値段の一式を出さない (値段の決め方と前処理のレシピは実験の成果物から写すため)
- 一式の画面: 「データ」に値段の決め方と前処理のレシピ (データセットなし), 予測に使う列, 値段の列, 売れた数の列, 原価の列, 商品の id の列, 行の id の列, 前処理の手順, 値段の候補と変える幅の上限 (割合を「+10 %」のように % で), 実験の今の値段の決め方 (商品ごとの記録の値段の中央値か行の値段), 学習用の分割の要約 (商品の数, 値段を変える商品の数, 弾力性の平均), 元の表での確かめ (比べた鍵, 選んだ割合が合う割合, 1 行あたりの見込みの利益の差の最大) を出す. 値段, 売れた数, 原価, 変える割合, 変える幅の上限, 弾力性は, それぞれの行に説明を添える (推論の欄の言葉の説明を読み返さずに分かるように). 「実験の評価」に結果の画面と同じ, 分割ごとの表を出す. 読み込みとモデルの入力の行は出さない (入力は予測に使う列を一式のレシピで前処理したもので, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と損得を使わず, 候補と上限の既定は一式が実験の成果物から写して持つため)
- 推論の欄: 欄の上に, 結果の画面と同じ言葉の説明と前提を出す (一式の画面は推論の欄が上にあり, 値段の言葉の初めて出る所のため). 行の表のファイル (前処理に要る元の列, 値段の列, 行の id の列を持つ, 学習のときと同じ形の表. 売れた数の列は要らない) と, 値段の候補 (カンマか空白で区切った割合の小数. 既定は一式の既定の値段の判断の候補) と変える幅の上限 (割合の小数. 既定は一式の既定の値段の判断の上限. 省けない) を書く. 入力は割合の小数 (ML-Inference の値段の判断と同じ値. % に直す桁の丸めを挟まないため) で, 欄の下に % にした値を出す. 候補は -1 より大きい数で, 重ならず, 0 (今の値段) を含み, 20 個まで. 上限は 0 以上の数. 外れれば推論できない (上限の欄が空の間も). 上限を超える候補を書いた場合は, その候補を選ばないと知らせる. 結論の決め方と意思決定の欄の代わりに, 上限の中で見込みの利益が最も大きい値段を選ぶこと (同じ利益なら今の値段に近い候補) と, 使えないものを書く
- 推論: `POST /api/bundles/{id}/predict` に行の表のファイル (`source`) と値段の判断 (`decision`. `{type: price, candidates, max_change}` だけ. 省くと一式の既定, 空の辞書で値段を決めない) を渡し, ML-Inference の `infer` で売れた数を予測して値段を選ぶ. 値段の判断の他の型と項目, 候補と上限の形は ML-Inference が理由付きで断る. 候補が 20 個を超えると断る (候補ごとに全ての行を予測し直すため. 省いて一式の既定を使う場合も). 文, 件数と種, 結論の決め方, 何段も先の予測, 並べるの欄を渡すと断る (効果の一式と同じ)
- 結果: 表は元の列と `status`, `reason`, `current_price` (今の値段), `cost` (原価), `units` (今の値段での予測した数), `current_profit` (今の値段の利益), `elasticity` (弾力性) と, ML-Inference の `decision`, `action` (値段を変えるか), `change` (選んだ割合), `price` (選んだ値段), `price_units` (選んだ値段での予測した数), `profit` (見込みの利益) で, 配列を持たない (元の列の値段の列が `price` なら `price (入力)`). 結論は ML-Inference の値段の結論 (`summary` は `rows`, `predicted`, `skipped`, `id`, `product`, `cost`, `units`, `elasticity`, `train`, `evaluations`, `measured`) のまま, 意思決定は値段の判断の結論 (`decision` の `summary` は `rows`, `undecided`, `changed`, `raised`, `lowered`, `total`, `current_total`, `gain`, `ratio`, `candidates`, `max_change`, `limited` と, 文と前提) のまま残す. 予測の後に表を読み直して件数を数え直すことはしない (件数だけの結論にすると弾力性, 実験の評価, 利益の比べが消えるため). 予測した行の弾力性の分布 (`counted`, `mean`, `min`, `p10`, `p50`, `p90`, `max`, 負の行の割合 `negative`. 数えた行が無ければ null) と弾力性の上げ幅は結果の `price` (`elasticity`, `step`) に残す (ML-Inference の結論は弾力性の平均だけを持つので, 推論の直後の予測の表から数える)
- 選んだ値段: `GET /api/results/{id}/prices` は置き場の予測の表を読み, `change` が空でない行を見込みの利益の差 (`profit` − `current_profit`) の大きい順 (同じなら表の順) に返す (利益の増える行から確かめるため). 行の数は大きくなり得るので, `offset` と `limit` で区切って 1 度に 500 行までにする. 行の id と商品の id は結果の `summary.id` と `summary.product` の列の値 (列の無い結果は空)
- 結果の画面: 結論の文, 行, 予測した行, 出せなかった行, 値段を変える行の数 (上げる行と下げる行を添える). 結論の文の下の「言葉の説明」に, 値段, 売れた数, 原価 (原価の列の無い結果は利益を売上で比べると書く), 利益 (見込み), 弾力性 (上げ幅を % で), 変える割合, 変える幅の上限と, 売れた数は試しに値段を変えた記録を前提にした予測で, 選んだ値段の利益は値段を変える試験で確かめるという前提を書く (結論の文がこれらの言葉の初めて出る所のため. 一式の画面では推論の欄の上に同じ説明を出す). 「利益の比べ」に, 選んだ値段の見込みの利益の和, 今の値段のままの和, 差, 比 (今の利益の和が 0 以下なら無し), 値段を変える行 (上げる, 下げる), 候補と上限 (% で), 上限を超える候補の方が見込みの利益の大きい行の数 (上限は値段を急に大きく変えないための決まりなので選ばないと添える), 候補の値段で予測できずに決めない行の数と, 値段の判断の文と前提を出す. 値段を決めていない結果は, 値段を決めずに推論した結果と書く. 「弾力性の分布」に, 予測した行の平均, 最小, 10 % 点, 中央, 90 % 点, 最大, 弾力性が負の行の割合と, 学習用の分割の弾力性の平均を並べる. 「実験の評価」に分割ごとの行, 商品, 売れた数の誤差 (平均絶対誤差 mae と二乗平均平方根誤差 rmse. 表の下に言葉を書く), 弾力性の平均, 選んだ値段の見込みの利益, 今の値段の利益, 利益の差, 利益の比, 値段を変える商品, 上限を出す (無ければ, 予測した数と弾力性を見て確かめると書く). 渡した表に売れた数の列があれば, 数え直した誤差を, 記録の値段での予測の誤差という文と並べる. 「選んだ値段」に行ごとの一覧 (行の位置, 行の id, 商品の id, 今の値段, 原価, 変える割合 (% で), 選んだ値段, 今の値段と選んだ値段での予測した数, 今の利益, 見込みの利益, 弾力性. 100 行ずつページを送る) を出す. 結論の決め方, 意思決定の決め直し, たどり直し, 外れ方の確かめ, 列の効き, 人の確かめは出さない (API も列の出力の結果だけか異常の度合いの結果だけで断る)

### 需要の一式 (一式の版 14)

ML-Inference の需要の一式 (`demand`) は, 商品ごとの日ごとの売れた数の記録から学んだ, 先の期間 (`demand.horizon` 日) の需要 (売れる数の合計) を学んだ水準 (`demand.levels`. 小さい順) ごとの分位点で予測するモデルを使い, 渡した日ごとの記録の表の商品ごとに, 最も遅い日を発注を決める日として, 品切れの損と売れ残りの損の比から決まる水準 τ の分位点から在庫の数を引いた数を, 0 から発注の数の上限の間の整数で発注する一式で, データセットを持たず, 需要の決め方と前処理のレシピとモデル, 予測に使う列 (`demand.features`. 前処理の後の列), 商品の id の列 (`demand.product`), 日付の列 (`demand.date`), 日ごとの売れた数の列 (`demand.units`), 在庫の数の列 (`demand.stock`. 無ければ null), 行の id の列 (`demand.id`), 品切れの損, 売れ残りの損, 発注の数の上限の既定 (`demand.shortage_cost`, `demand.holding_cost`, `demand.max_order`), 学習用の分割の要約 (`demand.train`), 実験の評価 (`demand.evaluations`), 元の表での確かめ (`demand.check`) を持つ. 説明の `kind` は `demand` で, 画面では「時間をまたぐ量の判断」と出す. 出力の形は `distribution` だが, 列の出力ではない (`column_output` が偽. 発注を決める日の行だけを返し, 1 行の予測が入力の 1 行に対応しないため).

- 作り方: ML-Quest の時間をまたぐ量の判断の骨組みの実験から ML-Inference の `make_demand_bundle` で作った一式を, 場所で登録する. 一式を作る対話には需要の一式を出さない (需要の決め方と前処理のレシピは実験の成果物から写すため)
- 一式の画面: 「データ」に需要の決め方と前処理のレシピ (データセットなし), 予測に使う列, 商品の id の列, 日付の列, 売れた数の列, 在庫の数の列 (無ければ在庫を 0 として決めると書く), 行の id の列, 前処理の手順, 先の期間 (日数), 学んだ水準, 品切れの損と売れ残りの損の既定 (水準 τ を添える), 発注の数の上限の既定, 学習用の分割の要約 (行, 商品, 先の期間の需要の平均), 元の表での確かめ (比べた行, 発注の数が合う割合, 水準 τ の分位点の差の最大, 分位点の損失) を出す. 分位点, 損, 上限, 在庫は, それぞれの行に説明を添える. 「実験の評価」に結果の画面と同じ, 分割ごとの表を出す. 読み込みとモデルの入力の行は出さない (入力は予測に使う列を一式のレシピで前処理したもので, 列の出どころを持たないため). 「問題」の欄は出さず, 問題も読まない (結論の決め方と損得を使わず, 損と上限の既定は一式が実験の成果物から写して持つため)
- 推論の欄: 欄の上に, 結果の画面と同じ言葉の説明と前提を出す (一式の画面は推論の欄が上にあり, 需要の言葉の初めて出る所のため). 日ごとの記録の表のファイル (学習のときと同じ形の, 商品の id, 日付, 売れた数, 前処理に要る元の列と, あれば在庫の数の列を持つ表. 過去の売れた数の列を作るため前の日までの記録も入れる. 発注を決める日の売れた数は要らない) と, 品切れの損, 売れ残りの損, 発注の数の上限を書く (既定は一式の既定の発注の判断. どれも省けない). 損は 0 より大きい有限の数 (ML-Inference の発注の判断と同じ), 上限は 0 以上の整数 (ML-Inference は 0 以上の数を受けて整数に切り捨てるが, 発注の数は整数なので画面では整数だけを書かせ, 切り捨てで書いた値と違う上限にならないように). 外れれば推論できない (欄が空の間も). 損を 2 つとも書くと水準 τ と学んだ水準を出し, τ が学んだ水準の範囲の外なら端の水準の分位点を使う (見込みの損は少なめに出る) と, 上限が 0 ならどの商品も発注しないと知らせる. 結論の決め方と意思決定の欄の代わりに, 比べる決め方 (前の期間と同じ数の発注), 水準 τ の分位点から在庫を引いた数を整数で発注すること, 使えないものを書く
- 推論: `POST /api/bundles/{id}/predict` に日ごとの記録の表のファイル (`source`) と発注の判断 (`decision`. `{type: order, shortage_cost, holding_cost, max_order}` だけ. 省くと一式の既定, 空の辞書で発注の数を決めない) を渡し, ML-Inference の `infer` で需要の分位点を予測して発注の数を決める. 発注の判断の他の型と項目, 損と上限の形は ML-Inference が理由付きで断る (このアプリは上限の大きさを絞らない. 上限は発注の数を切るだけで, 推論の重さを変えないため). 結論の決め方と何段も先の予測を渡すと断る (先の期間は一式の `horizon` で決まる). 文, 件数と種, 並べるの欄も断る (効果の一式と同じ)
- 結果: 表は発注を決める日の行 (1 商品 1 行) の元の列と `status`, `reason`, `order_date` (発注を決める日), `on_hand` (在庫の数), `previous_demand` (前の期間の合計), `prediction` (0.5 の点), `q:<水準>` (学んだ水準ごとの分位点) と, ML-Inference の `decision`, `action` (発注するか), `quantile` (水準 τ の分位点), `order` (発注の数), `capped` (上限で切ったか), `expected_cost` (見込みの損), `baseline_order` (前の期間と同じ数の発注), `baseline_cost` (その見込みの損) で, 配列を持たない. 結論は ML-Inference の需要の結論 (`summary` は `rows`, `predicted`, `skipped`, `id`, `product`, `date`, `stock`, `horizon`, `levels`, `dates`, `prediction`, `previous`, `train`, `evaluations`) のまま, 意思決定は発注の判断の結論 (`decision` の `summary` は `rows`, `undecided`, `ordered`, `total`, `capped`, `level`, `used_level`, `outside`, `expected_cost`, `compared`, `compared_cost`, `baseline_cost`, `saving`, `ratio`, `shortage_cost`, `holding_cost`, `max_order` と, 文と前提) のまま残す. 予測の後に表を読み直して件数を数え直すことはしない (出力の形 `distribution` は列の出力と同じなので, 種類 `demand` で見分ける. 件数だけの結論にすると分位点の要約, 実験の評価, 見込みの損の比べが消えるため). 予測した行の水準ごとの分位点の平均 (`quantiles`. 予測した行が無ければ null) と, 最も小さい水準から最も大きい水準までの分位点の幅の分布 (`width` の `counted`, `mean`, `min`, `p10`, `p50`, `p90`, `max`. 予測した行が無ければ null) は, 先の期間 (`horizon`), 学んだ水準 (`levels`), 幅を数える水準 (`low`, `high`) と結果の `demand` に残す (ML-Inference の結論は 0.5 の点の平均と和だけを持つので, 推論の直後の予測の表から数える)
- 発注の数: `GET /api/results/{id}/orders` は置き場の予測の表を読み, `order` が空でない行を発注の数の大きい順 (同じなら表の順) に返す (多く発注する商品から確かめるためで, 上限に当たった商品は上限の数なので上に来る). 行の数は大きくなり得るので, `offset` と `limit` で区切って 1 度に 500 行までにする. 行の id と商品の id は結果の `summary.id` と `summary.product` の列の値 (列の無い結果は空). 分位点は結果の `summary.levels` の順
- 結果の画面: 結論の文, 商品, 需要を予測した商品, 予測できなかった商品, 発注する商品の数 (発注の数の和と上限に当たった商品を添える). 結論の文の下の「言葉の説明」に, 需要 (先の期間の日数), 分位点, 品切れの損, 売れ残りの損, 水準 τ, 在庫 (在庫の数の列の無い結果は在庫を 0 として決めると書く), 発注の数の上限, 見込みの損, 比べる決め方 (前の期間と同じ数の発注) と, 需要は在庫が 0 の日の売れた数も含む記録から学んだ予測で, 見込みの損の比べは同じ予測の分布から数えたもので必ずこの決め方が良く出るので, 実際の損は発注の後の売れた数で確かめるという前提を書く (結論の文がこれらの言葉の初めて出る所のため. 一式の画面では推論の欄の上に同じ説明を出す). 「見込みの損の比べ」に, 品切れの損と売れ残りの損, 水準 τ (学んだ水準の範囲の外なら端の水準を使ったと添える), 上限, 発注する商品と発注の数の和, 見込みの損の和, 前の期間と同じ数の発注の見込みの損 (この決め方の同じ商品の損, 商品の数, 差, 比. 比べる損が 0 なら比は無し. 前の期間の記録の揃う商品が無ければ比べられないと書く), 上限に当たった商品の数 (上限は置き場所などの決まりなので超えないと添える), 分位点を予測できずに決めない商品の数と, 発注の判断の文と前提を出す. 発注の数を決めていない結果は, 発注の数を決めずに推論した結果と書く. 「需要の分位点」に, 予測した商品の水準ごとの分位点の平均の表と, 最も小さい水準から最も大きい水準までの幅の平均, 最小, 10 % 点, 中央, 90 % 点, 最大の表 (幅の広い商品ほど需要の読みが難しいと添える), 学習用の分割の先の期間の需要の平均, 前の期間の合計の平均を並べる. 「実験の評価」に分割ごとの行, 商品, 需要の誤差 (0.5 の分位点の平均絶対誤差 mae), 分位点の損失, 発注の数の損, 前の期間と同じ数の発注の損, 損の差, 損の比, 上限で切った行を出す (表の下に言葉を書く. 無ければ, 分位点の予測と発注の数を見て確かめると書く). 先の期間の売れた数は発注を決める時点に無いので, 渡した表で数え直さない. 「発注の数」に商品ごとの一覧 (行の位置, 行の id, 商品の id, 発注を決める日, 在庫, 前の期間の合計, 学んだ水準ごとの分位点, 水準 τ の分位点, 発注の数, 上限に当たったかの印, 見込みの損, 前の期間と同じ数の発注とその見込みの損. 100 行ずつページを送る) を出す. 結論の決め方, 意思決定の決め直し, たどり直し, 外れ方の確かめ, 列の効き, 人の確かめは出さない (API も列の出力の結果だけか異常の度合いの結果だけで断る)

### 検索の一式 (一式の版 15)

ML-Inference の検索の一式 (`search` と `ready`) は, 学習しない既製のモデルの埋め込みで, 問いの写真に余弦の近さで近い写真を, 登録した写真 (索引) から上位 K 件返す一式 (似た写真を探す). データセットを持たず, 既製のモデルの出どころ (版 6 の `ready`), 索引の写真の並びと埋め込み, 返す件数の既定 (`search.k`), 守る指標の 1 件の問いの待ち時間の上限 (`search.max_latency_ms`), 索引の写真のディレクトリ (`search.root`), 骨組みの評価 (`search.evaluation`. 写真に種類が無ければ空) を持つ. 説明の `kind` は `search` で, 出力の形は並べると同じ `ranking`.

- 作り方: ML-Quest の似た写真を探す骨組みの `bundle.py` が作る一式 (`outputs/inference`) を場所で登録する. 一式を作る対話には出さない (索引と評価は骨組みが写真から作るため)
- 一式の画面: 既製のモデルの出どころ, 重み, 前処理, ライセンスの行 (版 6 と同じ) に加えて, 「索引」に索引の写真の数と埋め込みの幅, 写真の種類の有無, 返す件数の既定, 待ち時間の上限 (無ければ「決めていない」), 骨組みの評価 (検証用の問いの数, Recall@K, NDCG@K と, 比べる相手 (写真を縮めた画素をそのまま並べたもの) の値と差) を出す
- 推論の欄 (「似た写真を探す」): 問いの写真のファイルかディレクトリと, 返す件数 K (既定は一式の `search.k`. 1 から 1,000). 結論の決め方と意思決定の欄の代わりに, 問いごとの写真の一覧と待ち時間を出すことと, 問題の欄が無い理由 (返す件数と待ち時間の上限は一式が問題から写して持つ) を書く
- 問題: 「問題」の欄は出さず, 問題も読まず候補も探さない (並べるの一式と同じ). 検索の判断は返す件数だけで, 結論の決め方も損得も持たず, 返す件数と待ち時間の上限は ML-Quest が骨組みを書き出すときに問題から config に写し, 骨組みが一式に写すため. 件数は推論の欄で変えられ, 索引と骨組みの評価は一式を作り直さないと変わらないので, 問題を ML-Pathfinder で直したら骨組みを書き出し直して一式を作り直す. 問題をつなぐ API はこの一式には 400 で断る
- 推論: `POST /api/bundles/{id}/predict` に問いの写真のファイルかディレクトリ (`source`) と件数 (`k`. 省くと `search.k`) を渡す. 件数は整数だけで, 小数, 文字, 真偽は 400 で断る. ML-Inference の `infer` に `k` と検索の判断 `{type: search, k}` を渡す (結論の決め方は渡さない). 文, 件数と種, 読み込みの設定, 利用者, 前に反応した品物の表, 正解の反応の表を渡すと断る. 問いの写真は 1 回に 10,000 個のファイルまで (ディレクトリの中のファイルを数える), 問いと順位の行 (問いの数 × 件数と索引の数の小さい方) は 100 万行まで (並べると同じ)
- 結果: 表は問いと順位ごとの 1 行 (画像の読み込みの表の列と `status`, `reason`, `rank`, `item`, `label`, `similarity`, `latency_ms` と, ML-Inference の `decision` と検索の判断の `action`). 結論は ML-Inference の件数と待ち時間の結論のまま (表を読み直して数え直さない). 結果には `search` (件数, 索引の写真の数, 待ち時間の上限, 写真の種類の有無, 骨組みの評価, 待ち時間の中央値と最大, 上限を超えた問いの数) を残す. 問いの写真のディレクトリは結果の `source_path`
- 写真の縮小画像: `GET /api/results/{id}/search-photo` に `side` (`query` は問いの写真, `item` は索引の写真) と `path` (結果の表の `path` か `item` の値) を渡すと, 長い辺を 256 画素以下に縮めた PNG を返す. 問いの写真は結果の `source_path` (ディレクトリならその中, ファイルならそのファイルだけ), 索引の写真は一式の `search.root` の中だけで, 解決した場所が外を指す (`..` やリンク), ファイルでない, 画像として読めない場合は 400 (写真の場所は画面から送るので, 決まった場所の外のファイルを読ませないため). 読む形式は PNG, JPEG, WEBP, GIF, BMP, TIFF だけで, 50 MB を超えるファイルと 2,500 万画素を超える画像は中身を読まずに 400 (小さなファイルで画素の多い画像で記憶を使い切らないため). 結果が検索の結果でない, 一式が登録されていないか `search.root` が無い場合も 400, 結果が無ければ 404
- 結果の画面: 結論の文, 問いの写真, 並べた問い, 並べられなかった問い, 返した件数と, 待ち時間の中央値と最大, 上限 (無ければ決めていない) と上限を超えた問いの数. 「骨組みの評価」に Recall@K, NDCG@K (見出しにそれぞれ「上位 K 件に入った同じ種類の写真の割合」「上位 K 件の同じ種類の写真の位置で見た並びの良さ」を添える) と比べる相手の値と差, 検証用の問いの数 (種類が無ければ評価が無いことと, 並んだ写真と近さを見て確かめること). 「似た写真」に問いごとに, 問いの写真と, 近い順の索引の写真 (縮小画像, 順位, 種類, 余弦の近さ) と待ち時間を並べる (画像は代わりの文に場所と順位を持つ). 並べられなかった問いは理由を出す. 結論の決め方, 意思決定の編集, たどり直し, 外れ方の確かめ, 列の効きは出さない

### 既製のモデルの一式 (一式の版 6)

ML-Inference の既製のモデルの一式 (`ready`) は, 学習せずにそのまま使うライブラリの学習済みの重みの一式で, データセットと実験を持たず, 出どころ (ライブラリ, モデルの名前, 重みの名前), 種類の名前の表, 前処理を持つ. 今は画像の分類だけで, 出どころは torchvision だけ (ML-Inference の決まり). 説明の `kind` は `ready` で, 画面では「既製のモデル」と出す. 最初の実例は torchvision の ImageNet で学習した ResNet18 (`resnet18`, `IMAGENET1K_V1`. 1,000 の種類).

- 作り方: 一式の一覧の「既製のモデルから作る」の対話で, 出どころ (`GET /api/info` の `ready_libraries`), モデルの名前, 重みの名前を選ぶ (初めは ResNet18 の値). 打つのが止まってから少し待って下見 (`GET /api/ready/preview`) し, 種類の数と先頭の名前, 重みの版, 前処理 (短い辺をそろえる大きさと補い方, 真ん中を切り出す大きさ, 正規化の平均と標準偏差), 重みのファイルの名前, ライセンスの警告を出す. 下見できない間と, 一式の名前が空の間は「作って登録」を押せない. 重みのハッシュ値 (sha256 の 16 進の 64 文字. 大文字と前後の空白はそろえる) は任意で, 書くと読んだ重みと違えば作らない (問題や前に作った一式で決めておいた値)
- ライセンス: 下見でも作るときも, ML-ModelControl の `pretrained_info` で読んだ情報を `make_ready_bundle` に渡す (下見と一式の記録が同じ情報になるように). 読めなければ (登録されていない部品など), 「読めなかった」と警告の付いた情報を渡す (警告の無い記録にしないため). 画面は警告の印 (`alert`) が真なら `message` と `source` を並べて警告する. 印の無い記録は, 商用で使えると分かったもの (`commercial`) の他を警告する
- 重み: 一式に写さず, 使うときに出どころから読む (ML-Inference の決まり). 初めて作るときは出どころから取りに行くので, 作るのは 1 つずつにする (同じファイルを同時に取りに行かないように). torchvision の重み (URL から PyTorch の置き場の `checkpoints` にファイルの名前で置き, そこから読む) が置き場に無ければ, このアプリが `make_ready_bundle` の前に時間の上限 (全体で 600 秒, 読み込みが途切れて 30 秒) を付けて取り, 超えたら止めて誤りにする (ぶら下がった取得が鍵を持ったまま, 他の既製のモデルの作成を待たせないため). 届いた分だけ小さく読み, 読むたびに全体の上限を見る (細く流れ続ける接続も止めるため). 取るのは https の URL だけで, https でない URL への転送も断る. 隣の一時ファイルに書き (取れなかったときは消す), ファイルの名前にハッシュ値の頭があれば torch.hub と同じく比べてから置く. 取れないもの (ネットワークの誤り, 時間の上限, 壊れた中身) は 502 で返す (入力の誤りの 400 と分けるため). 一式の画面は重みのファイルの場所と, そこにあるか (`weights_cached`) を出す. 出どころの重みは一式の外 (PyTorch の置き場) にあり, 覚えた説明の印に入らないので, あるかは説明を返すたびに確かめ直す
- 一式の画面: 「データ」に画像 (既製のモデル), 出どころ, 前処理, 重みのファイルを出し, 読み込みと前処理の行を出さない. 「問題」の欄は出す (下の「問題」). クラスは数と先頭の 10 だけ. ライセンスの警告は推論の欄の上に出す. 推論の欄は画像のファイルか画像を並べたディレクトリで, 結論の決め方の欄を出す. 意思決定の欄の代わりに, 意思決定, たどり直し, 外れ方の確かめ, 列の効き, 何段も先の予測を使えないと書く (データセットと外れ方の記録を持たないため. API に渡しても ML-Inference が理由付きで断る)
- 推論: `POST /api/bundles/{id}/predict` に画像のファイルかディレクトリの場所 (`source`) と結論の決め方を渡す (意思決定は渡さない). 表は読み込みの表 (`path` など) と, `prediction` (種類の名前), `confidence`, `p:<種類>`. 読めない画像は理由を付けて飛ばす
- 問題: ML-Quest の受け渡しの推論の `ready` (作り方が既製のモデルをそのままの予測だけが持つ. 出どころ, モデル, 重みの名前, 重みのハッシュ値) を持つ問題をつなげる. 結論の決め方は, 一式の既定値に受け渡しの結論の決め方を重ねて推論の既定にする. 意思決定は使えないと書き, 問題の意思決定は読まない (既製のモデルの一式は外れ方の記録を持たないため). 決めておいた `library`, `model`, `weights`, `sha256` のうち書いたものが一式と違えば, 食い違いとして出す (重みの名前は `READY_LIBRARIES` で版の決まった名前に直して比べる. `DEFAULT` と一式の `IMAGENET1K_V1` を違うと言わないため. 重みのハッシュ値は両方を小文字にして, 一式が読んだ重みのハッシュ値と比べる. 一式に記録が無ければ, 確かめられないと出す). 作り方が既製のモデルをそのままでない問題は, つなげるが使わないと書き, 既定は一式の既定値のまま. 候補は, 一式の上のディレクトリにある作り方が既製のモデルをそのままの問題だけ (ML-Quest の既製のモデルの骨組みは, 学習のプロジェクトの中に一式を作るため)
- 結果の画面: 意思決定と外れ方の確かめの欄を出さず, 使えないと書く. 結論の決め方を変えて出し直せる. 種類ごとの確率の列 (`p:<種類>`) が 20 を超えると予測の表には出さず, CSV にだけ入れると書く (ImageNet の 1,000 列を表に並べないため)

### 繰り返しの手順と起動の設定

- 一式の手順は ML-Inference の登録簿 (公開の `PROCEDURES`. 自作の手順は `register_procedure` で足す) から名前で引く. 組み込みは `ddim`, `euler`, `greedy`, `sample`
- 研究の自作の手順は, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --procedures pkg.module,...` か環境変数 `ML_PROVIDE_PROCEDURES` (`,` で区切る) に書いたモジュールを起動のときに import し, モジュールが import のときに `register_procedure` で登録する. 読めないモジュールは起動を止める. 読む途中で止まったモジュールが登録した手順は登録簿から外す (同じプロセスで直して読み直せるように. ML-ModelControl の部品の読み込みと同じ). 外すのは, 手順の関数を定義したモジュール (`__module__`) が読み込みの途中で止まって `sys.modules` に無いものだけ. 止まったモジュールが先に読み終えた別のモジュールは `sys.modules` に残り, 読み直しで import し直さないので, その手順は外さない (外すと読み直した後も手順が無いままになるため). 止まったモジュールが読み終えた別のモジュールの関数や, `functools.partial` などで包んだ関数 (`__module__` が包んだ型のモジュール) を登録した場合は外れず, 読み直すと既にある名前の誤りになる (起動し直せば読める)
- 手順の登録簿はプロセスで 1 つ. 読み込み済みのモジュールは import し直さず前の結果を使うので, `create_api` を何度呼んでも, 同じプロセスの他のアプリが先に同じモジュールを読み込んでいても重ねて登録しない
- 一式やファイルに書かれたコードは自動では読まない. 登録簿に無い手順の一式は「手順 … は登録簿にありません. 自作の手順なら, 登録するモジュールを起動の設定 (`--procedures` か `ML_PROVIDE_PROCEDURES`) に足してから起動し直してください」で止める

### 自作の部品と起動の設定

- 研究の自作の部品 (ML-ModelControl の `register_unit` で登録する部品) も手順と同じく, 起動の設定で明示したモジュールだけを読み込む (手元で任意のコードを読み込まないため). `ml-provide --units pkg.units,...` か環境変数 `ML_PROVIDE_UNITS` (`,` で区切る. 引数が環境変数より先) に書いたモジュールを, 起動のときに手順のモジュールの前 (手順のモジュールが部品を使えるように) で ML-Inference の `register_units` (ML-ModelControl の `register_units_from`) に渡す. モジュールは `UNITS` か `register_units(register)` で部品を宣言する (書き方は ML-ModelControl の docs/DESIGN.md の「自作の部品のモジュール」). 読めないモジュール, 部品を宣言していないモジュールは起動を止める. 手順も登録するモジュールが部品の読み込みの途中で止まった場合も, 手順の読み込みと同じ決まりでそのモジュールの手順を登録簿から外す (部品と手順の両方に同じモジュールを渡したときに, 直して読み直すと理由が「既にある名前」に変わらないため)
- 部品の登録簿 (ML-ModelControl の登録簿) はプロセスで 1 つで, 殻の下では ML-CreateArchitecture と共有する. 読み込み済みのモジュールは ML-ModelControl が前の結果を返すので, `create_api` を何度呼んでも, 他のアプリが先に同じモジュールを読み込んでいても重ねて登録しない. 同じ部品の名前を別々のモジュールで宣言すると, 後から読んだアプリが起動を止める
- `GET /api/info` の `unit_modules` に, 読んだモジュールと登録した部品の名前 (`[{"name": "pkg.units", "units": ["my.Block"]}]`) を返す
- 一式のモデルの定義に書かれた部品の名前からは何も読み込まない. 登録されていない部品を使う一式は, ML-Inference の `UnregisteredUnitError` (部品の名前とノード) に「自作の部品なら, 部品を宣言したモジュールを起動の設定 (`--units` か `ML_PROVIDE_UNITS`) に足してから起動し直してください」を添えて, 一式の画面 (一覧と一式の欄の誤り), 場所での登録, 画面で作る一式, 推論の誤りに出す

## 9. 問題とのつなぎ

問題 (ML-Quest の `problem.yaml`) は, 7 の「損得」で意思決定の型と損得と制約と根拠を, 5 の「機械学習の受け持ち」で当たりのクラス, 系列を分ける列, 何期先までを決める. 骨組みから学習した一式は, 学習した時点の値を一式の既定値に持つ. ただし, 画面で作った一式は既定値を持たず, 学習の後に問題の損得を見直すと一式の既定値は古くなる. そこで, 一式に問題をつなぎ, 推論の既定を問題の今の値にする.

- つなぐと, 一式の画面の推論の意思決定と結論の決め方の既定を, ML-Quest の受け渡し (`handoff` の `inference`) から読む. 結論の決め方は, 一式の既定値に問題の値 (まとめる列) を重ねる. 推論のたびに読み直す (問題を ML-Pathfinder で直せば, 次の推論から使う)
- 今のやり方: 量を決める型で, 問題に今のやり方 (`action.current`) があれば, 意思決定の `current` を ML-Inference の決まりにする. k 期前と平均は, 時刻の列 (問題の予測の時刻の列, 分割の時刻の列, 一式の過去の値の手順の時刻の列の順. 一式の手順の列なら, 系列を分ける列も ML-Inference が一式の手順から補う), 問題の系列を分ける列, データを入れたときに求めた 1 期の間隔 (`data.interval_seconds`. 無ければ ML-Inference が推論するデータの時刻の差から求める) を足す. 列は列の決まり (置いた後の量. 今ある量があっても問題と同じ意味). 時刻の列がどこにも無ければ入れず, 一式との食い違いの欄で知らせる. 決まりの列 (時刻, 系列, 今のやり方の列) が一式の学習のデータに無ければ, 食い違いの欄で知らせる (ML-Inference の `check_baseline`). たどり直しは, 推論するデータに今のやり方の列が無くても, 決まりから行ごとの値を作って比べる (利用者が列を足さずに済むように). 選ぶと振り分けは受け渡しの列の名前のまま
- 守る指標: たどり直しは, つないだ問題の守る指標 (受け渡しの `inference` の `guard`) を ML-Inference の `backtest` に渡し, この方針の行動で数える (つないでいない一式は渡さない). 推論の既定と同じく, たどり直しのたびに読み直す. 結果の画面のたどり直しの欄に, 守る指標の名前, 数えた量の説明, この方針での値, 守る線 (以下か以上), 守れたかと, 数えなかった理由 (数える量を指していない, 数える行が無い) を並べる. 割合の量は値も線も % で出し (ML-Inference の文に合わせる), 量の名前 (`counted`) は出さない (利用者の言葉でないため). 守る指標を答えた問題が推論に渡せない場合 (機械学習を使わない, 確かめに直すところがあるなど) は, 理由を添えて断る (400). 結果の画面で意思決定の型を変えて, 問題の守る指標が指す量をその型で数えられない場合も, 量の説明を添えて断る (400). ML-Inference の守る指標の誤り (`ValueError`) も 400
- 意思決定の欄の「今のやり方の列」は, 決まりがあれば, 空のまま決まりで比べると書き, 「使わない」で外せる. 列を書けば, その列で比べる
- 損得の根拠 (`action.basis`) と, 意思決定の文 (ML-Quest の `describe` と同じ) を出す. 根拠の無い損得はそう知らせる
- 一式との食い違いを出す: 目的の列が違う, 意思決定の型が一式のタスクに合わない (ML-Inference の `check_decision`), 結論の決め方が合わない (`check_rules`). 食い違いがあっても既定にはするが, 推論の前に気付けるようにする
- 一式の学習のデータの列 (意思決定, 今のやり方, まとめる列の列が無いことを知らせるため) は, 一式のデータセットの説明から次の順で取る. 1. 元のデータの場所 (`source.path`. 手元の場所を残す版 1 の書き出し) が読めれば, そのファイルの列 2. 説明に残る入力の列 (`source.columns`. 表の書き出しだけ) 3. 説明とレシピから集めた列 (学習に使う列, 目的の列, 手順が読む列, 読み込みの設定の列). 3 は自動で見つけた時刻の列などが抜けて全てとは限らないので, 列が無いことを知らせない (誤って知らせないため). どれも無い一式 (文や画像) も知らせない
- つなぐときは, 渡せる問題か (`handoff` が通るか) を確かめる. 機械学習を使わない問題や, 直すところのある問題は理由付きで断る
- つないだ後に問題のファイルが別の問題で上書きされた (作った時刻が違う) か, 読めなくなった場合は, 理由を出し, 既定は一式の既定値に戻す. つなぎは外さない (直せば戻る). たどり直しは, 先に守る指標の有無を見る. 守る指標が無ければ, 推論に渡せない問題でも, 推論に渡さずに守る指標無しでたどり直す. 消えた, 読めない, 上書きされたなどで有無を見られない場合も守る指標無しでたどり直し, 「つないだ問題を読めないので, 守る指標は数えていません」などの知らせの文を結果に添える (守る指標の無いたどり直しを, 問題の崩れで止めないため). 守る指標があって推論に渡せない場合だけ, 理由を添えて断る (400)
- 候補: 骨組みの学習のプロジェクトは `problem.yaml` を持ち, 学習の実験の中に一式を作る. つないでいない一式は, 一式の場所から 4 つ上のディレクトリまでたどり, 最初に見つけた推論に渡せる問題のファイル (`problem.yaml`) を候補に出す (つなぐかは利用者が決める)
- 元の問題: 見つけたファイルは, 骨組みが写した学習の時点の写し. 写しが元の場所 (ML-Quest の `problem_origin`. ML-Pathfinder の置き場の `problem.yaml`) を持ち, 元があって推論に渡せるなら, 元を候補にする (写しをつなぐと, ML-Pathfinder で直した損得が届かないため). 元の場所を持たない写しと, 元が無いか推論に渡せない写しは, 写しを候補にし, 直した損得が届かないことを文で添える. つないだ問題は推論のたびに読み直すので, 元をつなげば ML-Pathfinder で直した損得が次の推論の既定に入る
- 問題への書き戻しはしない (推論の画面で変えた損得は, その結果の決め方として残す. 問題を直すのは ML-Pathfinder)
- 問題の版: ML-Quest の版 2 (受け持ちの並び `ml.parts`. 今は 1 つ) を読む. 版 1 のファイルは ML-Quest が読んだ後に版 2 に移す (ファイルは変えない) ので, 版 1 と版 2 で同じ値になる. 知っている版より新しいファイルは, 読めない理由を出して止まる (読める項目だけで読み違えないため)
- 問題の欄を出さない一式: 雑音だけ, 並べる, 群分け, 異常の度合い, 効果, 値段, 需要, 検索の一式は, 欄を出さず, 問題を読まず候補も探さない (理由は 8 のそれぞれの節). どの一式かは API が一式の種類から決めて `uses_problem` で返し, 画面はそれに従う (種類の並びを 1 か所に置き, 画面と API で食い違わないため). 種類の分からない一式 (読めない一式) は欄を出す
- 受け持ちが列の予測 (予測するで, 正解の種類が表の列) の問題だけ, 意思決定と結論の決め方を既定にする (既製のモデルの一式は, 作り方が既製のモデルをそのままの問題の結論の決め方だけ. 8 の「既製のモデルの一式」). 他の受け持ち (作る, 並べる, まとめる, 効果を見積もる, 予測するで正解が点群や画像の領域など) は受け渡しの `inference` が空 (意思決定は無い) なので, つなげるが「この問題の受け持ち (作る, 正解の種類は画像) の推論の結論はまだ扱いません. 意思決定と結論の決め方は一式の既定値のままです」(括弧の中は受け持ちごと)と出し, 推論の既定は一式の既定値のままにする. 候補には出さない

## 10. 実験の一覧

学習した実験の一式を, 場所を打たずに登録するための一覧. 骨組みの学習のプロジェクトの学習のスクリプトは, 実験のディレクトリ (`outputs/<名前>/<日付>/<時刻>`) の中に推論の一式 (`inference`) か, 方策の骨組みなら方策の一式 (`policy`) を作る. 推論の一式と方策の一式は別の一覧にし, 同じ探し方で並べる.

- 学習のプロジェクトは, ML-Pathfinder の問題の設定の置き場 (`create_api` の `problems_dir`. 渡さなければ環境変数 `ML_PATHFINDER_HOME`, 無ければ ML-Pathfinder と同じ既定の場所. その中の `problems/<id>/problem.yaml`) の問題が記録した学習のプロジェクト (`project.path`. ML-Quest の `record_project` が書く) から得る. 読めない問題, 記録の無い問題, 無いディレクトリは飛ばし, 同じ学習のプロジェクトは 1 つにまとめる
- 実験は, 学習のプロジェクトの `outputs` の下を 5 つ下のディレクトリまで探し (リンクはたどらない), `inference.yaml` を持つ `inference` を推論の一式, `policy.json` を持つ `policy` を方策の一式とする. 一式の更新の時刻の新しい順に並べ, 500 件で打ち切る (打ち切ったことを画面に出す)
- 行は, 問題の名前, その学習のプロジェクトを記録した問題の識別子 (置き場のディレクトリの名前. 同じ学習のプロジェクトを記録した問題が複数あれば全て), 出力先からの実験の場所 (名前/日付/時刻), 一式の場所, 一式を作った時刻. 殻で問題を選んでいれば, 画面はその識別子を API に渡し, API がその問題が記録した学習のプロジェクトだけを見て上限を数える (上の「3. 画面」の「殻で選んだ問題」). 登録済みの一式 (登録の場所か, 外れ方を書き戻したときに写した元の場所が同じもの. 方策の一式は登録の場所が同じもの) は「登録済み」として一式か方策の画面へつなぐ
- 一覧から登録すると, 名前を「問題の名前 (実験の場所)」にして場所で登録し (同じ `POST /api/bundles` か `POST /api/policies`), 一式か方策の画面に移る. 一式は写さない. 場所で選ぶ登録も残す (置き場に記録の無い学習のプロジェクトと, 骨組みでない一式のため)

## 11. 元のデータセットのテスト用の分割

学習の結果 (実験) から登録した表と時系列の一式では, 推論するデータに, 学習に使ったデータセット (ML-EDA が書き出した版 1) のテスト用の分割を選べる. 学習・評価から推論へ進むときに, 推論するデータの場所を調べて入れずに, 学習に使わなかった行で一式を確かめるため.

- 見つけ方: 一式 (置き場に写した一式は写した元 `copied_from`) から, 一式自身か上の 2 つのうち普通のファイルの `run.json` を持つ最も近いディレクトリを実験とする. 実験の `config.yaml` の `data.dataset` (無ければ `task.yaml` の `dataset.path`) を, 実験の上にたどって最初の `configs/default/train.yaml` を持つディレクトリ (ML-Found の学習のプロジェクト) から辿る (ML-Quest の骨組みはこの値を学習のプロジェクトからの相対で読む). その `dataset.yaml` が版 1 で, `splits.test` の `file` がデータセットの中の普通のファイルならテスト用の分割とする. 読む `config.yaml`, `task.yaml`, `dataset.yaml` は 1 MiB までの普通のファイルだけ (リンクは読まない)
- 選べるのは表と時系列の列の予測の一式だけ (雑音だけ, 既製のモデル, 並べる, 群分け, 異常の度合い, 効果, 値段, 需要, 検索, ファイルの組のデータセットの一式は除く. ML-Inference の分割の推論が受け付ける一式)
- 画面は分割の名前だけを送る. 推論のときもサーバが同じ道で見つけ直し, 見つけた場所を ML-Inference の `{"dataset": 場所, "split": "test"}` で渡す (画面からサーバの上の好きな場所を読ませないため). 一式のデータセットと説明やレシピが違えば ML-Inference が理由付きで断る
- 結果は ML-Inference の結果の形の版 5 で, 入力の文は「元のデータセットのテスト用の分割 (場所 の test)」. 目的の列は元の値に戻るので, たどり直しと外れ方の測り直しにも使う. そのときも推論と同じ道で一式の実験から分割を見つけ直し, 結果の `split` と同じときだけ読む (違えば推論し直すよう, データセットが見つからなければその理由を添えて 400. 記録した場所をそのまま読まず, 一式の実験が指すデータセットの変化に気づくため). 前処理の前の列が無いので, 列の効きと行ごとの理由は求めない (画面は欄を出さず, API は 400). 何段も先の予測も選べない. 結果どうしの比べでは, 同じデータセットの同じ分割を同じ入力とする
- 見つからない一式 (実験の外, データセットの記録が無い, 学習のプロジェクトの外, 版 2 と 3, テスト用の分割が無い) は, 今まで通り場所を入れる. 実験の中の一式で見つからなければ, 画面は欄の下に理由を出す

## 12. 方策の一式

強化学習で学習した方策の一式 (ML-Found が書き出す `policy/`) を, ML-Inference の `load_policy` で読み, 画面に入れた観測から守りを当てた行動を見る. 形と守りの決まりは ML-Inference の docs/DESIGN.md の「方策の一式」が持ち, このアプリは自分で解釈しない.

- 登録: 推論の一式と別に `policies.json` に場所だけを覚える (一式は写さない). 登録の前に重みまで読み, 読めない一式は ML-Inference の誤りの文で断る. 同じ場所の二重の登録は断る
- 組み立て: 一式に写したモデルの定義 (`metadata.model.spec`) を持つ一式だけを読める. クラスの名前と引数 (`metadata.model.class`, `args`) だけの一式は, 名前からコードを読み込まない決まりのため, ML-Inference の誤りの文 (`metadata.model.spec` が無い) で断る
- 読み直し: 読んだ方策は 4 つまで覚えて使い回し, `policy.json`, 重み (`weights`), 写したモデルの定義 (`metadata.model.spec`) の更新時刻と大きさのどれかが変わったら読み直す (学習し直して書き出し直すと変わるため). 登録を外すと手放す
- 観測: 形や値の誤り (数でない, 形が違う, 有限でない, 止める条件の外) は断らずに, ML-Inference の守りの外れたときの動きとして返す (画面で守りの働きを確かめられるように). float にできない桁の大きな整数も, 数の配列にできない観測と同じ外れたときの動きにする. 要素 (入れ子のリストの中の値とリスト. 空のリストを並べた観測も上限に掛かるように) が 100,000 を超える観測だけは読まずに断る. 無い一式は観測を見る前に 404 にする
- 方策を動かすのは 1 つずつ. 推論とは鍵を分ける (大きな推論の間も行動を待たせないように)
- 観測のファイル: `.npy` は先頭の次元を観測の並びにする (pickle の配列は読まない). 値の型は小数, 整数, 真偽値だけ (文字, 複素数, 構造の型は理由を付けて断る). `.csv` は 1 行に 1 つの観測で, 1 行目に空でない数にできない欄があれば列の名前として読む (空の欄は見ない. 値の欠けた観測の行を列の名前と読まないため). 欄は整数, 小数 (`nan`, `inf` も) の順に読み, 数にできない欄は文字のまま渡して守りの外れたときの動きにする. 観測の空間が 1 つの値なら 1 つの欄をその値に, 多次元の box なら要素の数が合う行をその形に並べ直す. 1 つのファイルで 10,000 件, 値は全てで 1,000,000 個まで (1 件ずつ方策を動かすので, 長く止まらないように). 読む前にも止める: `.csv` はファイルが 32,000,000 バイト (約 32 MB. 1 つの値に 32 バイト) まで, `.npy` はファイルが 8,065,536 バイト (1 つの値に 8 バイトとヘッダの分) までで, ヘッダだけを読んで形の値の数と型を確かめてから中身を読む (ヘッダだけが巨大な形のファイルで記憶を使い切らないため). 方策を動かす鍵は件ごとに取り直す (長いファイルの間も 1 件ずつの行動を待たせないように) 1 件の観測の要素の上限は 1 件ずつのときと同じで, 超えた件は止めた (`stop`) として理由を残す
- 方策の結果: 置き場の `policy_results/<id>/` に, 1 件ずつの表 (`actions.csv`. 列は `index` (ファイルの中の観測の位置. 0 から), `observation` と `action` (JSON の文字. 行動なしは `null`), `status`, `reasons` (「 / 」で並べた理由)) とまとめ (`policy_result.yaml`. `format_version`, `policy_id` (方策の一式の id), `policy` (名前と場所), `source`, `created_at`, `rows` (件数), `counts` (守りの結果ごとの件数)) を隣に書いてから置き換えて残す. 持ち出しの CSV は, `=`, `+`, `-`, `@` で始まる数でない欄の頭に `'` を付ける (表計算のソフトが式として読まないように). 消している途中に表を読むと 404 形はこのアプリが持つ (推論の結果の形 (ML-Inference の `write_result`) は列の予測の表と結論のためのもので, 方策の行動と守りの結果を入れないため). 知らない新しい版は読まずに一覧から飛ばす. 方策の登録を外しても結果は残す (方策の名前と場所を結果にも書く)

## 13. 1 行の予測の理由

結果の画面で選んだ 1 行について, ML-Inference の `explain_rows` で元の列ごとの効き (`effect:<列>`. その列の値を他の行の値に替えたら予測がどれだけ変わるか. 正ならその行の値が予測を上げた) と理由の文 (`reason`) を求める.

- `explain_rows` は渡した全ての行で求め, 推論の回数は列の数 × 回数 (10 回) なので, 入力の全ての行ではなく, 選んだ行と比べる行だけを渡す. 比べる行は, 過去の値の列を作らない一式では入力から等しい間隔で選んだ 200 行 (効きは他の行の値に替えたときの変わり方なので, 選んだ行だけでは 0 になるため), 過去の値の列を作る一式では選んだ行の前の続いた 999 行 (過去の値に前の行が要るため)
- 入力は結果に残した入力のファイルを, 推論と同じ読み込み (学習のときの読み込みと設定に, 推論のときの設定を上書き) で読み直す. 行の数が推論したときと違えば, 行を合わせられないので断る
- 押すまで求めない (推論を繰り返すため). 求めた理由は結果に残さない

## 14. 結果どうしの比べ

結論の決め方, 意思決定, 一式を変えたときの違いを, 結果を 1 つずつ開かずに見るために, 選んだ結果のまとめを並べる.

- 比べるのは, 全ての結果が同じ一式 (一式の id. 一式の id が無い古い結果は一式の場所) か, 同じ入力のファイル (結果に残した読んだファイルの場所) の組だけ. 同じ場所のファイルは, 中身が後から変わっていても同じ入力とする (結果は読んだファイルの中身を残さないため). 一式も入力も違う組は, 違いが一式によるものか入力によるものかを分けられないので比べない. 書いた文の結果は同じ件数でも中身が違いうるので, 同じ入力としない
- タスクの違う組 (分類と回帰など) と, 列の出力でない一式の結果 (群分けを除く) を含む組は, 判断の内訳と得の意味が違うか持たないので比べない. 比べられない組も, 選んだ結果と理由は返す (画面で理由と結果へのリンクを出すため)
- 群分けの結果 (出力の形が `cluster`) は, 全てが同じ群分けの一式 (上の一式の決まり) で, 結果に残した `grouping` の群の数, 群を作る列, 学習のときの群の要約が同じ組だけを比べる (群の番号の意味は一式ごとに違うため. 同じ入力のファイルでも, 違う一式なら比べない). `grouping` を持たない古い群分けの結果を含む組は, 同じ一式かを群で確かめられず, 学習のときの群の要約も無いので比べない (推論し直すと比べられると理由に書く. 違う一式とは言わない). 一式を消した結果も, 残した `grouping` で比べる. 群分けの結果と他の結果の混ざった組は, 結論の形 (群の要約と判断の内訳) が違うので比べない. 理由は他の組と同じく `reasons` に入れる
- 群分けの結果どうしの比べの画面は, 何を比べたかと結論 (全体の文, 行, 割り当てた行, 割り当てられなかった行, 群の数) の後に, 次を並べる. 値は各結果の結論の群の要約 (`summary.groups`) と結果の `grouping` の学習のときの群の要約から取り, 予測の表は読まない. 1. 「群の大きさ」: 群ごとに件数, 割合, 学習のときの割合との差 (ポイント. 増えたか減ったかの言葉を添える). 行の見出しに学習のときの割合を添える (同じ一式なので結果の間で同じ). 割り当てた行の無い群も 0 件で並べる (群が消えたことに気付けるように) 2. 「結果 1 からの割合の差」: 結果 2 以降の群ごとの割合の差 (別の時期の新しいデータで増えた群と減った群を見るため). 全ての差が表示の桁で 0 の群には「違う」の印を付けない 3. 群ごと (と全体) の「列の特徴」: 群を作る列ごとの平均か最も多い値 (見出しは 1 つの結果の画面の群の要約と同じく, 数の列は「平均」, 種類の列は「最も多い値」を添え, 学習のときの値も添える)
- 読むのは 1 つの結果の画面と同じまとめ (`result.yaml` と予測の表の列の名前) だけで, 予測の表は読まず, 推論, 結論の出し直し, たどり直しもしない. 意思決定とたどり直しは結果に残した値を出し, たどり直していない結果は空
- 値の違いは画面が並べた値の文字で見分ける (表示の桁で同じに見える値は同じとする). 時刻は違って当然なので印を付けない
- 選ぶのは, 左の「結果」の一覧 (全ての一式の結果) か, 一式の画面の過去の結果の一覧 (その一式の結果. 一式の決め方や意思決定を変えて出し直した結果を, 一式の画面から離れずに比べるため). 選びと上限は 2 つの一覧で同じ
- 一度に比べるのは 6 つまで (画面の列が読める幅に収まるように). 一覧で 6 つ選ぶと, 選んでいない結果の印は押せなくなる
- 方策の結果 (`policy_results/`) は比べる対象の外. 一覧で選ぶのは推論の一式の結果だけ (守りの結果ごとの件数は判断の内訳や意思決定と形が違い, 並べ方を別に決めるため)

## 15. 課題の型への広げ方

機械学習の課題は, 1 件の分からない値を当てる「予測する」(分類, 回帰, 時系列の予測. 検出, 領域分け, 文字起こし, 3D の形のような構造のある出力と, 正解のほぼ無い異常の検知も) のほかに, 正解が 1 つに決まらない中身を「作る」, 多くの候補から「並べる」(推薦, 検索), 正解の無いデータを「まとめる」(群分け), 行動の「効果を見積もる」(uplift, バンディットや強化学習の方策) に分けられる. 正解の出どころ (列, 対のファイル, 自分自身, 今の処理の出力, 行動の結果, 介入の記録, 指示 (プロンプト)), 1 件の単位 (行, まとまり, 対, 要求と候補, 窓), 作り方 (規則, 既製のモデルをそのまま, 頭だけ学習, 微調整, 一から) で, データの形と確かめ方が変わる. 推論と結論の中身は ML-Inference に足し, この画面はそれを使う. 列の出力でない一式は 1 件ごとの配列を見せる (上の「受け持ちと出力の形」) が, 結論と意思決定は列の出力 (確信, クラスの確率) と 3 つの意思決定を前提にしている.
